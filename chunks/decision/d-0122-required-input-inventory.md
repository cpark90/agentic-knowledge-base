**결론** — 체계를 한 프로젝트에 인스턴스화하는 데 필요한 입력을 15종으로
확정하고, 각각에 대해 결정하는 것·제공 주체·변경 시 파급을 기록한다.
태그 어휘(설계 에이전트 + 유저)를 빼면 제공 주체는 전부 유저다.

**근거** (노트 9.1절) — 네 갈래로 묶인다.
- **프로파일계** — 도메인 프로파일(이 프로젝트의 작업 종류. plane 청크의
  실체·판정 도구·앵커 해석기, 2.11절), 판정 도구 바인딩(plane별 실제 명령,
  5.4절), 앵커 해석기 구성(청크 IRI → 저장 위치 사상, 4.9절). 바뀌면 해당
  plane 청크 전부 재검사 또는 링크 양 끝 재해석.
- **어휘계** — 상위 온톨로지 선택(1회. 바뀌면 온톨로지 전체 재정렬,
  사실상 불가역), 태그 어휘(기존 범주 재계산), 언어 정책(1회, 0.6절
  표기 형식).
- **조직계** — 에이전트 카탈로그(스코프 전부 재파생, 3.4절), 실행 모드
  (하네스 재구성, 재진입 요약 필요 여부), 메모리 승격 규칙(`memory` plane
  비우기 정책), 프로세스 규칙(작업 순서 제약. 스코프 conditional로 인코딩),
  재판정 경계(링크·가정 일괄 재판정 시점. 8.6절 큐 처리 빈도).
- **임계값계** — 청크 상한(42줄 기본, plane별 오버라이드), 상승 임계값
  N·M·K(6.11절), 커버리지 임계(자율 진행 허용 하한, 10.1절), 후보 상한
  (복원 시 k, 라벨 목록 표시 수, 7.7절).

**파급의 크기가 곧 변경 비용이다** — 상위 온톨로지 선택과 언어 정책은 1회
입력이고, 나머지는 프로젝트마다 다시 정한다.
