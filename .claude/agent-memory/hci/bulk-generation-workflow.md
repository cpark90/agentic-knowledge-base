# 대량 청크 생성 작업의 요령 (2026-09-10)

- 생성 스크립트는 **먼저 scratchpad 파일로 저장**하고 실행한다. heredoc 안에서 한 번에
  실행하면 중간 assert 하나에 수십 KB의 본문을 다시 보내야 한다 (37건 재도출 때 한 번 겪음).
- 요구 IRI 같은 참조는 하드코딩하지 말고 파일에서 라벨로 읽는다 — 자릿수 긴 uuid는 옮겨 적다
  틀린다. 별칭 → 라벨 부분 문자열 → 유일성 assert.
- 결정 하나 = 디렉토리 하나(결론·근거·대안). 42줄 초과는 생성 직후 줄 수로 잡는다.
- 노트가 명시적으로 대비·기각한 안만 대안으로 쓰고, 없으면 "대안 없음 — 후보가 하나였다는 사실"
  (7.4절). 지어내지 않는다.
- 순서: 원문 `[확정]` 목록 추출 → 기존 라벨과 겹침 확인 → 형식 예 1개 확인 → 생성 → `bazel test //...`
  → 문서 수치 동기화(intent·README·roadmap·감사·리뷰 진행 표) → 링크 검사.
- **용어 일괄 치환 뒤에는 조사 교정이 따라야 한다** — 받침이 다른 명사로 바꾸면 은/는·이/가·을/를·과/와·으로/로·이다/다가
  어긋난다(2026-09-11: 94파일 198곳). 치환 스크립트에 받침 규칙(유니코드 종성) 기반 교정 단계를 붙여 한 번에 돌린다.
