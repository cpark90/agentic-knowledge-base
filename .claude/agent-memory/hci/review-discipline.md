# hci 검토 규율 — 2026-09-29~10-02 에 실제로 틀린 것에서 뽑았다

1. **재검토의 첫 단계는 원본 항목의 `## 답` 을 다시 읽는 것이다.** 유저는 답을 고쳐 적는다. 2026-09-30 에 `jev-credentials` 의 답이 "1." 에서 "jev 를 직접 쓰지 않음"으로 바뀌었는데 읽지 않고 반대 방향의 재검토를 냈다. 태깅(`status`)만 보지 말고 본문을 본다.
2. **"참고하라"와 "도입하라"를 갈라 묻는다.** 유저가 외부 사례(jev)를 기준으로 들면 방법론의 참고인지 서비스의 도입인지를 항목의 첫 질문으로 세운다. 가르지 않아 결정·도구·ODD 조건까지 내려갔다가 되돌렸다.
3. **유저의 정의를 받으면 내 틀로 번역하지 않는다.** "서비스 = 에이전트가 쓰는 지식 베이스"를 접점 셋·skill API 로 옮겼다가 정정받았다. 유저 문장을 결정 문장으로 그대로 쓰고, 내 해석은 "hci 의 읽기"로 따로 표시한다.
4. **산발은 제거가 아니라 편입이다**(유저 결정 2026-10-01). 서비스 밖으로 분류해 빼는 안을 내지 않는다.
5. **근사 수치에는 방법과 한계를 같이 적는다.** 토큰 근사(한글 3자/토큰)는 실측 2.35 와 1.7배 달랐고, 정규식 한 벌로 센 "정의문 규칙 36"은 52, "FAIL 태그 44"는 네 목록 합집합 56 이었다. 한 목록만 세고 전수인 것처럼 적지 않는다.
6. **성공 조건에는 단위를 적는다.** "`pct` 36 안팎"은 호출 표현식 수였고 링크의 단위는 호출하는 청크(12)였다.
7. **refresh 제거는 사슬 단위다.** 인수 기록의 `ref` → handoff, handoff 의 `source` → 유저 lane 항목이 실재를 요구한다. 발신자가 기록을 `closed` 로 바꾼 뒤 셋을 같은 사이클에 지운다. 먼저 지우면 `channel_lint` 가 FAIL 한다.
8. **휘발성 데이터는 보이면 바로 옮긴다.** 다른 세션 스크래치패드의 실험 응답은 채널(`inquiries/<실험>/`)로 복사하고 정식 자리(`kb/vv/run/`)로의 이동을 handoff 에 적는다.
9. **승인 태깅이 handoff 보다 앞설 수 있다.** 담당 역할은 태깅을 신호로 바로 움직인다. 그때 handoff 는 사후 기록으로 쓰고 순서를 적는다.
10. **push** 는 `git -c credential.helper='!gh auth git-credential' push origin main`. 판정 자격·키는 채널에 적지 않는다.
