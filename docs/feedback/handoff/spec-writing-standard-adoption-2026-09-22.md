# 명세 문서 작성 규격 — 기정을 두고 공백만 채우는 안 (2026-09-22)

유저 답(2026-09-22): *"1.을 선택하되 추가적으로 기존 저작에도 적용함."* 선택지 1(열 공백을 채우되 게이트는 단계로
승격)을 채택하고, 새 저작에만 적용한다는 단서를 **기존 저작까지 확대**한다. "함께 확인할 것" 둘에 이견이 없었으므로
중복은 안전율 유지(제안 9.3 불채택), 상태 어휘는 `stable` 유지다.

## 파급효과

기존 저작에 적용할 때 실제로 걸리는 것은 **33건**이다. 전체 청크 파일 871개를 읽어 셌다.

| 규칙 | 위반 | 비고 |
|---|---|---|
| 메타 문장 | **2** | `p12-generated-document-form/conclusion.md` · `p0-classification-by-tags/conclusion.md` — 둘 다 "다음과 같다" |
| 채움 문구 | **0** | |
| 빈 값 이상 표기(`N/A`·`TBD`·`미정`) | **1** | |
| 손 번호 목록(`2.` 이상) | **30** | 그중 `verified` 도장 **5** — `p14-adoption-stages`·`p12-cognition-measurement`·`p11-agent-catalog-derives-scope`·`p11-inputs-are-parameters`·`p7-dev-kb-completion` |
| 목록 항목 > 9 | **0** | |
| 목록 중첩 3단계 | **0** | |

- **도장 5건이 유일한 마찰이다.** `STYLEGUIDE.md` §4가 "검증 뒤 내용을 고치면 게이트가 거부한다"고 정한다. 그 다섯은 편집 뒤 `endorse`로 재판정해야 한다. 나머지 25건은 도장이 없다.
- **닿지 않는 것**: frontmatter에 `verified`가 있는 파일 240개 가운데 235개는 위반 목록 밖이라 편집 대상이 아니다. 링크·복합체·IRI·라벨은 바뀌지 않으므로 `//kg:chunks_kg`의 링크 수와 복원 비율은 불변이다. `contentHash`는 편집한 33건만 바뀐다.
- **G2의 기존 적용은 청크가 아니라 문서 이관이다.** `docs/open-questions/` 11 파일을 `미확정` 슬롯으로 옮기는 것이며, 청크 695개에 빈 슬롯을 일괄 추가하는 것이 아니다. 일괄 추가하면 도장 240건이 전부 재판정 대상이 되어 유저 답의 취지(비용이 낮은 채움)와 어긋난다.
- **G3의 기존 적용은 편차 측정이 먼저다.** 대상은 요구 35 · 결정 200 · V&V 48이다. 현행 형태를 그대로 기술하므로 편차가 나오면 그것이 저작 편차의 실측치다.

## 반영 계획

1. **developer** — `tools/kb_lib.py`에 `PROSE_META`·`PROSE_FILLER`·`EMPTY_VALUE` 상수와 목록 규칙 검사(항목 수·중첩·손 번호·항목당 줄)를 더한다. 단일 정의처 규칙대로 상수는 `kb_lib` 하나다. `tools/consistency.py`에 축 둘(⑧ 첨가 · ⑨ 목록)을 보고로 낸다.
2. **orchestrator** — `STYLEGUIDE.md` §0에 세 빈 값(`없음`/`해당 없음`/`미확정`)·메타 문장 금지·채움 금지·목록 규칙을, §4에 `미확정` 선택 슬롯을 적는다. 결정 3건을 저작한다 — 빈 값의 세 뜻 · 슬롯은 질문 하나에 답한다 · 판정자 질문의 형식(noul·choice·score, 확신도 임계 셋, 자동화 전 20건 라벨링).
3. **developer** — `kb/ontology/shapes/profile-development-shapes.ttl`에 슬롯 표를 기술한다. 대상은 실물이 있는 여섯 — 요구 · 결정 결론·근거·대안 · 검증 목표 · 합격 기준 · 케이스. 슬롯마다 등록 질문 하나를 함께 적는다. **`--check` 보고를 먼저 내고 편차가 0이 아니면 3번에서 멈춘다.**
4. **developer** — 위반 33건을 고친다. 손 번호 30건은 `1.`로, 메타 문장 2건은 삭제하거나 주장 문장으로 바꾸고, 빈 값 1건은 세 값 중 하나로 바꾼다. **도장 5건은 편집 뒤 `endorse`로 재판정**한다(`bazel run //tools:endorse`).
5. **developer** — 미결 집계 뷰 `//kg:open`을 만들고 `docs/open-questions/` 11 파일을 `미확정` 슬롯으로 이관한다. 이관은 문서 삭제를 포함하므로 `//:doccheck_test`로 죽은 링크를 확인한다. `docs/README.md`·`roadmap.md`의 링크가 대상이다.
6. **보류 그릇** — G7 논평 틀은 `annotation` 첫 청크가 생길 때, G8 위험 틀은 항목 `vv-profile-hazards-2026-09-19`의 답이 올 때 함께 연다. 지금 만들면 쓰는 곳이 없다.
7. **게이트 승격** — ⑧·⑨의 보고 수치가 0이 된 뒤 `chunk_lint`로 올린다. 검사 강화는 약화가 아니므로 별도 승인이 필요 없다(`STYLEGUIDE.md` §2).

**같은 사실이 서술된 지점의 검색 키워드**(중복을 안전율로 용인하므로 전수 grep이 방어다):
`빈 값` · `없음` · `미확정` · `해당 없음` · `메타 문장` · `채움` · `목록` · `슬롯` · `판정자` · `확신도` · `open-questions` · `미결`.
문서 쪽은 `STYLEGUIDE.md` · `docs/rules.md` §1 · `docs/method.md` §4 · `docs/tools.md` 게이트 표 · `docs/roadmap.md`를 함께 본다.

## 확인 못 한 것

- 슬롯 shape가 기존 청크에서 내는 편차 수. 도구를 만들기 전에는 모른다. 편차가 크면 3번에서 멈추고 항목을 다시 연다.
- `미확정` 슬롯이 42줄 예산을 얼마나 먹는지. 슬롯 하나는 1~3줄로 잡았으나 실측이 없다.
- G9 판정자 형식의 효과. 규약만 적고 `judge` 도구는 V&V 프로파일 답 뒤이므로 이번에 재지 못한다.
- G10 그림 틀의 효과. 다이어그램을 담은 파일이 1개뿐이라 표본이 없다.
- 메타 문장 패턴 11개와 채움 문구 6개의 오탐률. 이번 스캔은 hci의 임시 스크립트이고 `kb_lib`에 들어갈 목록은 developer가 정한다.

## 판정

`apply`다. 유저 답이 선택지와 확대 범위를 모두 지정했고, 기존 저작 적용의 실측 비용이 33건으로 작아 **다시 물을 것이
없다.** 유일한 마찰인 도장 5건은 기존 절차(`endorse`)로 해소되며 게이트를 약화하지 않는다. 다만 G2와 G3의 "기존 적용"은
청크 일괄 편집이 아니라 각각 문서 이관과 편차 측정으로 읽었다 — 일괄 편집은 도장 240건을 재판정 대상으로 만들어 유저
답의 취지와 어긋나기 때문이다. 담당 역할이 다르게 읽으면 수행 전에 채널로 되돌린다.
