# 외부 서비스 없이 판정을 세운다 (2026-09-30 승인)

유저 답: *"1."* — **기계 환원을 먼저 하고 남는 둘(근거·라벨 대표성)만 세션 판정자가 맡는다.** 임계는 일치율로 바꾸고
자동 적용은 3지표 가운데 둘(정확도·판별력)이 재진 뒤에만 켠다.
"함께 답할 것"(`jev` 참고의 자리)에 이견이 없었으므로 hci 권고대로 **결정 `p8-judge-question-form` 의 근거에 출처로 남긴다**.

## 파급효과

**되돌릴 것 다섯** — 문자열 실측 **13곳**이 `cond-judge-service`·`asm-judge-service` 를 가리킨다.

| 산물 | 무엇을 뺀다 |
|---|---|
| `tools/judge.py`(383줄) | `call_service()`·`urllib` 호출·자격 환경 변수 셋·자격 없음 `EXIT_CONFIG` 갈래 |
| ODD | 조건 `id:cond-judge-service` 와 그 등록 |
| 그래프 | 가정 `id:asm-judge-service` 와 로그·주석의 `assumes` 링크 |
| 결정 | `p8-judge-calibration-binding` 의 외부 서비스 서술 |
| 문서 | `docs/tools.md` 의 `judge` 행·게이트 총람 문구 |

- **가정을 빼면 `assume_check` 의 영향 집합이 바뀐다.** 지금 판정 로그·결과 주석이 그 가정을 `assumes` 하므로, 빼기 전에 그 청크들의 `assumes` 를 먼저 고쳐야 그래프가 끊기지 않는다.
- **게이트 `judge-log` 의 필수 필드가 한 칸 바뀐다.** `kb_lib.JUDGE_LOG_FIELDS` 가 "모델 식별자"를 요구하는데 판정자가 세션이면 그 값은 **판정자 식별자**(세션·모델)다. 상수와 게이트 메시지를 함께 고친다.
- **임계의 뜻이 바뀐다.** 확신도가 자기 보고이므로 0.9 이상 자동 적용의 근거가 없다. 새 규칙은 **판정자 둘의 일치 + 미끼 검출**이다.
- 닿지 않는 것: 질문·척도 어휘 4파일과 shape · 선택 집합 255 상한 · 판정 로그와 결과 주석의 형식 · `--fixture` 경로. 그것들이 System One 참고의 산물이고 서비스와 무관하다.

## 반영 계획

1. **orchestrator — 청크의 `assumes` 먼저.** 판정 로그·결과 주석이 `id:asm-judge-service` 를 가리키는 링크를 걷어내거나 새 가정(세션 판정자의 전제)으로 돌린다. **이것이 2번보다 앞이다** — 순서를 바꾸면 그래프가 없는 가정을 가리킨다.
2. **developer — `judge.py` 정리.** 외부 호출과 자격을 뺀다. 지금 `--fixture` 를 **정식 입력 경로로 승격**한다 — 세션 판정자가 낸 값·확신도 JSON 을 받아 같은 검사·라우팅·로그를 돈다. 호출 수단이 없어져도 형 검사와 255 상한은 남는다.
3. **developer — 기계 환원 둘.** ① **요약** — `핵심:` 항목마다 지지 블록의 참조가 있는지 보는 검사(게이트 승격 가능) ② **중복·자리** — 후보 생성까지. 중복은 `consistency` ③(Jaccard)과 링크를, 자리는 슬롯 표지를 쓴다. 확정은 판정자 몫으로 남긴다.
4. **developer — `judge-log` 필드.** `kb_lib.JUDGE_LOG_TABLE_HEADER`·`JUDGE_LOG_FIELDS` 의 "모델 식별자"를 "판정자 식별자"로 고치고 게이트 메시지를 맞춘다. 기존 로그가 있으면 형식 변경이 append-only 와 부딪히는지 확인한다.
5. **orchestrator — 결정 둘.** ① `p8-judge-calibration-binding` 개정 — 외부 서비스 서술을 빼고 **임계 = 일치율**(판정자 둘 이상의 일치 + 미끼 검출), 자동 적용은 정확도·판별력이 재진 뒤. ② `p8-judge-question-form` 의 근거에 **참고 출처**를 적는다 — 질문의 형 셋과 확신도를 값으로 남기는 성질이 System One 의 참고이고 **서비스 도입은 아니었다**. 다음 세션의 같은 오독을 막는 문장이다.
6. **vnv — 세션 판정 절차.** 판정자 둘을 각각 새 세션으로 열고 같은 입력 상태에 같은 질문을 준다. 미끼는 `tools/label_sample.py` 가 이미 만든다(`--decoys`). 관측으로 남길 수치는 일치율·미끼 검출률·사람 재판정 일치다. **캘리브레이션은 재지 않고 "판정 불가"로 적는다** — 자기 보고 확신도로는 성립하지 않는다.

**검색 키워드**: `judge` · `call_service` · `AKB_JUDGE` · `cond-judge-service` · `asm-judge-service` · `확신도` · `임계` · `일치율` · `미끼` · `JUDGE_LOG`.

## 확인 못 한 것

- **세션 판정자를 무엇이 호출하는가.** 사람이 새 세션을 열어 질문지를 넘기는 절차인지, orchestrator 가 dispatch 하는지 정해지지 않았다. 2026-09-11 실험은 사람이 열었다.
- 일치율의 임계 수치. 2026-09-11 실험의 판정자 둘 일치 69/70 이 유일한 표본이다.
- 기존 판정 로그의 존재 여부와 형식 변경의 영향. 로그가 이미 커밋됐으면 append-only 가 걸린다.
- 요약 검사를 게이트로 올릴 때의 오탐률. `핵심:` 슬롯을 쓰는 청크 수를 세지 않았다.
