# 판정 서비스의 자격과 첫 측정 (2026-09-29 승인)

유저 답: *"1."* — **자격을 주고 첫 측정을 돌린다.**

## 파급효과

- 3지표(정확도·판별력·캘리브레이션) 측정이 시작된다. 2026-09-11 라벨 실험이 캘리브레이션에서 "판정 불가"로 끝난 상태가 처음 풀린다.
- 외부 서비스가 운영 조건이 된다 — ODD 조건 하나가 따라온다(승인 2026-09-26 의 "함께 답할 것").
- 게이트는 그대로다. 판정자는 `bazel run` 전용이고 게이트는 판정 로그의 형식만 본다.
- **자격 자체는 저장소에 들어오지 않는다.** 환경 변수로 주고 저장소·채널·로그에 키를 적지 않는다. 판정 로그에는 모델 식별자만 남는다.

## 반영 계획

1. **유저 — 자격 전달.** 엔드포인트·키·모델 식별자를 **셸 환경 변수로** 준다(`AKB_JUDGE_ENDPOINT`·`AKB_JUDGE_API_KEY`·`AKB_JUDGE_MODEL`). 채널이나 대화에 키를 붙여넣지 않는다 — 채널은 커밋되는 파일이다.
2. **developer — `call_service()` 를 맞춘다.** 지금 요청·응답 형식이 `미확정` 이다. 공개 문서가 필드 이름을 밝히지 않으므로 첫 호출의 응답으로 형식을 고정하고 고정물 키를 갱신한다.
3. **developer — ODD 조건 신설.** 판정 서비스 도달·모델 식별자·자격 존재를 조건으로 올린다. 판정 방법은 객관적 관측 수단이어야 한다 — 예를 들어 자격이 있을 때만 통과하는 도달 검사이고, 없으면 조건 미충족으로 `--fixture` 모드가 정상이다.
4. **vnv — 첫 측정.** 구간당 표본 20(결정이 정한 수)으로 정확도·판별력·캘리브레이션을 잰다. 미끼를 섞어 판별력을 보고, 결과를 관측으로 남긴다. 임계 셋(0.9 / 0.5)의 실측 정확도가 첫 산출이다.
5. **vnv — 3지표 실패 시.** 하나라도 실패하면 자동 적용을 켜지 않고 결과를 관측으로만 남긴다(노트 8.14 절차).

**검색 키워드**: `judge` · `call_service` · `fixture` · `확신도` · `임계` · `캘리브레이션` · `TYPESAFE` · `자격`.

## 확인 못 한 것

- 요청·응답 형식. 공개 문서에 없으므로 첫 호출이 알려준다.
- 이 저장소의 한글 산문에서 판정자가 내는 정확도. 측정 전에는 모른다 — 그것이 이 작업의 목적이다.
- 비용의 실측. 공개 단가로 한 회차 1달러 미만으로 추정했고 첫 측정이 실제 값을 낸다.

## 판정

`apply` 다. 다만 **1번은 유저의 작업**이고 그것 없이는 2~5번이 돌지 않는다. 자격이 오기 전까지 developer 는 고정물로 형식만
맞추고 기다린다.

## 정정 (hci, 2026-09-30)

환경 변수 이름은 `AKB_JUDGE_ENDPOINT`·`AKB_JUDGE_API_KEY`·`AKB_JUDGE_MODEL` 이다(`docs/tools.md` 의 `judge` 행). hci 가 적은 `TYPESAFE_API_KEY` 는 예시였고 도구가 읽는 이름이 아니다. 계획 1번을 고쳤다.

## 재검토 (hci, 2026-09-30) — 셋이 달라졌다

유저 요청으로 다시 조사했다. **자격이 "기다릴 것"이 아니다.**

### 1. 대기 명단이 없다

**2026-09-21 에 TypeSafe 가 대기 명단을 없앴다**(공개 6일 뒤). 누구나 `console.typesafe.ai` 에서 가입해 키를 만들 수 있고
**신규 계정에 $5 크레딧**(약 1.2억 입력 토큰)이 붙는다. 이전 조사 시점(2026-09-26)에 hci 가 그 변경을 놓쳤다 —
handoff 의 1번을 "유저가 자격을 준다"로만 적어 **어디서 얻는지를 적지 않았다.** 그것이 이 정정의 첫 항목이다.

### 2. 비용이 추정보다 두 자릿수 작다

hci 가 "한 회차 1달러 미만"이라 적었다. 실측하면 그보다 훨씬 작다 — 청크 954개의 본문이 **436,775자 ≈ 14.6만 토큰**이다.

| 규모 | 입력 토큰 | 비용 |
|---|---|---|
| 전 청크 × 질문 하나 | 14.6만 | **$0.006** |
| 전 청크 × 질문 여섯(게이트에 걸 전부) | 87만 | **$0.037** |
| 첫 측정(표본 60청크 × 질문 여섯 × 3구간) | 5.5만 | **$0.002** |

**$5 크레딧이면 전 청크 × 질문 여섯을 130회 이상 돌린다.** 비용은 판단의 변수가 아니고 크레딧만으로 충분하다.

### 3. 요청 형식이 미확정이 아니다 — 다만 출처가 엇갈린다

공식 개념 문서가 **`POST /v1/systemone`** 과 SDK 를 적고, 모델 경로는 **`jev-latest`** 다. 이차 출처 하나는 OpenAI 호환
`/v1/chat/completions` 라고 적는데 그것은 공개 직후의 서술로 보인다. **공식 문서의 경로를 먼저 시도하고** 실패하면 호환
경로를 본다. 필드 이름은 여전히 확인하지 못했다 — API 참조 페이지에 접근하지 못했다(404).

### 계획 1번을 고친다

| 옛 1번 | 새 1번 |
|---|---|
| 유저가 자격을 셸 환경 변수로 준다 | ① 유저가 `console.typesafe.ai` 에서 가입해 API 키를 만든다($5 크레딧, 대기 없음) ② 셸에 `AKB_JUDGE_ENDPOINT=https://api.typesafe.ai/v1/systemone`·`AKB_JUDGE_API_KEY=<키>`·`AKB_JUDGE_MODEL=jev-latest` 를 설정한다 ③ developer 가 첫 호출로 필드 이름을 고정한다 |

2~5번은 그대로다. **자격 없이 진행할 길도 적어 둔다** — `--fixture` 오프라인으로 형식·게이트·판정 로그를 검증할 수 있으나
3지표 가운데 **캘리브레이션은 고정물로 흉내낼 수 없다.** 대안 판정자(에이전트 세션 여럿의 일치율)는 확신도가 아니라 일치율이라
캘리브레이션 축을 채우지 못한다 — 2026-09-11 라벨 실험이 그 한계를 이미 보였다.

## 철회 (hci, 2026-09-30)

**이 인수인계는 무효다.** 유저가 항목의 `## 답` 을 고쳐 적었고 hci 가 그것을 읽지 않은 채 handoff 와 재검토를 썼다.

현재 답: *"jev를 직접 사용하지 않음. … 별도의 서비스를 활용하지 않게 다시 대처방안 마련해서 진행. 현 knowledge-base
프로젝트에서 지식의 구조화에 대해서 구상할때 jev의 방법론과 system one을 참고하라는 의미였음."*

**어긋난 경위.** 2026-09-29 에 답이 `1.` 이었고 hci 가 그것으로 handoff 를 썼다. 유저가 그 뒤 답을 위 문장으로 교체했다.
hci 는 2026-09-30 의 재검토에서 **항목의 답을 다시 읽지 않고** 접근 경로·비용만 조사해 "자격을 얻는 방법"을 덧붙였다.
재검토의 첫 단계가 원본 항목을 다시 읽는 것이어야 했다.

**더 앞선 오독도 있다.** 2026-09-26 항목 `jev-judge-binding` 을 hci 가 "판정자를 실제 System One 모델에 붙일 것인가"로
세웠다. 유저의 지시는 **`jev` 의 방법론과 System One 을 지식 구조화의 참고로 보라**는 것이었고 서비스를 도입하라는 것이
아니었다. 그 오독이 결정·도구·ODD 조건·가정까지 내려갔다.

계획 1~5번은 수행하지 않는다.
