# 판정자를 System One 모델에 붙인다 — 게이트 밖 보고로 (2026-09-26 승인)

유저 답: *"1."* — **게이트 밖 보고로 먼저 붙인다.** 판정자는 `bazel test` 밖의 도구이고 게이트는 판정 로그의 존재와 형식만
검사한다. 밀폐성이 깨지지 않는다. 함께 고칠 것은 J1~J5 다섯이다.

## 파급효과

- 결정 `p8-judge-question-form` 을 개정한다. 지금 임계 셋(0.9 / 0.5)이 **확신도의 뜻을 적지 않는다** — jev 의 캘리브레이션은 **집단 수준**이고 개별 답의 정확성을 보장하지 않는다.
- 도입 표본이 바뀐다. "20건 이상"은 구간 셋의 정확도를 재기에 부족하다 — 구간별 표본이 필요하다.
- Choice 의 cardinality 상한 **255** 가 규약에 들어온다. "같은 주장을 담은 블록은?"을 청크 780 후보로 물으면 넘고, 권고 패턴은 독립 점수 → 명시 선택의 2단계다.
- **판정자가 설명을 만들지 못한다.** 논평 틀의 `본문:`(문장 ≤4)을 판정자가 채울 수 없다 — 작성 주체를 정해야 한다.
- 외부 서비스가 운영 조건이 된다 — 네트워크·자격·모델 버전. 게이트 밖이므로 `bazel test` 는 그대로다.

## 반영 계획

1. **orchestrator — 결정 개정**(`supersedes`). 다섯을 적는다. ① 확신도는 **집단 수준의 캘리브레이션**이고 개별 답의 보증이 아니다 ② 임계별 정확도를 **구간마다 표본으로** 재며 20건은 하한이 아니라 구간당 하한이다 ③ Choice 는 닫힌 집합 **255 이하**이고 넘으면 점수 → 선택 2단계다 ④ 판정 결과의 논평 `본문:` 은 판정자가 아니라 **사람 또는 System 2 가 쓰거나 `해당 없음`** 이다 ⑤ 판정자 모델 식별자와 캘리브레이션은 **함께 버전이 바뀐다**.
2. **developer — `tools/judge.py`.** `bazel run` 전용이다. 질문·척도·임계를 프로파일 shape 에서 읽고, 결과를 판정 로그와 논평 청크로 낸다. 게이트에 넣지 않는다.
3. **developer — 게이트는 로그만 본다.** 판정 로그의 형식·필수 필드(질문 id·값·확신도·모델 식별자·입력 지문)를 `chunk_lint` 또는 새 검사가 본다. 외부 호출은 게이트 밖이다.
4. **developer — ODD 조건 하나.** 판정 서비스 도달·자격·모델 버전을 조건으로 올리고 판정 방법과 등급을 적는다. 게이트 밖 도구의 전제이므로 ODD 가 그 자리다.
5. **vnv — 3지표 측정.** 정확도·판별력·캘리브레이션을 구간별로 재고 결과를 관측으로 남긴다. 2026-09-11 라벨 실험이 캘리브레이션에서 "판정 불가"로 끝난 것이 기준선이다.

**검색 키워드**: `판정자` · `judge` · `확신도` · `임계` · `캘리브레이션` · `noul` · `choice` · `score` · `System One`.

## 확인 못 한 것

- 구간당 표본 수. 통계적 근거를 hci 가 정하지 않았다 — 구간 셋에 각 20건이면 60건이고, 라벨 실험의 60과 같은 규모다.
- API 접근 수단·비용 승인. 케이스당 약 $0.0004 이고 입력 100만 토큰당 $0.042 라는 공개 수치만 확인했다.
- 판정자가 이 저장소의 한글 산문에서 어떤 정확도를 내는지. 측정 전에는 모른다.
