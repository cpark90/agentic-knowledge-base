# "프로파일" 28건 — 옛 표기인가, 표준 용어인가 (orchestrator 중계)

원본: [`agents/orchestrator-consistency-cleanup-2026-09-12.md`](agents/orchestrator-consistency-cleanup-2026-09-12.md) 전달 2.

## 질문

`consistency` 보고의 ⑥ 옛 표기 검사에 "프로파일" 28건이 계속 잡힌다. orchestrator 는 **유지**로 판정했다 —
"개발 프로파일"·"V&V 프로파일"·"참조 프로파일"·"도메인 프로파일"은 전부 용어집이 표준으로 인정한
**도메인 프로파일**의 한정 형태라는 근거다. 보고는 계속 28건을 띄운다 — **보고의 소음을 남길지, 용어집을 고쳐 없앨지**가
유저 판단이다. 도구에 예외를 넣는 것은 검사 약화라 orchestrator 가 배제했고, 나도 동의한다.

## 이미 정해진 것

- 용어집이 산문 한글 용어의 원본이고, 없는 조어를 새로 만들지 않는다 (`docs/glossary.md`, 원장 19)
- "도메인 프로파일 / domain profile"은 **유지** 용어다 (용어집 행: OWL 2 profile 관용, ISO 34503)
- `consistency` 는 게이트가 아니라 **보고**다 — 판정은 사람 (`p4-redundancy-as-safety-margin`)

## 현재 상태 (hci 재실측 2026-09-12)

- 보고 ⑥ 잔존 28건 = "프로파일" 27파일 + `verifier/`(디렉토리명) 1.
- 용어집의 해당 행은 표준 용어 열에 "도메인 프로파일", 옛 표기 열에 "프로파일"이다.
- **orchestrator 의 유지 근거("전부 도메인 프로파일의 한정 형태")는 실측과 다르다.** 27파일의 출현을 전부 세면
  **한정 있음 24 · 한정 없음 40**이다 (개발/V&V/도메인/참조/RL 등의 수식어가 앞에 붙은 것과 아닌 것).
  한정 없는 40건의 대부분(24건)은 `p2-skeleton-and-domain-profile` — "프로파일은 코어를 확장만 하는 온톨로지 모듈이다"처럼
  **그 결정이 정의하는 대상 자체**를 가리킨다. 나머지는 "코어와 프로파일을 나누고", "프로파일 규칙(d-0057)",
  "정당한 축소 프로파일"처럼 첫 언급 뒤의 단축형이다.

즉 판단할 것은 "보고가 한정 형태를 잘못 잡는가"가 아니라 **"한정 없는 단축형 '프로파일'을 표준으로 인정하는가"**다.

## 답이 가르는 것

- **용어집을 고치면**(옛 표기 열에서 "프로파일" 삭제) 보고가 0이 되고, 앞으로 한정 없는 "프로파일"도 잡히지 않는다 —
  드리프트를 조금 허용하는 대신 보고가 조용해진다.
- **그대로 두면** 보고가 매번 28건을 띄우고, 사람이 매번 "유지 판정"을 되풀이한다. 진짜 오염이 섞여 들어와도 묻힌다.

## 선택지

1. **단축형을 표준으로 인정**(권고) — 용어집의 옛 표기 열에서 "프로파일"을 빼고, 표준 용어 열을 "도메인 프로파일
   (단축형 프로파일)"로 적는다. 근거: 한정 없는 40건 중 24건이 `p2-skeleton-and-domain-profile` 의 정의 대상이라
   "도메인 프로파일"로 바꾸면 오히려 어색하고(이 체계의 프로파일은 도메인만이 아니라 V&V·참조도 있다),
   첫 언급에 한정을 붙이고 이후 단축하는 것은 표준 관행이다. `consistency` ⑥ 이 0이 되어 새 오염만 뜬다.
   담당 역할이 용어집 한 줄 수정.
2. **한정을 강제** — 40건을 "도메인/개발/V&V/참조 프로파일"로 고친다. 용어집을 그대로 두므로 드리프트가 0으로 유지된다.
   비용: 청크 20여 개 수정 + 그만큼 판정 도장이 물러난다(`trust-shapes`), 정의 대상 문장이 어색해진다.
3. **보고는 그대로, 판정 기록만 채널에** — 28건을 "판정 완료, 유지"로 알려진 소음으로 둔다. 비용: 매 보고마다 사람이
   걸러야 하고, 진짜 오염이 섞여 들어와도 묻힌다.
4. 도구에 예외 목록 — 배제(검사 약화).
