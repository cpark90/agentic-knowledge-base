# 자연어의 모호성과 지식 구조 — 조사와 규칙 제안

## 1. 요약

자연어만으로 지식을 쌓으면 문장과 문단을 잇는 말(지시어·접속사·문단 순서)이 곧 구조가 된다. 그 구조는 독자마다 다르게 읽히고, 언어모델은 모호한 곳에서 묻지 않고 조용히 가정한다. 최근 연구는 이 손실을 수치로 보여준다 — 모호한 요구에서 코드 생성 정확도가 28포인트 넘게 떨어지고, 같은 요구가 실행마다 양립 불가한 구현으로 갈리며(모델 간 57%), 모델의 모호성 감지는 재현율 85%에 정밀도 50%, 위치 특정은 23%를 넘지 못한다. 반대로 같은 과제를 표현만 바꿔 주면 정확도가 12.5%에서 100%까지 갈린다.

제안은 하나의 원칙과 그 적용이다. **구조·연결·조건·어휘는 형식으로 옮기고, 자연어에는 원자 문장 하나만 남긴다.** 남은 문장에는 통제 자연어 규칙을 적용해 지시어·접속사·정도 부사·양화를 금지하고, 모호성은 "여러 번 독립적으로 형식화해 동치인가"로 측정해 미확정의 한 종류로 다룬다. 자연어 산문은 사람이 읽는 투영이지 소스가 아니다.

## 2. 문제

| 자연어가 맡고 있는 일 | 생기는 불확실성 |
|---|---|
| 연결 — "이것", "위에서 말한", "따라서", "하지만" | 가리키는 대상과 관계의 종류(근거인가, 조건인가, 순서인가)가 해석에 달린다 |
| 구조 — 문단 순서, 제목, 접속사 | 부분–전체·정제·의존 관계가 암시로만 있다. 기계는 읽지 못하고 사람은 다르게 읽는다 |
| 조건·양화 — "~인 경우", "충분히", "대부분", "가능하면" | 판정할 수 없다. 언제 만족되는지 정해지지 않는다 |
| 어휘 — 같은 개념의 다른 말, 다른 개념의 같은 말 | 검색·대조·중복 판정이 실패한다 |
| 시간 — "현재", "최근", "이전 버전" | 언제를 기준으로 참인지 없다 |
| 행위자 — 수동태, "처리된다" | 누가 하는지 없다 |

이 여섯이 자연어로 남아 있는 한, 지식의 각 조각이 정확해도 조각 사이의 관계가 불확실하다. 불확실성은 조각 수에 비례해서가 아니라 연결 수에 비례해 는다.

## 3. 모호성의 분류

| 종류 | 예 | 출처 |
|---|---|---|
| 어휘적 | "pattern" — 부분 문자열인가 정규식인가 | Clarity Is Not Assumed (2604.21505) |
| 구문적 | 대명사·수식어의 걸림 — "A와 B의 로그를 삭제" | 같은 곳 |
| 의미적 | 문맥에 따라 뜻이 갈리는 구 | 같은 곳 |
| 모호함(vagueness) | 빠진 세부 — "적절한 부분집합" | 같은 곳 |
| 연결의 모호 | 지시어·접속사가 무엇을 무슨 관계로 잇는지 | 본 문서 |
| 양화·조건의 모호 | "대부분", "필요하면", "~인 경우"의 경계 | INCOSE 요구 작성 지침 |
| 시간의 모호 | "현재", "최신" | 같은 곳 |
| 행위자의 모호 | 수동태, 약한 동사(support, handle, manage) | 같은 곳 |

## 4. 조사 결과

### 4.1 자연어를 그대로 두면 생기는 일

| 발견 | 수치 | 출처 |
|---|---|---|
| 언어모델은 모호한 요구에서 묻지 않고 조용히 하나의 해석을 고른다 | 명확한 벤치마크 대비 정확도 −28pt 이상 (GPT-4). 실행마다 다른 구현, 충돌률 2배, 모델 간 불일치 57% | Clarity Is Not Assumed (2604.21505) |
| 모호성 감지는 되지만 위치를 못 짚는다 | 재현율 ~85%, 정밀도 ~50%, 위치 특정 ≤ 23%, 해소 < 60% | 같은 곳 |
| 코드 생성 능력과 명확화 능력은 별개다. 추론을 강화해도 모호성 식별은 거의 늘지 않는다. 모호성이 여러 개면 급격히 무너진다 | 6개 SOTA 모델, 턴 할인 핵심 질문율로 측정 | ClarifyCodeBench (2607.00711) |
| 같은 과제도 표현이 다르면 성능이 다르다. 자연어 자체가 병목 | 논리 회로 과제, 15가지 표현: 불리언 식 100% ↔ 신호 전파 서술 12.5% | Shaping Schema via Language Representation (2605.09271) |

### 4.2 형식으로 옮기면 생기는 일

| 발견 | 수치 | 출처 |
|---|---|---|
| 표현의 네 수준 — 0 모호한 자연어 / 1 구조화 형식 / 2 논리 제약(코드·수학) / 3 과학적 형식화. 수준이 오를수록 모델 내부 스키마가 안정 | 스키마 불일치(KL)가 예측 오차의 상한 | Shaping Schema (2605.09271) |
| 자연어 → 형식 명세 번역은 범위가 좁을수록 된다 | LTL 번역 최대 94.4%, 하드웨어 단언 89%, Dafny 단언 50%+, 전체 계약 합성은 일관성 없음 | Short Survey on Formalising Requirements (2506.11874) |
| 여러 번 독립 형식화해 동치가 아니면 그것이 모호성이다. 반례로 되먹임하면 검증 정확도가 오른다 | 55.4% → 98.5% (혈액투석 안전 요구). 반례가 세밀할수록 효과 큼 | VERIMED (2605.13817) |
| 사람 검토는 여전히 필요하다 — 특히 단언 수준을 넘는 명세에서 | 반복 정제(nl2spec) · 신경-기호 혼합(SAT-LLM) · 검색 보강 | Short Survey (2506.11874) |

### 4.3 통제 자연어(CNL)의 위치

| 체계 | 무엇을 통제하는가 | 남는 모호성 |
|---|---|---|
| EARS | 요구 문장의 형 6가지(ubiquitous · event · state · unwanted · optional · complex). 조건·트리거·응답의 자리 고정 | 응답 구의 내용, 어휘 |
| ISO/IEC/IEEE 29148 · INCOSE 지침 | 요구의 특성(단일·검증 가능·비모호)과 금지어 — 약한 동사, 수동태, 정도 부사, 열린 목록("등"), 대명사, 부정 중첩 | 문장 안의 의미 |
| ASD-STE100 | 어휘 약 900단어, 단어당 뜻 하나, 문장 길이·시제 제한 | 문서 구조 |
| Attempto Controlled English | 영어 부분집합을 1차 논리로 무손실 번역 | 표현력 |
| Gherkin | Given/When/Then의 자리 | 각 절의 내용 |

통제 자연어는 문장 안의 모호성을 줄이지만 문장 사이(연결·구조)는 다루지 않는다. 그 부분은 슬롯·링크·문서 틀이 맡아야 한다.

## 5. 원칙 — 자연어의 자리

| 정보의 종류 | 표현 수단 | 자연어의 역할 |
|---|---|---|
| 관계 (근거 · 정제 · 검증 · 대체 · 의존 · 부분) | 타입 있는 링크, `[#id]` 참조 | 없음 |
| 구조 (문서 · 섹션 · 블록 · 슬롯) | 문서 틀 · 블록 틀 · 슬롯 키워드 | 없음 |
| 조건 · 양화 · 범위 · 판정 | 판정식(CEL) · 범위 표기 · 표 | 없음 |
| 어휘 (개념 · 역할 · 요인 · 환경) | 온톨로지 라벨, 닫힌 집합에서 선택 | 라벨의 정의문 하나 |
| 시간 | ISO 8601, 리비전 해시 | 없음 |
| 행위자 | 카탈로그 역할 · 도메인 모델 actor | 없음 |
| 사실 · 요구 · 결정 · 정의 | **원자 문장 하나**, 통제 자연어 | 여기 |
| 의도 · 이유 · 설명 | 문장 ≤ N, 근거 판정으로 감쌈 | 여기 |

자연어는 두 자리에만 남는다 — 원자 문장과 이유. 나머지는 형식이다. 이유와 의도까지 형식화하면 오히려 정보가 빠지므로, 그 둘은 자연어로 두되 "입력에서 지지되는가"를 판정자가 묻는다.

## 6. 규칙 — 자연어 문장 슬롯

### 6.1 문장의 형

| 규칙 | 내용 | 검사 |
|---|---|---|
| 한 문장 한 술어 | 주어 – 술어 – 목적어 하나. 둘이면 문장 둘 또는 항목 둘 | lint — 접속 어미·"및"·"그리고" |
| 슬롯마다 문장 형 고정 | 요구는 EARS, 정의는 "<상위> 중 <종차>인 것", 검증 목표는 "<대상>은 <성질>을 보여야 한다", 가정은 "~라고 가정한다", 원칙은 명령문 | shape |
| 행위자 명시 | 수동태와 행위자 없는 문장 금지. "처리된다" → "<역할>이 처리한다" | lint — 피동 어미 |
| 약한 동사 금지 | 지원한다 · 처리한다 · 관리한다 · 다룬다 · 고려한다 → 관측 가능한 동사로 | lint — 어휘 |
| 열린 목록 금지 | "등", "기타", "…" 로 끝나는 열거 금지. 목록은 닫혀 있거나 `미확정` | lint |

### 6.2 연결의 금지

| 금지 | 예 | 대신 |
|---|---|---|
| 지시어 | 이 · 그 · 해당 · 위의 · 아래의 · 앞서 · 후술 | `[#id]` |
| 논리 접속사 | 따라서 · 그러므로 · 그래서 · 하지만 · 그러나 · 왜냐하면 | 슬롯(`근거:` · `반박:`) 또는 링크 |
| 순서 접속사 | 먼저 · 그 다음 · 마지막으로 | 절차 목록 |
| 열거 접속사 | 및 · 그리고 · 또한 · 또는 | 항목 둘, 또는 판정식의 `&&` `\|\|` |

### 6.3 조건 · 양화 · 정도의 외부화

| 자연어 | 형식 |
|---|---|
| "~인 경우", "~일 때", "~이면" | `조건:` 펜스(CEL) 또는 EARS의 When/While/If 자리 |
| "이상", "이하", "최대", "약" | 범위 표기 `[a..b]`, 단위 명시 |
| "대부분", "일부", "거의", "보통" | 비율·개수, 또는 `미확정` |
| "충분히", "적절히", "빠르게", "안정적으로" | 판정식 또는 척도(상황으로 정의) |
| "가능하면", "필요하면", "원칙적으로" | 삭제, 또는 `optional` 패턴 + 조건 |
| "현재", "최근", "기존" | 리비전 해시 · ISO 8601 · `[#id]` |
| "중요한", "핵심적인" | 삭제. 중요도는 우선순위 슬롯 |

옮길 수 없는 표현은 문장에서 빼고 `미확정:`에 적는다.

### 6.4 어휘

| 규칙 | 내용 |
|---|---|
| 라벨 하나 | 같은 개념은 온톨로지 `rdfs:label` 하나로. 동의어는 `altLabel`(색인용), 본문 금지 |
| 정의는 속 + 종차 | "<상위> 중 <종차>인 것". 순환 정의·예시로 대체 금지 |
| 새 용어는 제안 | 라벨에 없는 말은 본문에 쓰지 않고 용어 제안 워크플로로 |
| 단어당 뜻 하나 | 한 문서 안에서 같은 단어를 두 뜻으로 쓰지 않는다 |

## 7. 모호성의 검출과 처리

### 7.1 세 층

| 층 | 방법 | 잡는 것 |
|---|---|---|
| lint (결정론) | 6절의 금지 패턴 | 지시어 · 접속사 · 정도 부사 · 피동 · 약한 동사 · 열린 목록 |
| 다중 형식화 (VERIMED 방식) | 같은 문장을 N번 독립적으로 판정식·논리로 옮기고 동치를 검사한다. 동치가 아니면 모호 | 의미적 모호, 양화 경계 |
| 다중 해석 (Clarity 방식) | 같은 문장에서 구현·케이스를 k개 생성해 분기하면 모호 | 빠진 세부, 함축된 가정 |

### 7.2 처리

| 규칙 | 내용 |
|---|---|
| 모호는 미확정의 한 종류 | 판정 결과가 "모호"이면 문장을 본문에서 빼고 `미확정:`에 "<문장> — 해석 A / 해석 B"로 옮긴다 |
| 조용한 가정 금지 | 에이전트는 모호한 문장을 한 해석으로 좁혀 쓰지 않는다. 해석이 필요하면 가정 블록으로 명시하고 판정식을 붙인다 |
| 반례로 되먹임 | 다중 형식화가 갈린 지점의 구체적 반례(어떤 입력에서 두 해석이 다른가)를 미확정 항목에 붙인다 |
| 위치는 슬롯 단위 | 모델의 위치 특정이 약하므로 "어느 슬롯이 모호한가"까지만 요구하고 문장 안의 위치는 요구하지 않는다 |
| 밀도 상한 | 한 블록에 모호 항목이 3개를 넘으면 블록을 반려한다 — 다중 모호에서 해소율이 급락 |

### 7.3 판정 질문

| 질문 | 형 |
|---|---|
| 이 문장의 형식화 N개는 서로 동치인가 | noul (기호 검사가 우선, 판정자는 보조) |
| 이 문장은 하나의 해석만 갖는가 | noul |
| 이 문장이 가리키는 대상은 무엇인가 | choice {ID 목록, 없음} |
| 이 조건은 어느 입력에서 참인가 | 반례 생성 (기호) |

## 8. 남겨두는 자연어

| 자리 | 허용 | 감싸는 장치 |
|---|---|---|
| 결정의 의도, 근거의 보증 | 문장 ≤ 3 | 근거 판정("입력에서 지지되는가"), 한정 슬롯 = 가정 링크 |
| 설명 블록 | 문장 ≤ 8 | 예산, 메타 문장 금지, 관련 `[#id]` |
| 라벨의 정의문 | 문장 1 | 속 + 종차 형 |
| 논평 | 문장 ≤ 4 | Conventional Comments 라벨, 대상 슬롯 ID |

이 네 자리 밖의 자연어 산문은 소스가 아니라 렌더러가 만드는 투영이다.

1. **절반은 2026-09-22에 이미 들어왔다.** 슬롯 = 질문 · 빈 값 셋 · `미확정` 슬롯 · 첨가 금지 · 목록 규칙 · 판정자 질문 형식이 명세 규격 반영으로 게이트와 결정이 됐다. 제안 7.3의 판정 질문 형은 결정 `p8-judge-question-form` 과 같은 형이다.
2. **새것은 문장 층의 금지 패턴 일곱과 슬롯별 문장 형이다.** 기존 저작에서 실측하면 **828건**이 걸리고 그중 **피동 416건(315 파일)**이 절반이다.
3. **모순이 하나 있다.** 제안 6.2는 지시어를 `[#id]` 로 대체하라 하는데 이 저장소는 `[#id]` 를 **불채택**했다(인용 2043건·690 파일). 대체 수단 없이 지시어를 금지할 수 없다.
