# 링크를 더 유연하고 견고하게 — 조사 결과와 선택지 다섯 (2026-09-18, 2차 재검토 2026-09-19)

> **정정 (2026-09-19 재검토).** 1차에 쓴 "링크 모델이 실제 링크의 39%만 덮는다"는 **분모를 잘못 잡은 것이다.**
> `assumes`(634)는 청크 → 가정이고 `usesConcept`(136)는 청크 → 온톨로지 개념이라 둘 다 `agt:Link` 의 치역
> (`KnowledgeItem`)에 애초에 들어가지 않는다. 저작된 청크 간 링크만 세면 `refines` 370 + `supersedes` 134 = 504 가
> **전부** 링크 개체와 증거를 갖는다. 아래 현재 상태와 선택지 A 를 그에 맞게 다시 썼다. 결론은 약해지지 않고
> **자리를 옮긴다** — 문제는 모델이 덮지 못하는 것이 아니라 모델이 **켜지지 않은 부분**이다.

원문 요청: [`inquiries/suggestion.md`](inquiries/suggestion.md) — "노드간의 링크를 좀 더 flexible하고 robust하게 하려면 어떻게 해야할지 조사해줘."

조사 셋을 합쳤다. ① 이 저장소의 링크 실물 측정 ② 참조 저장소(`~/git/agrtls`) 전 repo 의 링크 유지 기법
③ 외부 표준·문헌(W3C RDF·PROV-O·SKOS·Web Annotation·RFC 5147·Akoma Ntoso·나노출판·추적성 도구).

**근거의 확인 수준.** 조사자가 1차 출처를 두 번 확인한 것과 그러지 못한 것을 갈라 둔다 — 아래 선택지를 청크로 저작할 때
미확인분은 출처를 한 번 더 걸러야 한다.

| 강도 | 무엇 |
|---|---|
| **두 번 확인** | 링크 속성 모델 비교 전체(RDF 1.2 의 표준화 단계·reification 무의미론·그래프 이름 경고·두 실측 벤치마크·Wikidata 덤프 구조) · PROV-O 의 "정성 형태는 이항을 함의하고 등가 이항을 함께 싣기를 권장" · Akoma Ntoso 의 `wId`/`eId` · Web Annotation 의 다중 셀렉터 문면과 "소비자는 하나를 골라야 한다" · 앵커 고아율 27.3%와 재부착 3.5% · DOORS Next 7.0 의 link validity 통합 · SKOS 의 이중 상속·비전이·하위 속성 지침 · **RFC 5147** 의 `length=`·`md5=` 구문과 "변경을 탐지하게 한다"는 취지(복구 장치가 아니다) · PROV-O 의 `wasInfluencedBy` 상위 술어 방침("적용 가능하면 구체 하위 술어를 쓴다") · w3id.org 의 성격(W3C 가 운영하지 않는 공동체 약속) · 나노출판의 불변 규율(발행분은 고치지 않고 `npx:supersedes` 로 대체하거나 `npx:retracts` 로 철회한다) · DCMI dumb-down 원칙 |

| **확인 실패 — 인용하지 않음** | ISO/IEC/IEEE 29148 의 조항 번호와 식별자 인용(유료 표준, 원문 대조 실패) · Trusty URI 의 블랭크 노드 제약 · Memento·Robust Links 세부 · Hypothes.is 앵커링 문서(접근 실패 — 필요하면 클라이언트 소스를 직접 읽는다) |

## 질문

링크는 지금 **frontmatter 의 IRI 목록**이고, 도구가 그것을 `agt:Link` 개체와 증거 항목으로 구체화한다. 이 모델을 어디까지
넓힐 것인가가 정해지지 않았다. 넓히는 축이 둘이라 함께 물어야 한다 — **유연성**(무엇을 가리킬 수 있는가, 새 관계를 어떻게
더하는가)과 **견고성**(양 끝이 바뀌어도 링크가 살아남는가, 붕괴를 언제 알아차리는가). 비용이 큰 것과 작은 것이 섞여 있어
한 번에 고를 문제가 아니다.

## 이미 정해진 것

설계는 이미 상당히 유연하다 — **구현이 따라가지 못하는 것이 문제의 절반이다.**

| 노트 | 무엇을 정했나 |
|---|---|
| 9.11 | 모든 링크가 `when`(ODD 속성·가정 위의 CEL 술어)을 가질 수 있다. **`assumes`·스코프 조건·링크 조건이 한 메커니즘**이고, 무효화 전파는 `when` 이 거짓이 된 링크를 따라가는 것이다 |
| 9.11 | 링크 상태는 **저장값이 아니라** `when` 평가 + 증거 규칙(구축·실행·제안 × 극성)의 결과다. 확률로 합산하지 않는다 |
| 10.4 | 후보 → 제약 검사 → 판정 → 확정. 임베딩 유사도는 후보를 추리는 데만 쓴다 |
| 10.5 | 링크는 산출물 본문 밖(head·`-space`)에 둔다. plane 마다 **앵커 해석기**를 두고 링크 모델은 앵커가 무엇을 가리키는지 모른다 |
| 10.6 | `valid`/`suspect`/`invalid`, 트리거는 변경 통지, 재판정은 재검증 시점에 일괄 |
| 10.10 | 링크의 속성 — 타입·양 끝·상태·근거·만든 주체·확인한 주체·시각 |
| 10.11 `[안]` | 재판정 규칙 카탈로그(라벨만 변경 → 영향 없음, 분할 → 두 새 IRI 로 복제해 각각 후보, 폐기 → invalid …) |

어휘의 유연성 훅도 이미 있다 — `serves ⊑ refines`, `supersedes ⊑ prov:wasRevisionOf`, `cites ⊑ references ⊑ dependsOn` 처럼
고유 관계가 표준 관계 아래 잎으로 달려 있다.

## 현재 상태 (실측, 2026-09-19 재검증)

| 관계 | 수 | 무엇을 가리키나 | 링크 모델 안인가 |
|---|---|---|---|
| `refines` | 370 | 청크 → 청크 (저작) | **예** — 링크 개체 + 구축 기록 증거 |
| `supersedes` | 134 | 청크 → 청크 (저작) | **예** — 같음 |
| `cites` | 30 | 청크 → 청크 (**본문에서 추출**) | 아니다 — 평범한 트리플 |
| `usesConcept` | 136 | 청크 → 온톨로지 개념 (**본문에서 추출**) | 아니다 (치역이 지식 항목이 아니다) |
| `assumes` | 634 | 청크 → **가정** | 아니다 (치역이 `agt:Assumption`) |
| `part_of` | 564 | 복합체 구성 | 아니다 — **구성은 링크가 아니다**(4.5절, 두 메커니즘은 겹치면 안 된다) |

**저작된 청크 간 링크는 504/504 = 100% 가 링크 개체를 갖는다.** 모델이 적용되는 자리에서는 건강하다. 문제는 네 곳이다.

| 공백 | 실측 |
|---|---|
| **본문에서 추출한 참조가 후보가 아니다** | `cites` 30 + `usesConcept` 136 = 166 이 상태 없이 단언된다. `agt:CandidateLink` 는 어휘에 있고 **실물 0** — 추출 참조가 바로 그 자리다(10.4절: 복원은 후보로 시작한다) |
| **조건이 링크에 닿지 않는다** | `assumes` 634 는 9.11절이 말하는 `when` 의 특수형인데, 청크에만 붙고 **그 청크의 링크로 전파되지 않는다**. `assume_check` 는 깨진 가정의 영향 *청크*를 계산하고 영향 *링크*는 계산하지 않는다. `when` 실물 0 · `suspect` 실물 0 |
| **링크 정체성이 양 끝에 묶여 있다** | IRI = `sha256(출발\|종류\|도착)[:12]`. 분할·병합으로 IRI 가 바뀌면 링크 개체가 다른 것이 되어 증거·이력을 실어 나를 수 없다 |
| **가리키는 단위가 청크 전체뿐** | 문장·조항을 가리킬 수단이 없다. 노트 10.5절이 "plane 마다 앵커 해석기"를 정했으나 해석기도 selector 어휘도 없다 |

이미 닫혀 있는 것 — 무주공산 폐기 **0** · 살아 있는 청크가 폐기 청크를 가리키는 stale 링크 **0** · 증거 없는 확정 링크 **0**.
`satisfies`·`verifies`·`serves`·`constrains` 가 0인 것은 링크 모델의 결함이 아니라 계약·스키마·구현 plane 이 비어 있어서다.

## 답이 가르는 것

- **유연성을 먼저 사면**(선택지 C) 문장·조항 단위를 가리킬 수 있게 되지만, 실측 고아율이 27%인 영역이라 재앵커링 도구와
  "추측/고아"를 드러내는 규율이 함께 와야 한다. 비용이 가장 크다.
- **견고성을 먼저 사면**(A·B·D) 지금 있는 링크가 깨지지 않게 되지만 가리키는 단위는 여전히 청크 전체다.
- **아무것도 하지 않으면** 후보·확정 절차가 데이터를 갖지 못한 채로 남고(후보 0), 무효화가 링크에 도달하지 못하며,
  분할·병합이 시작되는 순간(42줄 상한이 강제한다) 링크의 증거와 이력이 조용히 사라진다.
- 다섯은 **따로 고를 수 있다.** 의존은 C→B 하나(세밀한 앵커가 의미를 가지려면 정체성이 먼저 안정돼야 한다).

## 선택지

### A. 본문 추출 참조를 후보 링크로 (권고, 비용 낮음)

`extract_refs` 가 본문에서 뽑는 `cites` 30·`usesConcept` 136 은 지금 상태 없이 단언된다. 저작된 링크와 **증거의 질이 다른데
표기가 같다** — 하나는 편집의 부산물(구축)이고 하나는 사후 추출(복원에 가깝다).

- 이 저장소에 맞게: 추출 참조를 `agt:CandidateLink` 로 만들고 증거 종류를 구축 기록이 아닌 것으로 단다. 어휘는 이미 있고
  실물이 0이다. 그러면 10.4절의 "후보 → 제약 검사 → 판정 → 확정" 절차가 **처음으로 데이터를 갖는다**.
- 덤으로 3단계 지표가 정직해진다 — 지금은 사후에 이은 링크도 구축 기록으로 표기돼 복원 비율이 실제보다 낮다
  (1단계 마감 때 이은 28건이 그렇다). 참조 저장소의 규칙과 같은 자리다: **자동 추론이 못 가르는 것은 선언한다.**
- `assumes`·`part_of` 는 넣지 않는다 — 전자는 가정(조건)이고 후자는 구성이다. 링크로 만들면 두 메커니즘이 겹친다.
- 비용: `extract_refs` 의 방출 형태 + `chunk2kg` 의 증거 종류 한 줄. 위험: 낮음.

### B. 링크 정체성을 양 끝에서 떼기 + 분할·병합 규율 (권고, 비용 낮음)

링크 IRI 가 양 끝의 해시라 분할·병합이 링크 이력을 끊는다. 외부에 정착된 해법은 **2단 식별자**다 — Akoma Ntoso(OASIS)는
`wId`(work-level, **절대 바뀌지 않는다**)와 `eId`(expression-level, 재번호매김 시 바뀐다)를 나눠 조항 재배치에도 링크를 유지한다.

- 이 저장소에 맞게: 청크 uuid 를 `wId` 자리로 확정하고, **분할 시 조각 하나가 원 uuid 를 승계**하고 나머지는 새 uuid +
  `prov:specializationOf`(같은 것의 다른 입도)로 잇는다. 지금 쓰는 `wasDerivedFrom` 만으로는 "같은 것"과 "새로 만든 것"이
  구분되지 않는다. 링크 IRI 는 양 끝 해시 대신 **생성 시각·주체를 포함한 안정 식별자**로 바꿔 증거를 실어 나른다.
- 같은 규율의 외부 선례: **나노출판**은 발행분을 고치지 않고 새 판본이 `npx:supersedes` 로 이전을 가리키며, 철회는 별도 발행분의 `npx:retracts` 다 — 우리 `supersedes` + 새 IRI 와 같은 형태다.
- 참조 저장소의 같은 규칙: 분할 시 **조항 번호 보존 + 원 자리에 포인터 한 줄**(그쪽 L18). 번호 재배치가 인용 66곳을
  한꺼번에 거짓으로 만들 뻔한 사고가 근거다.
- 비용: 어휘 2개 + 규칙 한 절 + `chunk2kg` 의 IRI 계산. 위험: 승계 규칙이 자의적이면 링크가 엉뚱한 조각으로 간다.

### C. 링크 종점에 selector 층 — 문장·조항을 가리킨다 (유연성의 핵심, 비용 큼)

지금 링크는 **청크 전체**만 가리킨다. W3C Web Annotation Data Model(REC)이 표준 어휘를 준다 — `TextQuoteSelector`(exact +
prefix/suffix) · `TextPositionSelector` · `RangeSelector` · `refinedBy`(문단 → 구절 좁히기).

- **다중 셀렉터가 견고성의 정의다**(스펙 문면: "발견 가능성을 최대화하기 위해 여러 셀렉터를 준다"). 다만 스펙은 소비자가
  하나를 골라야 한다까지만 정하고 **폴백 순서를 규정하지 않는다** — 우리가 정해야 한다. 실제 구현(Hypothes.is)의 사슬은
  Range → Position → quote(위치는 힌트로만) → 퍼지 탐색이고, **위치로 잡은 텍스트가 exact 와 다르면 폐기**한다.
- 무결성 장치의 유일한 IETF 선례는 RFC 5147 의 `length=`·`md5=` — 오프셋 앵커가 가리키는 대상이 바뀌었는지 **탐지**한다.
- **실패율을 먼저 알고 들어가야 한다**: 유일한 정량 연구에서 앵커 6,281개 중 **27.3%가 고아**였고, 고아 중 3.5%만 재부착
  가능했다. 운영 교훈은 "숨기지 말고 고아를 별도로 드러내라"이고, 이것은 참조 저장소가 독립적으로 도달한 규칙
  ("행이 없다는 것은 판정할 것이 없다는 뜻이 아니다")과 같은 자리다.
- 참조 저장소에는 **선례가 없다** — 기계가 아는 최소 단위가 문서이고 조항 지시는 사람 관례로만 존재한다. 공백이다.
- 비용: 온톨로지 모듈 1~2 + frontmatter 링크 항목의 객체형 확장(`sources:` 가 이미 객체형이라 선례는 있다) + 재앵커링 도구.
- 단계적으로: 청크 전체 링크는 그대로 두고 selector 는 `refinedBy` 식 **정제로만** 얹는다. 그러면 실패해도 링크는 산다.

### D. `when` 구현 — 설계된 통일 메커니즘을 켠다 (비용 중간)

`assumes`·스코프 조건·링크 조건이 한 메커니즘이라는 9.11 의 설계를 실물로 만든다. 상태는 여전히 저장하지 않고 조건 평가와
증거 규칙의 결과로 두되, 계산 결과를 **생성물로 물질화**해 매 질의 재계산을 피한다(`bazel-bin` 에만 — 문서는 생성물 규칙과 충돌 없음).

- 참조 저장소가 독립적으로 같은 결론에 왔다: 링크 상태를 저장하지 않고 (출발 상태 × 도착 상태 × 관계)로 매번 유도하며,
  **죽은 문서끼리의 링크는 예외**로 둔다("폐기된 설계가 폐기된 결정을 가리키는 것은 stale 이 아니라 둘이 함께 죽었다는 이력").
- 외부 실무의 경고: 산업 추적 매트릭스가 **suspect 로 가득 차는** 것이 흔한 실패이고, 사람의 링크 검증 오류율은 약 25%다.
  도구들은 트리거를 좁히는 쪽으로 이동했다 — 어떤 필드 변경이 suspect 를 유발하는지 타입별로 선언하고(Jama),
  `invalid` 은 자동 전이 대신 수동 판정으로(DOORS Next 가 7.0 에서 그렇게 바꿨다).
- **가장 먼저 닫을 구멍**: 청크에 붙은 `assumes` 가 그 청크의 링크로 전파되지 않는다. 가정이 깨지면 영향 청크는 계산되지만
  영향 링크는 계산되지 않아, 무효화가 링크 상태에 도달하지 못한다. `when` 을 켜면 이 경로가 이어진다.
- 이 저장소에 맞게: 트리거를 링크 타입별로 좁게 선언하고, **suspect 포화율 자체를 지표로 관측**한다.
- 비용: `when` 평가기(ODD 판정 재사용) + `revalidate` 확장 + 지표 한 줄.

### E. 어휘 확장 규칙 성문화 + 탈출구 (비용 낮음)

새 관계는 **기존 네 족 아래 잎으로만** 더한다(`rdfs:subPropertyOf` 의 함의 규칙이 하위 호환을 보장한다 — 부모만 아는 질의는
자식이 늘어도 깨지지 않는다). SKOS 가 같은 패턴의 표준 사례다.

- 더 명시적인 근거는 **DCMI dumb-down 원칙**이다 — "클라이언트는 어떤 한정자든 **무시하고** 한정 없는 것처럼 쓸 수 있어야 하며, 구체성은 잃어도 남는 값은 대체로 옳고 쓸모 있어야 한다." 같은 문서가 "여기 열거한 한정자는 **닫힌 집합이 아니고** 앞으로 자랄 한정자 무리의 토대"라고 적는다 — 닫힌 어휘를 유지하면서 확장을 허용하는 근거로 SKOS 보다 직접적이다.
- **함정**: 대부분의 스토어가 기본적으로 추론하지 않는다. 그래서 게이트가 **부모 트리플을 함께 생성**해야 한다 —
  PROV-O 가 정성 형태를 쓸 때 "등가 이항 트리플을 함께 싣기를 권장"하는 것과 같은 이유다.
- **탈출구 하나**: `relatedTo` 아래 약한 잎 하나를 두어 "관계는 있는데 이름이 아직 없다"를 기록 가능하게 한다. 지금은
  어휘 밖 술어가 게이트에 막혀 **기록 자체가 불가능**하고, 그래서 관계가 산문으로 새어 나간다. 주기적으로 승격·정리한다.
- 비용: 규칙 한 절 + 어휘 1 + `chunk2kg` 의 부모 트리플 생성.

## 권하지 않는 것

- **RDF 1.2 triple term 을 지금 데이터 모델로 채택** — Concepts·Semantics 만 CR 이고 Turtle·SPARQL 1.2 는 초안, 주요 구현도
  미완이다. 다만 **우리 `agt:Link` 가 구조적으로 reifier 와 동형**이므로, 매핑 규칙만 적어 두면 표준이 서는 날 기계적 변환이 된다.
- **singleton property** — 고유 술어 폭증으로 주요 엔진 다섯 중 넷이 실패한 것이 벤치마크로 나와 있다.
- **named graph 에 링크 정체성을 걸기** — 표준이 "그래프 이름이 그 그래프를 지칭할 필요가 없다"고 명시해 정체성을 걸 자리가 아니다.
- **지속 식별자 서비스(DOI·w3id·purl)에 기대기** — 단일 저장소 안의 링크에는 해당 없고, w3id.org 는 **W3C 가 운영하지 않는** 공동체 약속이고,
  지속성은 리다이렉트를 유지하겠다는 관리자들의 약속이지 기술 보장이 아니다 — 지시는 위치만 지킨다.
