# 도입 단계별 통과 조건의 재정의 — 양이 아니라 의미 보존·구체화·유기적 연결

## 질문

노트 14.1의 단계별 통과 조건은 대부분 **양**이다 — 토큰 감소, 고아율 < 10%, 링크 밀도 하한, 확장 ≥ 1건,
바인딩률 100%. 유저 지적(2026-09-10): "각 단계별 통과조건이 너무 단순하게 설정되어 있음. 단순히 양을
줄이는 것이 목적이 아닌 **의미를 보존하면서 가상화 단계에 따라 지식 및 결과물이 구체화되고 지식이
유기적으로 연결되는 것**이 목적이다." 어려운 이유: 세 축 중 "의미 보존"과 "유기적"은 그래프 질의로
바로 잡히지 않아 대리 지표와 실험을 함께 정해야 하고, 조건을 바꾸면 노트 14.1·roadmap·결정
`p14-adoption-stages`·`metrics` 도구가 같이 바뀐다.

## 이미 정해진 것

- 세 축의 원천은 노트에 이미 있다 — 의미 보존: 4.13 라벨 대표성 · 7.4 대안 필수 · 2.12 `sources` 빈 청크 = 실패 / 구체화: 6.2 하강 4전이(전이마다 근거와 `refines`) · 6.8 전이 게이트 · 7.2 결정의 세 수준 / 유기적 연결: 4.5 참조 원칙 · 10.12 매트릭스 "빈 칸이 곧 누락" · 9.11 장부 · 8.3 가로대
- 1단계의 "토큰 감소"는 이미 "의미를 보존하면서 예산 이내"로 재정의됐다 (결정 원장 17, [`stage1-pass-measurement.md`](stage1-pass-measurement.md))
- 단계는 여덟이고 사례 프로젝트 하나에서 끝까지 한다 ([`p14-adoption-stages`](../../kb/dev/decision/p14-adoption-stages/conclusion.md)) — 단계 수·순서는 바꾸지 않는다
- 지표는 생성물(`bazel build //kg:metrics`)로 낸다

## 답이 가르는 것

- 세 축을 **모든 단계에 공통 열**로 두면 단계마다 "이 단계가 세 축에 무엇을 더했는가"를 묻게 되고, 양 지표는 축의 대리로 격하된다. 양 지표만 남기면 지금처럼 "고아율 0%인데 필요한 결정을 못 펼치는" 통과가 생긴다.
- "의미 보존"의 판정을 **실험**(라벨 대표성, 답 완전성)으로 두면 사람·에이전트 개입이 단계마다 필요하고, **대리**(확정 문장 커버리지, 대안 존재, 절 인용 결정의 포함)로 두면 기계적이지만 느슨하다 — 둘 다 적고 실험을 최종으로 두는 것이 권고.
- 노트 14.1을 고치면 결정 `p14-adoption-stages`가 `supersedes`로 대체되고 roadmap 표·`metrics`의 통과 판정이 따라 바뀐다. 노트를 그대로 두면 이 저장소의 조건과 원문이 어긋난 채 남는다.

## 선택지 — 제안 표 (권고: 이대로 채택, 수정은 유저)

각 단계의 통과 조건을 세 축으로 쓴다. 굵은 것이 그 단계의 **핵심 축**이고, 괄호는 기계적 대리(생성물로 냄), "실험"은 사람·에이전트 판정.

| 단계 | 의미 보존 | 구체화 (가상화 단계 = level 사다리) | 유기적 연결 |
|---|---|---|---|
| **1 청크·plane** | **원문의 확정 내용이 청크에 빠짐없이** (재도출 커버리지 = 확정 문장 대비 결정 100%, 감사 §3) · 라벨 대표성 실험 통과 · 과제의 작업 집합이 예산(200줄) 안에서 답을 완결 | plane = 판정 방식, level = 정제 높이로 배정됨 (거주표 위반 0) | 고아율 < 10%는 필요조건. 구성체·인용으로 **연결 성분이 하나**로 수렴 (고립 성분 0) |
| **2 ODD·스코프** | 모든 조건에 객관적 판정 방법·등급, 명시 제외에 검토 기록 (판정 방법 없는 조건 0) | **스코프가 ODD 조건 × plane 권한에서 파생됨** (파생 안 된 스코프 0) · 역할·작업(앵커)별 작업 집합 ≤ 예산 (2026-09-11 정정: 정의에 앵커 이웃) | 가정·스코프·시나리오 변수가 ODD 조건을 가리킴 (ODD 밖 참조 0) · 첫 대조 이탈 0 |
| **3 링크 구축** | 링크마다 판정 근거(장부 항목 ≥ 1, 종류 명시) · 구축 비율(편집 부산물로 생긴 링크 / 전체) | `refines`가 level을 **한 단계씩** 내려감 (건너뜀 0) | **매트릭스 채움률** (plane×plane·level×level, 빈 칸 = 실제 누락) · 복원 비율 < 20% |
| **4 가정·무효화** | 무효화는 삭제가 아님 — 이력 보존 (invalidated 항목의 provenance 100%) | 판정식 등급 A·B 비율 (D는 0) | 가정 하나를 인위로 깨뜨렸을 때 **계산된 영향 집합 = 실제 의존 집합** (정밀도·재현율 실험) |
| **5 사다리 완성** | 각 수준이 상위를 **정제**한다 — abstract에 변수, logical에 후보·제약·배제 근거, concrete에 값·표본 근거 (빈 수준 0, 대안 청크 100%) | **결정 완결률**(concrete 도달) · 하강 완주율 상승 | `refines` 연쇄의 functional 도달률 100% · `-space` 확정마다 배제 근거 존재 |
| **6 상승** | 승격된 어휘·규칙이 관측에 `wasDerivedFrom`으로 닿음 (출처 없는 확장 0) | 상승 4전이(실행 기록 → 도메인 → 변수 → 개념) 각각 산출 ≥ 1 | 승격된 어휘가 기존 청크에서 **쓰임** (`usesConcept` 0인 고립 어휘 0) |
| **7 V&V** | 기준이 계약 사후조건에서 파생 (기준 바인딩률 100%) · 변이 검출률 > 0 | 케이스가 표본 근거로 생성됨 (수기 케이스 0) · 환경 배정 재현성 | **가로대 채움률**(요구별 목표·기준·verifier) 100% · 독립성 0건 · 실행 증거가 `satisfies` 장부에 흘러감 |
| **8 복원·감사** | 감사 보고서가 체계 밖 정보 없이 생성 (자족성) | 복원 후보의 확정 비율 · 확정된 복원 링크에 근거 종류 | 매트릭스 빈 칸이 전부 **실제 누락**(거짓 빈 칸 0) — 감사가 발견한 누락의 종류가 어휘 확장으로 이어짐 |

채택 시 바뀌는 것: (1) 노트 14.1 표의 "통과 조건" 열 (유저 문서 — hci가 고쳐도 되는지) (2) `p14-adoption-stages`를
새 결정이 `supersedes` (3) `roadmap.md` 표 (4) `metrics.py`에 연결 성분 수·매트릭스 채움률·level 건너뜀·거주표 위반 추가
(5) 1단계는 "라벨 대표성 실험"과 "확정 문장 커버리지"가 남은 조각.
