# 관측 청크의 시각 표기를 생성 문서 규약에 맞출 것인가 (2026-09-21)

원본: [`agents/orchestrator-generated-document-form-2026-09-21.md`](agents/orchestrator-generated-document-form-2026-09-21.md)

## 질문

생성 문서 규약 G3이 시각 표기를 `%Y-%m-%dT%H:%M:%SZ`로 고정했다. 관측 청크는 생성 문서가 아니라 청크이므로 G3의 대상이
아니고, orchestrator는 건드리지 않았다. 관측의 표기를 같은 형태로 통일할 것인가.

어려운 이유는 관측이 **append-only**라는 데 있다. 커밋된 기록은 고치지도 지우지도 않으므로, 통일해도 기존 기록은 옛 표기로
남는다. 어느 쪽을 골라도 한동안 두 표기가 공존한다. 고를 것은 "공존을 규약으로 인정하는가"다.

## 이미 정해진 것

- 관측은 append-only다. 커밋된 기록은 불변이다(원장 35, `vv_run` 규약).
- G3의 근거는 생성 문서의 기계 판독성이다. 관측 청크는 `chunk_lint`·`chunk2kg`가 검사하며 시각 형식을 강제하지 않는다.
- `kb/vv/`는 **vnv의 쓰기 범위**다(`agt:writesIn "kb/vv"`). `kb/dev/memory/`는 orchestrator의 범위다. 도구 자체는 developer의 범위다.
- 파일명 규약은 이미 UTC 압축형이다(`run-20260919T065358Z.md`·`obs-20260913T154324Z.md`).

## 현재 상태 (실측 2026-09-21)

- 관측 기록은 셋이고 frontmatter의 시각이 전부 **오프셋형**이다 — `2026-09-19T06:25:48+00:00`·`2026-09-19T06:53:58+00:00`·`2026-09-13T15:43:24+00:00`.
- 같은 청크의 본문 요약은 **분 해상도**를 쓴다(`2026-09-19T06:25Z`). 한 파일 안에서 두 형식이 함께 있다.
- 생성 문서는 `2026-09-21T12:40:27Z` 형태다. 규약은 `kb_lib.GENDOC_TIME_FORMAT` 한 곳이 정의처이고 주석이 "오프셋 표기·분 해상도를 쓰지 않는다"고 적는다.
- 고칠 자리는 넷이다 — `tools/assume_check.py:171`·`:179`, `tools/vv_run.py:143`·`:149`.
- 2026-09-14에 같은 어긋남이 이미 보고됐다. 파일명은 UTC이고 원장·로드맵은 KST 날짜를 써서 한 사건이 두 날짜로 불렸다.

## 답이 가르는 것

- **통일하면** 다음 기록부터 생성 문서와 시각을 그대로 비교할 수 있다. 기존 셋은 옛 표기로 남으므로 규약에 "커밋된 기록은 소급하지 않는다"를 한 줄 적어야 한다. 적지 않으면 다음 세션이 소급 수정을 시도한다.
- **두면** 저장소에 두 표기가 계속 남는다. 감사가 관측과 생성 문서의 시각을 나란히 놓을 때마다 변환이 필요하고, 변환 규칙이 어디에도 없다.
- **소급 재생성하면** append-only 규율을 깬다. 그 규율은 2026-09-19에 "첫 커밋 기록부터 적용한다"로 확정됐다.

## 선택지

1. **새 기록부터 G3 표기로 바꾸고 소급하지 않는다** (권고). 도구 넷을 `kb_lib.now_utc`로 통일하고, 본문 요약의 분 해상도도 초 해상도로 올린다. 규약에 소급 금지 한 줄을 더한다. 비용: developer가 도구 두 개를 고치고 vnv가 `kb/vv/` 쪽 결과를 확인한다. 기존 기록 셋은 그대로다.
2. **관측은 현행 유지하고 G3은 생성 문서에만 적용한다.** 대신 "관측 청크의 시각은 오프셋형"이라는 규칙을 명시해 두 표기가 **의도된 것**임을 적는다. 비용: 규칙 한 줄. 변환 규칙도 함께 적어야 감사가 흔들리지 않는다.
3. **관측도 생성 문서와 같은 게이트에 넣는다.** `gendoc`의 시각 검사를 관측 청크까지 넓힌다. 비용: 기존 기록 셋이 FAIL이 되므로 면제(`docs/waivers.md`) 선언이 따른다.
