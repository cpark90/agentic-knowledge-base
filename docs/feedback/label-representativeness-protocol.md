# 라벨 대표성 실험 — 1단계 통과의 마지막 조각, 프로토콜 제안

## 질문

14.1 정정본의 1단계 "의미 보존" 축에서 기계적 대리(확정 문장 커버리지 100%, 앵커 작업 집합 예산 내 98.7~100%)는
찼고, **실험**만 남았다 — 4.13절 "라벨 대표성: 라벨만 보고 본문을 예측한 정확도(에이전트 실험)". 어려운 이유:
"예측이 맞았다"의 판정이 사람 또는 다른 에이전트의 판단이라 재현성이 낮고, 표본·판정자·통과 기준을 정하지
않으면 결과를 통과 조건으로 쓸 수 없다. 이것은 1단계를 "통과"로 적을지 정하는 실험이라 유저가 정한다.

## 이미 정해진 것

- 라벨이 청크의 인터페이스다 — 읽기 응답의 기본은 라벨 목록, 본문은 요청 시 (5.6절, `p4-label-is-the-interface`)
- 라벨 대표성은 판정 불가 규칙이라 게이트 밖 규약이다 (STYLEGUIDE §4, tools.md "게이트 밖")
- 의미 보존의 최종 판정은 실험이고 양 지표는 대리다 (`p14-stage-pass-conditions`, 원장 18)
- 에이전트는 신뢰할 수 없는 센서 — 판정은 사람 또는 검사 통과 판정자 (2.5절); 학습된 판정자는 3지표 + 사람 승인 (8.14절)

## 현재 상태 (실측 2026-09-11)

- 살아 있는 청크 607 (요구 33 · 결정 부분 573 · 새 결정 1). 라벨 한/영 각 하나, 결정 라벨은 결론 문장형("…이다", "…한다").
- 작업 집합 재측정(`stage1-pass-measurement.md`)에서 필요한 결정을 못 펼친 과제 2/5 — "라벨을 보고 펼칠지 고르는" 단계의 실패였다. 라벨 대표성이 낮으면 앵커 이웃을 펼칠 때 엉뚱한 것을 펼친다.
- 라벨 부패 리스크는 기계화되지 않았다(`risks-and-tensions.md`) — contentHash 는 있으나 "본문 해시 변경 시 라벨 재검토" 트리거가 없다.

## 답이 가르는 것

- **판정자가 사람이면** 재현성은 낮지만 결과가 곧 승인이고, 표본 30개 × 5분이면 한 세션에 끝난다. **다른 에이전트 세션이면** 반복 가능하지만 판정자 자체의 신뢰가 8.14절 3지표를 요구한다.
- **통과 기준을 비율로 두면**(예: 적합 ≥ 80%) 1단계 통과가 확정되고, **불합격 라벨의 수정까지 요구하면** 통과 전에 라벨 재저작이 따른다.
- 표본을 결정에 몰면 결론 문장형 라벨이라 쉽고, 요구·근거·대안을 섞으면 어려워진다 — 층화가 결과를 가른다.

## 선택지

1. **사람 판정 · 층화 표본 30 · 3점 척도 · 적합 ≥ 80%** (권고). 표본 = 요구 5 · 결정 결론 10 · 근거 8 · 대안 7 (무작위, seed 고정). 절차: 판정자에게 라벨만 보이고 "이 청크가 무엇을 말하는지 한 문장으로 예측" → 본문 공개 → 3점(적합 / 부분 / 부적합) 판정. 결과는 관측(`memory` plane)으로 기록, 부적합 라벨은 재저작 후 재판정. 비용: 유저 30분.
2. **다른 에이전트 세션 판정 · 표본 60 · 같은 척도** — 이 세션이 아닌 새 세션(다른 컨텍스트)이 예측·판정. 비용: 판정자 신뢰 미검증(8.14절), 결과에 사람 승인 필요.
3. **실험 연기, 대리로 통과 처리** — 1단계를 "대리 통과"로 적고 실험은 2·3단계 산출이 쌓인 뒤. 비용: 14.1 정정본이 실험을 최종 판정으로 두므로 조건 위반.

채택 시 hci 가 표본 추출 스크립트(`tools/label_sample.py`, seed 고정)와 판정 기록지를 만들고, 결과를 `metrics` 밖 관측으로 남긴다.

## 답
2, 에이전트가 수행하는 것을 기본으로 하되 안전율의 개념으로 같은 내용이 반복적으로 포함되는 상황도 용인함. 대신 전체적인 정합성 관리 및 정리 작업을 중간중간 수행하면서 통일성 향상 작업을 수행.

## 재검토 (답 수신 후)

유저 답은 세 조각이다 — **(a)** 판정자는 에이전트(2안), **(b)** 같은 내용의 반복을
**안전율**로 용인, **(c)** 대신 **주기적으로 정합성·통일성 정리**를 수행. (a)는 실험
프로토콜이고 (b)·(c)는 실험을 넘어 **저작 규칙의 변경**이다 — 따로 다룬다.

### (a) 에이전트 판정 프로토콜 — 8.14절을 이 실험에 적용

2안의 비용은 "판정자 자체의 신뢰 미검증"이었다. 8.14절이 답을 이미 준다: 학습된
판정자는 **정확도·판별력·캘리브레이션** 세 지표를 통과해야 하고, 결과에 사람 승인이 붙는다.

| 요소 | 내용 |
|---|---|
| 판정자 | 이 세션이 아닌 **새 세션**(컨텍스트 분리). 라벨만 받고 본문을 예측 → 본문 공개 → 3점 판정 + 확신도(0~1) |
| 표본 | 층화 60 (요구 10 · 결론 20 · 근거 15 · 대안 15, seed 고정) + **미끼 10** — 라벨을 다른 청크의 본문에 바꿔 붙인 음성 표본 |
| 정확도 | 유저가 60 중 **10을 무작위 재판정**(사람 기준) — 일치 ≥ 9/10 |
| 판별력 | 미끼 10 중 "부적합" 검출 ≥ 9/10 — 못 잡으면 판정자가 라벨을 읽지 않고 본문에 순응한 것 |
| 캘리브레이션 | 확신도 상위 절반의 정답률 > 하위 절반의 정답률 — 뒤집히면 확신도를 버린다 |
| 통과 기준 | 판정자 3지표 통과 **그리고** 실표본 60의 적합 ≥ 80% |
| 기록 | 판정 결과는 각 청크 head의 `verified`(판정자 `agent:<세션>`, 사람 재판정은 `human:`) + 실험 전체는 관측 1건 |
| 실패 라벨 | 재저작 후 같은 판정자로 재판정. 재저작은 저작 행위라 developer |

비용: 판정 세션 1회 + 유저 10건 재판정(~10분). 3지표 중 하나라도 실패하면 결과를
통과 조건에 쓰지 않고 1안(사람 판정)으로 돌아간다 — 그것이 "에이전트는 센서"(2.5절)의
뜻이다.

### (b) 중복 용인 — 어디와 부딪히고 어디까지 허용되는가

**부딪히지 않는 것.** `p4-chunk-split-and-merge`의 병합 신호는 "항상 함께 읽힘 / 자립성
위반 / 합쳐도 42줄"이지 "내용이 겹침"이 아니다 — 내용 중복 자체를 금지한 결정은 없다.
근거·대안 청크가 결론의 맥락을 되풀이하는 것은 자립성 요구의 **결과**이고 이미 실재한다.

**부딪히는 것 — 경계를 그어야 한다.**

| 층 | 중복 | 판정 |
|---|---|---|
| T-Box 개념·용어 | 같은 뜻의 개념 둘 | **용인 불가** — `p0-one-word-one-concept`, d-0160(만들기 전에 검색). 안전율이 아니라 드리프트 |
| 요구(`requirement`) | 같은 관심사의 요구 둘 | **용인 불가 권고** — refines 연쇄가 갈라져 전방·후방 추적 커버리지가 왜곡된다 |
| 라벨 | 다른 청크에 같은 라벨 | **용인 불가** — 라벨이 인터페이스라 같은 라벨은 같은 청크로 읽힌다 |
| 청크 **본문**(결정 부분·논평·기억) | 같은 내용이 여러 청크에 | **용인** — 유저 답의 안전율은 여기 |

**용인의 비용은 컨텍스트 예산이다** (1.4절). 중복은 작업 집합 안에서 예산을 먹으므로
"어디서 겹치는가"가 중요하다 — **다른 스코프 사이의 중복은 안전율**(각자 자립),
**같은 작업 집합 안의 중복은 정리 대상**(같이 펼쳐져 예산만 먹음).

**안전율의 중복과 드리프트된 중복을 가르는 장치**: 알고 둔 중복은 `coUpdatesWith`
(`relatedTo` 족, 이미 어휘에 있음)로 묶는다 → 한쪽이 바뀌면 다른 쪽이 `suspect`가 되어
정리 큐에 오른다. **링크 없는 중복이 드리프트**다. 이 규칙 하나로 (b)와 (c)가 이어진다.

### (c) 주기적 정합성·통일성 정리 — 새 운용 작업

| 요소 | 내용 |
|---|---|
| 리듬 | **재판정 경계와 같다**(커밋·세션 종료, d-0106 일괄 재판정) — 편집마다 하지 않는다. 보고는 커밋마다 자동, 병합 판정은 도입 단계 끝마다 |
| 입력 | `consistency` 보고(뷰, 게이트 아님): ① 정확 중복(contentHash 동일) ② 라벨 중복 ③ 근사 중복 후보(본문 n-gram 겹침 ≥ θ — 유사도는 후보 추림만, d-0009) ④ 라벨 형식 위반(결론 문장형·한/영 1:1) ⑤ 용어집 밖 용어 |
| 판정 | 후보마다 셋 중 하나 — **병합**(새 IRI + `prov:wasDerivedFrom` 둘) / **묶기**(`coUpdatesWith`, 안전율로 유지) / **유지**(다른 스코프, 링크 불필요). 판정 근거를 관측으로 |
| 담당 | 정리는 저작이므로 developer, 결과 검토는 채널 — hci 담당 |
| 지표 | `metrics`에 **중복률**(정확·근사)과 **묶인 중복 비율** 추가 — 안전율이 예산을 넘는지 감시 |

### 바꿔야 하는 것

1. **결정 1건 신설** — "본문 중복은 안전율로 용인하되 `coUpdatesWith`로 묶고 재판정 경계에서
   정리한다" (`p4-` 계열, refines r-014·r-012). 기존 결정을 뒤집지 않는다 — 경계표만 새로 긋는다.
2. `rules.md` §1에 중복 경계표 한 단락, `risks-and-tensions.md`에 "안전율 vs 컨텍스트 예산" 긴장.
3. `tools/consistency.py`(보고 뷰) + `metrics` 중복률.
4. 실험 도구 `tools/label_sample.py`(층화 + 미끼 생성, seed 고정) + 판정 기록지.

### 확인이 필요한 것 (셋)

1. **용인 범위** — 청크 본문만이고 개념·용어·라벨·요구는 제외, 이 경계에 동의하는가.
2. **정리 리듬** — 보고는 커밋마다 자동, 병합 판정은 도입 단계 끝마다. 이 두 박자로 되는가.
3. **판정자 승인** — 유저 재판정 10/60 + 미끼 10으로 8.14절의 "사람 승인"을 갈음하는 데 동의하는가.

### 실험 (저장소 밖에서 수행 — 판정 기록은 승인 뒤 `verified`에 남긴다)

실험 자체는 저장소 파일을 바꾸지 않으므로 먼저 돌렸다. seed 20260911, 층화 60(요구 10·결론 20·근거 15·대안 15)
+ 미끼 10. 판정자는 이 세션이 아닌 새 에이전트 세션, **도구 사용 0회**(저장소 미열람).

| 지표 | 결과 | 기준 |
|---|---|---|
| 실표본 적합률 | **60/60 = 100%** (부분 0 · 부적합 0) | ≥ 80% |
| 판별력 — 미끼 검출 | **10/10** 전부 부적합으로 잡음 | ≥ 9/10 |
| 캘리브레이션 | **판정 불가** — 오답이 0이라 확신도 상·하위 절반의 정답률이 같다(100/100). 통과·실패를 말할 수 없다 | 상위 > 하위 |
| 층별 | 요구 10/10 · 결론 20/20 · 근거 15/15 · 대안 15/15 | — |

읽는 법 — 미끼 10/10은 판정자가 본문에 순응하지 않고 라벨을 실제로 읽었다는 증거다. 다만 "부분"을 한 번도
쓰지 않았고, 확신도 0.65~0.7을 준 두 항목(#57 어휘 확장 예외, #63 환경·지식의 독립 변화)에서 "라벨이 일부만
대표"라고 적으면서도 적합을 줬다 — 경계에서 너그러운 쪽으로 기운다. **사람 승인(유저 재판정 10건)이 이
경계를 잡는 자리**이고, 재판정 목록은 스크래치패드 `label-exp/result.md`에 있다 (라벨만 먼저 보고 예측 →
본문 대조). 재판정 일치 ≥ 9/10이면 1단계 "의미 보존" 축이 실험으로 닫힌다.
