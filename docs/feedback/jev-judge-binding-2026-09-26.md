# 판정자를 System One 모델에 붙일 것인가 (2026-09-26)

조사: [`inquiries/jev-system-one-model-2026-09-26.md`](inquiries/jev-system-one-model-2026-09-26.md)

## 질문

결정 `p8-judge-question-form` 은 판정자의 **형**을 System One 으로 정해 두었다(질문 셋·원자성·병렬·확신도 임계·척도는 상황으로).
실행 주체는 정하지 않았다. 판정자를 실제 System One 모델에 붙일 것인가, 붙인다면 무엇을 먼저 고쳐야 하는가.

어려운 이유는 둘이다. 첫째, 붙이면 **외부 서비스가 게이트 안으로 들어온다** — 이 저장소의 게이트는 밀폐된 Bazel 테스트이고
네트워크·API 키·재현성이 그 성질과 부딪힌다. 둘째, 붙이지 않으면 판정자가 계속 **에이전트 세션**이고 그것은 System 2라
확률을 내지 않으므로 결정이 정한 임계 셋이 **작동할 수 없다.**

## 이미 정해진 것

- `p8-judge-question-form` — 질문의 형 셋, 원자성(같은 입력에 병렬), 출력은 값과 확신도, 임계 셋(0.9 이상 자동 · 0.5~0.9 사람 확인 · 0.5 미만 보류), 도입 전 20건 라벨링, 계산·다단계 추론 배제. 질문·척도·임계는 프로파일 shape 에 저장하고 **판정자 모델 식별자와 버전을 맞춘다**.
- 요구 `verification-means-trust` — 검증 수단 자체의 신뢰도를 잰다.
- 노트 2.5절 — 에이전트는 신뢰할 수 없는 센서다. 판정은 사람 또는 검사 통과 판정자다.
- 노트 8.14절 — 학습된 판정자는 정확도·판별력·캘리브레이션 3지표 + 사람 승인을 통과해야 한다.
- ODD 는 실행 환경의 조건만 담고 판정 방법은 **객관적 관측 수단**이어야 한다.

## 현재 상태 (실측 2026-09-26)

- 판정자 실물이 **없다.** `judge` 도구도 없다. 라벨 대표성 실험(2026-09-11)의 판정자는 **새 에이전트 세션**이었고 확률 대신 3점 척도와 자기 보고 확신도를 냈다.
- `annotation` plane 청크 **7**(판정 주석 4 · 논평 3). 판정 기록의 자리는 열렸다.
- 게이트 **23/23** 이 전부 밀폐 실행이다. 오늘 열린 질문 [`agents/orchestrator-test-hermeticity-2026-09-23.md`](agents/orchestrator-test-hermeticity-2026-09-23.md)가 `env_inherit = ["HOME"]` 하나를 두고 같은 긴장을 이미 다룬다.
- `jev` 실측치 — 70~500ms · 입력 100만 토큰당 $0.042 · 케이스당 약 $0.0004 · Choice 상한 **255** · **설명을 생성하지 못한다** · 캘리브레이션은 **집단 수준**이다.

## 답이 가르는 것

- **붙이면** 임계 셋이 실제 확률로 작동하고, 문장 단위 근거 판정("이 문장은 입력에서 지지되는가")이 비용상 가능해진다. 대신 게이트가 외부 서비스에 의존하거나, 판정을 게이트 밖 보고로 두어야 한다.
- **붙이지 않으면** 판정자는 에이전트 세션이고 확신도는 자기 보고다. 3지표 가운데 **캘리브레이션을 잴 수 없다** — 2026-09-11 실험이 "오답 0이라 판정 불가"로 끝난 것이 그 증거다.
- **캘리브레이션이 집단 수준이라는 사실**은 도입 절차를 바꾼다. 20건은 구간 셋의 정확도를 재기에 부족하다. 구간별 표본이 필요하고, 그 수를 정하지 않으면 임계가 근거 없는 수치로 남는다.
- **설명을 만들지 못한다는 한계**는 논평 틀에 직접 걸린다. 판정 결과의 `본문:`(문장 ≤4)을 판정자가 채울 수 없다. 사람이 채우거나, System 2 가 채우거나, 그 슬롯을 판정 기록에서 비우는(`해당 없음`) 규칙이 필요하다.

## 선택지

1. **게이트 밖 보고로 먼저 붙인다** (권고). 판정자를 `bazel test` 밖의 도구(`bazel run //tools:judge`)로 두고, 결과를 논평 청크와 판정 로그로 남긴다. 게이트는 그 로그의 **존재와 형식**만 검사한다 — 외부 호출이 게이트에 들어오지 않으므로 밀폐성이 깨지지 않는다. 함께 고칠 것 넷: 캘리브레이션의 뜻과 구간별 표본 수(J1·J2) · Choice 상한 255와 2단계 패턴(J3) · 논평 본문의 작성 주체(J4) · 모델 식별자와 캘리브레이션의 결합 명시(J5). 비용: 결정 개정 1 + 도구 1 + ODD 조건 1(네트워크·자격).
2. **판정자를 게이트에 넣는다.** 확신도 0.9 이상을 자동 적용하고 미만을 FAIL 로 막는다. 비용: 밀폐성 예외 선언 + 재현성 설계(같은 입력·같은 모델 버전에서 같은 답인지) + 오프라인 캐시. 오늘의 `test-hermeticity` 질문과 **같은 답이어야 한다.**
3. **붙이지 않고 형만 유지한다.** 판정자는 계속 에이전트 세션이고 확신도는 자기 보고로 둔다. 결정 본문에 "캘리브레이션은 현재 판정 불가"를 명시한다. 비용: 결정에 한계 한 줄. 3지표의 한 축을 포기한다.
4. **형부터 고치고 바인딩은 뒤로.** J1~J5 다섯을 결정에 반영하고 모델 결합은 다음에 판단한다. 비용: 결정 개정 1. 실행은 여전히 없다.

## 함께 답할 것

**외부 의존을 ODD 에 올릴 것인가.** 붙이는 쪽을 고르면 판정 서비스가 운영 조건이 된다 — 네트워크 도달·자격·모델 버전·요금이
조건이고 판정 방법은 객관적 관측 수단이어야 한다. **권고는 조건 하나를 ODD 에 추가하고 등급을 매기는 것**이다.
