
# 현재 위치와 다음 산출

진행 상태는 계속 바뀌므로 지식, 곧 청크가 아니라 문서로 둔다. **두 순서를 구분한다**
(노트 Part XIII·구조도). [`method.md` §0](method.md#0-순서와-완료-판정)는 체계가 굴러갈 때의
**운용 순환**이고, 아래 도입 순서는 **체계를 세우는 8단계**다. 하나로 합치면
"체계를 만드는 일"과 "체계로 일하는 것"이 섞인다.

## 도입 순서 — 체계를 세우는 8단계 (노트 Part XIV · 14.1)

각 단계가 이전 단계 없이 성립하지 않고, 각 단계 끝에 측정 가능한 산출이 있다.
1단계만으로도 이득이 있어야 한다. 체계의 존재 이유는 갱신 단절 해소이며, **4단계가 그것을
처음 검증하는 지점**이다. 거기서 실패하면 설계를 재검토한다.

## 입력 바인딩 현황

입력은 체계의 구성요소가 아니라 파라미터다. 입력이 바뀌면 체계가 재구성되고, 체계가 바뀌면 활용 기능이 영향받는다.
입력의 규칙은 결정(p10-* 재도출분)에 있고, 여기는 이 저장소가 각 입력에 무엇을 바인딩했는가의 현황표다.

| 입력 | 결정하는 것 | 이 저장소의 바인딩 | 상태 |
|---|---|---|---|
| 도메인 프로파일 | 작업 종류, plane 실체, 판정 도구, 앵커 해석기 | **없음** — 첫 분야 프로파일이 미착수 (아래 도입 순서) | 공백 |
| 에이전트 카탈로그 | 역할과 read/write | `kg/catalog-kg.ttl` — 노트 10.2절 9역할의 부분집합 4역할(inspection은 2026-09-13 hci로 통합). design은 developer가 겸함(유저 결정 C4) | 바인딩됨 |
| 상위 온톨로지 선택 | 개념의 최상위 분류 | **미선택** — BFO/IAO 정렬은 "정렬 예정"으로 유보. 사실상 불가역이라 신중 | 공백 |
| 실행 모드 | 세션 유지 / dispatch | 카탈로그의 역할별 `agt:executionMode` | 바인딩됨 |
| 메모리 승격 규칙 | 단기기억의 승격 시점·목적지 | `.claude/agent-memory/` 규약 (역할 메모리 → 반복 시 표준 규칙) — 어휘로는 미형식화 | 부분 |
| 재검증 시점 | 링크·가정 일괄 재판정 시점 | **커밋** — Bazel 캐시가 바뀐 입력의 게이트만 재실행 | 바인딩됨 |
| 태그 어휘 | 분류 태그 | `kb/ontology/related/tag/` — 범주 9종. 값 어휘는 범주별 출처에서 | 바인딩됨 |
| 언어 정책 | 식별자·산문의 언어 | 산문 한글, 식별자 영어 케밥, 라벨 한/영 1:1 (`AGENTS.md`) | 바인딩됨 |
| 프로세스 규칙 | 작업 순서 제약 | 스코프 conditionalRule (`kg/catalog-kg.ttl`) — 예: "구현 전 상세 설계" | 바인딩됨 |
| 판정 도구 바인딩 | plane별 판정 도구의 실제 명령 | `decision`: 게이트+유저 승인. 나머지 plane은 항목이 생길 때 | 부분 |
| 앵커 해석기 구성 | IRI → 저장 위치 사상 | `agt:assertionLocation` = 저장소 상대 경로 (산문 계열만) | 부분 |
| 청크 상한 | 42줄 기본값, plane별 오버라이드 | 42줄 고정 (`tools/chunk_lint.py`) — 오버라이드 없음 | 바인딩됨 |
| 일반화 임계값 | N·M·K | **미설정** — 일반화 미착수 | 공백 |
| 커버리지 임계 | 자율 진행 허용 하한 | **미설정** — 커버리지 측정 미착수 | 공백 |
| 후보 상한 | 복원 k, 라벨 목록 표시 수 | k ≤ 7 (결정 재도출분 참조) — 도구 미구현 | 부분 |

### 입력 간 의존 (노트 10.7절)

```
상위 온톨로지 선택 → (온톨로지) → ODD → 에이전트 카탈로그 → 스코프
                                  ↘ 태그 어휘
언어 정책 → 표기 형식 (독립)
실행 모드 → 메모리 승격 규칙 → 재검증 시점
```

앞이 바뀌면 뒤가 재검토된다. **상위 온톨로지 선택이 아직 공백인 것이 이 표의
가장 큰 미결이다.** 사슬의 맨 앞이라 사실상 불가역이고, 그래서 서두르지 않는다.

- 입력은 **온톨로지 어휘로 쓴다**. 어휘 밖의 입력은 체계가 읽을 수 없다.
- 입력은 **버전 관리된다**. 언제 무엇이 바뀌었는지 남아야 파생물의 재검토
  범위가 계산된다. 이 저장소에서는 git이 그 역할이다.
- 바인딩을 바꾸면 위 표의 "변경 시 파급"(결정 원문 참조)에 따라 파생물을
  재검토하고, 이 표를 같은 커밋에서 갱신한다.

## 운용 순서 위의 위치

| 단계 | 상태 | 막고 있는 것 |
|---|---|---|
| 1. 프로파일 구축 | **미착수** | 절차 자체가 없다. 첫 프로파일을 만들면서 절차를 뽑아야 한다 |
| 2. ODD 작성 | **완료**(이 저장소 자신에 대해) | — |
| 3. 정제(저작) | 부분 — `decision` × `concrete` 한 칸만 채워졌다. 계층을 타지 않고 concrete로 직행했다 | abstract·logical의 형식 언어와 `-space` 형식 |
| 4. 조회 | 부분 — `workset` 첫 형태(역할 스코프 × 수준 창 × 앵커 이웃, 예산 패킹) | 앵커 밖 일반 질의 도구(`query`)가 없다 |
| 5. 연결 | 부분 — 인용 링크 · frontmatter 링크마다 링크 개체 + 구축 기록 증거 · `handoff`(수동 읽기 집합) | 하네스가 읽기·쓰기 집합을 자동 기록하지 않아 후보 링크가 안 생긴다 |
| 6. 갱신 | 부분 — `revalidate`(본문 해시 변경 → 재판정 대상) | 상태 저장·전파 규칙(`propagate`)이 없다 |
| 7. 뷰 | 부분 — `metrics`·`consistency`·`workset`·`communities` | 일반 질의(`query`)·tangle·매트릭스 뷰가 없다 |
| 8. 일반화 | 미착수 | 관측(`memory`·실행 기록)이 없다 |

**병목은 4·5단계의 자동화다.** 조회(`workset`)·연결(링크 개체·`impact`)의 첫 형태는 있으나 하네스가 읽기·쓰기
집합을 기록하지 않아, 링크가 편집의 부산물로 생기지 않고 손으로 구축된다.

   않는다. 그 결정에서 후보는 -space 청크다.
3. ~~본문 인용 추출~~은 **완료됐다**(2026-09-07, `tools/extract_refs.py`, 인용 링크 27개).
   참조 무결성이 생성 시점에 강제된다.
4. **규칙 물질화**는 `superseded → suspect`와 가정 위반 → `invalidated` 전파를 SPARQL
   UPDATE로 옮기는 것이다. 산출물은 `bazel-out`에만 둔다 ([`method.md` §7](method.md#7-갱신)).
5. **활용 도구 1차: `labels`/`workset`, `query`**를 만든다. 조회가 여기서 시작된다. 그래프를
   임베디드 저장소에 올리고 질의를 도구로 노출하되, **부분그래프를 통째로 로드하지 않는다.**
   스코프 필터와 예산 패킹을 그 위에 얹는다.
6. **프로파일 구축 절차**는 첫 분야 프로파일을 실제로 하나 만들면서 뽑는다.
   Bazel 라벨을 코드 앵커로 쓰는 것이 그 프로파일의 첫 결정 후보다.
7. **미구현 게이트**는 카탈로그 정합성, 복합체 동질성, 결정 역할 태그, 정규화 검사다
   ([`tools.md` §게이트 밖](tools.md#게이트-밖--규약으로-남은-것)).
8. **`metrics` 도구**는 지금 손으로 세는 수치를 산출로 만든다. 문서는 수치를 적지 않고 생성물을
   인용한다.

산출 이력과 재정렬의 경위는 git 이력이 원본이다 (`git log -- docs/roadmap.md`).
