# 도입 순서와 현재 위치

체계 전부를 한 번에 도입하지 않는다. 각 단계가 이전 단계 없이 성립하지 않고,
각 단계 끝에 **측정 가능한 산출**이 있다. 원래 노트 Part XII이었고, 진행 상태를
추적해야 하는 프로젝트 문서이므로 청크가 아니라 여기 있다.

## 단계

| 단계 | 도입 | 전제 | 끝의 산출 (측정) | 상태 |
|---|---|---|---|---|
| **1. 청크와 plane** | 42줄 청크, plane 클래스, 라벨 목록 읽기 | 온톨로지 `entity/` 최소본 | 청크 수, 고아율 | **완료** |
| **2. ODD와 스코프** | ODD 작성 절차, 스코프 파생, situation | 1단계 + 에이전트 카탈로그 | ODD 이탈 0회, 스코프별 situation 크기 | **완료** |
| **3. 링크 구축** | 편집 부산물로 `refines`·`satisfies` | 2단계 + 하네스의 읽기·쓰기 집합 기록 | 링크 밀도 | 미착수 |
| **4. 가정과 무효화** | 가정 청크, 판정 식, 전파 | 3단계 + ODD 판정 방법 A등급 이상 | 전수조사 없이 무효 범위 계산 1회 성공 | 미착수 |
| **5. 사다리 완성** | abstract·logical 수준, 후보 링크 | 4단계 | `decision` 청크의 `refines` 연쇄가 functional까지 닿는 비율 | 미착수 |
| **6. 상승** | 관측 → 어휘 | 5단계 + 실행 기록 누적 | 온톨로지 확장 건수 | 미착수 |
| **7. 복원과 감사** | 링크 복원, 감사 리포트 | 6단계 | 복원 비율, 감사 리포트 | 미착수 |

**1단계만으로도 이득이 있어야 한다** — 42줄 청크와 라벨 목록 읽기만으로 컨텍스트
낭비가 줄어야 한다. 그렇지 않으면 이후 단계를 진행할 근거가 없다.

**4단계가 이 체계의 존재 이유를 처음 검증하는 지점이다** (갱신 단절의 해소).
여기서 실패하면 설계를 재검토한다.

## 현재 위치 — 2단계 완료

| 산출 | 실측 |
|---|---|
| 청크 수 | `chunks/decision/` — `ls chunks/decision/*.md \| wc -l` |
| 고아율 | 0 — 모든 청크가 `kg/composite-kg.ttl`의 어느 구성체의 부분 |
| ODD 조건 | 7개, 전부 판정 방법과 등급 보유 |
| 스코프 | 역할 5개 전부 파생됨 (`id:scope-*`) |
| ODD 이탈 | 1건 발견·해소 — 동시 에이전트 한도(≤2)와 카탈로그 역할 합(5)의 불일치 |

**측정이 자동화되어 있지 않다.** 고아율·청크 수는 손으로 세고 있고, ODD 이탈은
문서를 읽다가 발견했다. 단계별 산출이 "측정 가능"하다는 것과 "측정되고 있다"는
것은 다르다 — 3단계 진입 전에 지표 수집을 게이트에 넣는 것이 자연스럽다.

## 3단계 진입 조건

3단계(링크 구축)를 시작하려면 다음이 필요하다:

1. **`related/trace` 온톨로지 모듈** — 링크 타입을 object property로, plane 제한을
   정의역·치역 공리로. 추적성 정보 모델은 [`id:chunk-d0010`](../chunks/decision/d-0010-link-types.md).
2. **하네스의 읽기·쓰기 집합 기록** — 링크는 편집 연산의 부산물로 만들어진다
   ([`id:chunk-d0009`](../chunks/decision/d-0009-link-by-construction.md)). 지금
   하네스는 무엇을 읽고 무엇을 썼는지 기록하지 않는다. 이것이 실질적인 장애물이다.
3. **9.6절 입력 검증 게이트** — 2단계의 산출물(카탈로그·스코프)이 기계로 검사되지
   않으면 3단계가 그 위에 쌓인다. `docs/gate-design.md`의 미구현 목록 참조.

## 단계별 소요

노트는 단계별 기간·인력을 **추정하지 않는다** — 실측 전에는 추정하지 않는다는
방침이다. 1·2단계의 실측치도 이 저장소 하나의 사례이므로 일반화하지 않는다.
