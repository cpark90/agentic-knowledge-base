# 커버리지의 분모를 어떻게 세는가

## 질문
커버리지의 분모는 ODD다. 그런데 ODD는 속성들의 값·범위 집합이고 "한 속성 조합이 어느
단계에서든 한 번 검증되면 커버"인데, 조합의 수는 값 범위의 곱이라 폭발한다. 분모를
**전체 조합**으로 세는가, 대표 조합인가, 속성별 개별 커버인가?

## 이미 정해진 것
- 분모는 ODD, 단계별 합산, 6단계(실환경) 관측은 제외, 100은 될 수 없다 (d-0135).
- 테스트베드의 환경 정의는 ODD의 부분집합이어야 한다 (d-0139).
- 위험 시나리오는 결함 요인 조합에서 내려 만든다 — 조합 공간의 빈칸이 "아직 시험 안 한 것"
  (d-0140).
- 자율 진행을 허용할 커버리지 하한은 체계가 정하지 않는 입력이다.

## 현재 상태
ODD 조건 7개(정적 4·환경 2·동적 1)이고 값이 대부분 단일값이라 이 저장소에서는 조합 공간이
작다. 시나리오 0, 커버리지 측정 0. `defect` 어휘가 없어 위험 가중도 계산할 수 없다.

## 답이 가르는 것
커버리지 수치의 의미와 자율 진행 판단의 기준. 분모 산정이 다르면 같은 시나리오 집합의
커버리지가 몇 배 차이 난다.

## 선택지
- **A. t-wise(기본 pairwise)** — 모든 t개 속성 조합이 최소 1회. 분모가 계산 가능하고 조합
  테스팅의 표준이다. t는 ODD 입력.
- **B. 위험 가중** — 결함 요인 조합에 걸린 조합만 분모에 넣는다. `defect` 어휘가 선행해야 한다.
- **C. 프로파일 입력** — 코어는 "분모는 ODD"만 고정하고 산정 방식은 분야마다 정한다.
