# 후보 링크를 확정으로 올리는 판단을 무엇으로 하는가

## 질문
가능 집합인 후보에서 확정 링크로 넘어가는 순간 "이 둘이 실제로 이 관계에 있다"를 무엇을
근거로 말하는가? 구축이면 만든 주체가 알므로 근거가 있지만, 복원·후보 축소·유저 확정의
경우 근거의 종류와 강도가 정해지지 않았다.

## 이미 정해진 것
- 근거는 검사 가능성 순으로 구축 기록 > 동시 편집 이력 > 테스트 공동 커버 > 임베딩 > 같은
  세션에서 읽음이다 (d-0110). 임베딩은 후보 추림에만 쓴다.
- 가능성은 확률이 아니라 가능/불가능 집합이다 (d-0097).
- 후보 없음(모순)은 자동으로 풀지 않고 유저에게 넘긴다 (d-0103).
- 임베딩 유사도를 확정 근거로 쓰는 것은 기각 (d-0009).
- 후보 상태와 신뢰도 ω의 설계는 [`../feedback/dependency-graph-design.md`](../feedback/dependency-graph-design.md)에 있다.

## 현재 상태
링크는 0이고 판단 사례는 없다. 가장 가까운 것은 분해 감사가 "d-0067은 d-0008의 누락 보충"이라고
산문으로 판정한 것이며, 근거는 "같은 절 출처"였다.

## 답이 가르는 것
확정을 에이전트가 할 수 있는지, 유저 확인이 필요한지가 갈린다. 그리고 "후보를 좁히는 것은
자유, 근거 없이 하나를 할당하는 것은 금지"라는 균형점을 기계 규칙으로 어떻게 쓰는지가 갈린다.

## 선택지
- **A. 근거 종류 = 확정 권한**: 구축·동시 편집·테스트 공동 커버는 에이전트가 확정할 수 있고,
  임베딩·같은 세션 읽음은 후보까지만 허용한다. 링크 개체에 근거 종류를 필수 속성으로 둔다.
- **B. 유일 후보면 자동 확정**: 제약 전파 결과 하나만 남으면 할당한다.
- **C. 항상 유저 확정**: 연결 단계 초기에 운영하는 방식이다. 링크 밀도가 낮게 유지되는 대가를 치른다.
