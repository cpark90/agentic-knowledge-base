# methodology — 전체 순서와 그 이유

**methodology는 순서이고, [`method.md`](method.md)는 각 단계를 어떻게 하는가이며,
[`rules.md`](rules.md)는 그 결과가 유효한지의 규칙이다.** 원본은 노트 v3
([`agent-knowledge-system-notes.md`](agent-knowledge-system-notes.md)) Part VI·XI과
운용 지도다. 여기의 순환은 **운용 순환**이고, 이 저장소 자신이 어디까지 왔는가의
**도입 7단계**는 [`roadmap.md`](roadmap.md)에 있다 — 둘은 다른 축이다.

## 순서

```
프로파일 구축 → ODD 작성 → 하강(저작) → 조회 → 연결 → 갱신 → 투영 → 상승
                                                                    │
                     (교훈이 다시 프로파일·ODD·결정으로) ←──────────┘
```

| # | 단계 | 산출 | 다음 단계의 전제가 되는 이유 | 방법 |
|---|---|---|---|---|
| 1 | **프로파일 구축** | `profile/<분야>` 모듈 — 각 plane의 실체·판정 도구·조건 어휘·결함 유형 | 어휘가 없으면 ODD의 조건을 개념에 대응시킬 수 없다 (d-0063 2단계) | [method §1](method.md#1-프로파일-구축) |
| 2 | **ODD 작성** | 조건 3분류·판정 방법·등급, 명시 제외 | ODD가 비면 스코프가 잘리지 않고 가정이 참조할 속성이 없다 — **체계 전체가 정지한다** (d-0063) | [method §2](method.md#2-odd-작성) |
| 3 | **하강(저작)** | functional → abstract → logical → concrete → executable 의 청크 | 조회·연결의 대상이 있어야 한다 | [method §3·§4·§5](method.md) |
| 4 | **조회** | 작업 집합 (스코프 × level 창) | 에이전트가 무엇을 보는지가 정해져야 편집의 읽기 집합이 정의된다 | [method §8](method.md#8-조회) |
| 5 | **연결** | 링크 — 편집 부산물로 구축, 복원은 예외 | 링크 없이는 무효화 범위를 계산할 수 없다 (d-0009) | [method §6](method.md#6-연결) |
| 6 | **갱신** | 가정 판정 → 무효화 전파 → 재판정 | 갱신 단절의 해소가 이 체계의 존재 이유다 (d-0007) | [method §7](method.md#7-갱신) |
| 7 | **투영** | tangle·weave·문서·추적 매트릭스 — 저장하지 않고 질의 | 축적된 지식이 쓰이는 형태 (d-0075) | [method §9](method.md#9-투영) |
| 8 | **상승** | 관측 → 도메인 → 변수 → 개념. 온톨로지가 자란다 | 다음 프로젝트가 자란 어휘로 시작한다 (d-0006) | [method §10](method.md#10-상승) |

**단계를 건너뛰지 않는다.** functional에서 곧바로 executable로 가는 것이 현재 에이전트의
기본 동작이며 그것이 사다리 단절의 원인이다 (노트 6.1절).

**하강의 산출은 개발 KB(`kb/dev/`)에, 검증 지식은 V&V KB(`kb/vv/`)에 쌓인다.** 하강과
나란히 vnv 역할이 검증 목표·시나리오·판정 기준을 저작하고 `verifies`로 개발 KB를
가리킨다 — 저작·판정 분리가 KB 수준에서도 성립한다 (노트 Part VII).

## 완료 판정

각 단계는 다음으로 넘어가기 전에 판정된다. 판정은 시간이 아니라 **상태 확인**이다.

| 단계 | 완료 판정 |
|---|---|
| 프로파일 구축 | 경쟁 질문이 전부 질의로 답해진다 (d-0052) · `bazel test //ontology:gate_test` PASS |
| ODD 작성 | 조건마다 객관적 판정 방법과 등급 A~C · 5단계 절차의 마지막(실제 조건 대조)에서 이탈 0 (d-0063) |
| 하강 | 각 전이가 근거와 `refines` 기록을 남겼다 · 게이트 PASS (d-0005) |
| 조회 | 역할별 작업 집합이 컨텍스트 예산 안에 든다 (d-0041) |
| 연결 | 링크 밀도 > 0, 복원 비율이 낮다 (d-0112) |
| 갱신 | 전수조사 없이 무효 범위가 계산된다 (d-0007) |
| 투영 | 저장된 뷰가 없다 — 전부 질의 결과다 (d-0075) |
| 상승 | 온톨로지 확장 건수 · 승격된 교훈이 규칙이 되었다 (d-0006 · d-0017) |

## 도입 순서 — 1단계만으로도 이득이 있어야 한다

전부를 한 번에 도입하지 않는다. **앞 단계만으로 이득이 확인되지 않으면 다음 단계를
진행할 근거가 없다.** 이 저장소 자신의 진행 상태와 실측은 [`roadmap.md`](roadmap.md).
