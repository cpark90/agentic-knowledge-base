# 리스크와 설계 긴장

리스크는 체계가 실패하는 방식이고, 긴장은 서로 반대 방향을 요구하는 두 요구 사이에서 정한 균형점이다. 이 문서는
둘을 추적한다. 이 문서의 대응은 다른 곳의 결정을 **가리키기만** 하므로, 이 문서는 단위 지식이 아니라 문서로 둔다.
여기서 결정을 다시 서술하면 같은 내용을 두 곳에서 관리하게 된다.

## 리스크와 대응

| 리스크 | 대응 | 이 저장소의 방어 상태 |
|---|---|---|
| **어휘 우회** — 온톨로지 밖 용어로 지식이 생성된다 | 게이트가 어휘 밖 술어를 거부한다 | **기계화됨** — `validate.py`의 vocab 검사 |
| **가정 폭증** — 단위 지식마다 가정을 붙이다 관리할 수 없게 된다 | 가정은 ODD 속성만 참조하므로, 가정 수의 상한은 속성 수와 단위 지식 수의 곱이다. D등급은 배제한다 | **기계화됨** — odd-ref 게이트 |
| **질의 지연** — 그래프가 커지면 작업 집합 조립이 느려진다 | 라벨과 상태를 head 그래프에 두어 본문 없이 질의한다 | **구조로 충족** — head를 분리했다 |
| **어휘 경직** — 온톨로지가 자라지 못해 새 개념을 담을 수 없다 | 일반화가 온톨로지까지 닿게 한다(`p6-ascent-generalization`) | 미착수 — 일반화 단계 |
| **정제 계층 우회** — functional에서 곧바로 executable로 건너뛴다 | 중간 산출물을 커밋 조건으로 둔다 | **측정됨** — 한 단계씩 내려가지 않는 `refines`와 지식 종류별 허용 수준 표의 위반은 생성 뷰 `bazel build //kg:metrics`의 "세 축 대리" 절이 센다 |
| **logical 공동화** — logical 수준에 후보 없이 형식만 남는다 | `contract`와 `schema`의 logical 칸을 시험대로 삼는다 | **해소됨** — 실험으로 독립 내용 안을 확정했다(Q79-a, [`p6-contract-logical-is-content`](../kb/dev/decision/p6-contract-logical-is-content/conclusion.md), [설계 공간](../space/contract-artifact-logical-space.md)) |
| **정체성 단절** — 리팩터링할 때 개체가 새로 생긴다 | 지속 IRI와 해시 버전 IRI를 함께 둔다 | [미해결](../space/temporal-identity-space.md). `contentHash`는 있고 해시 버전 IRI는 정하지 않았다 |
| **링크 붕괴** — 오래된 링크가 실제 구조를 잘못 알린다 | 링크 상태를 관리하고 재검증 시점을 둔다 | 부분 — 링크 개체의 수와 증거 기록 비율은 `bazel build //kg:metrics`의 "3단계 대리" 절이 내고, 상태는 증거 기록 규칙(verify 질의)으로 판정한다. suspect 후보는 `revalidate`가 본문 해시가 바뀐 단위 지식에서 링크와 역의존(rdeps)을 따라 계산하고, 상태는 저장하지 않는다 |
| **구축 누락** — 링크를 만들 수 있던 순간에 만들지 않는다 | 링크를 편집의 부산물로 강제하고, 복원은 감사에만 쓴다(`p10-link-by-construction`) | 미착수 — 읽기와 쓰기의 기록이 없다 |
| **직렬화 노이즈** — diff가 의미 없는 변경으로 오염된다 | 정규화 직렬화 | 정규 직렬화는 도구 `canonicalize`를 사람이 돌리는 규약이고 테스트가 아니다. 그래서 게이트 등록부(`defs/kb.bzl`의 `GATES`)는 `canon`을 기계 밖 판정 계층인 `human`에 둔다(유저 답 Q114-a, 2026-10-24). 테스트로 도는 게이트의 목록은 `bazel query 'tests(//...)'`가 낸다 |
| **온톨로지 과설계** — 역량 질문에 기여하지 않는 개념이 생긴다 | 개념을 역량 질문과 대조한다 | 목록은 있다([`competency-questions.md`](competency-questions.md)). 대조는 규약이고, `term_propose`의 `--cq`가 받는다 |
| **항목 파편화** — 억지로 나눠 자립성 없는 단위 지식이 늘어난다 | 병합 신호와 크기 분포를 본다 | 규약이다. 크기 분포는 `bazel build //kg:metrics`의 "크기 분포" 절이 낸다 |
| **라벨 부패** — 본문은 바뀌고 라벨은 바뀌지 않는다 | 본문 해시가 바뀌면 라벨 재검토를 요구한다 | 해시는 있으나 재검토 트리거는 없다. 대신 `consistency`의 라벨 형식 항목과 라벨 대표성 실험이 그 역할을 대신한다 |
| **ODD 단일 장애점** — ODD가 틀리면 전부 틀린다 | 작성 5단계로 검증하고 판정 등급을 둔다 | 조건마다의 판정 방법은 ODD 문서의 CHECKS에 있고, 판정 결과는 `bazel run //tools:odd_check`가 낸다 |
| **도입 저항** — 토큰 상한(결정 `p1-chunk-unit-is-tokens`)과 라벨, 지식 종류(`plane`) 선택이 부담이 된다 | 앞 단계만으로 이득을 확인한다 | 통과 조건은 결정 [`p14-stage-pass-conditions`](../kb/dev/decision/p14-stage-pass-conditions/conclusion.md)에 있고, 통과 여부는 `bazel build //kg:metrics`가 낸다 |
| **자기목적화** — 체계가 자기 자신을 서술하는 데 노력이 쏠린다 | 산출물은 온톨로지와 방법, 도구의 셋뿐이고, 결정은 참조로 동결한다 | **실제로 일어났다** — 2026-09-02 재정렬 |

**기계화된 것은 아직 소수다.** 기계화된 것은 어휘 우회와 가정 폭증, 정체성 해시, 링크 증거 규칙, 드리프트 가드
정도이고, 나머지는 규약이거나 아직 착수하지 않은 단계에 걸려 있다. 따라서 리스크 표가 길다고 방어가 두꺼운 것은
아니다.

## 설계 긴장

설계 긴장에서는 어느 한쪽을 택하지 않고 균형점을 정한다. 이 표의 목적은 **균형점이 정해진 것과 아직 정해지지
않은 것을 구분하는 것**이다.

| 긴장 | 한쪽 | 다른 쪽 | 균형점 |
|---|---|---|---|
| **컨텍스트 청결과 지식 누적** | dispatch — 깨끗한 컨텍스트 | 세션 유지 — 누적 지식 | 전체 컨텍스트가 아니라 작업 집합만 넘긴다. 누적한 지식은 `memory` 승격으로 보존한다 |
| **유저 판단과 자율 진행** | 결정마다 유저에게 묻는다 | 무인으로 진행한다 — 커버리지를 전제한다 | 커버리지가 임계 이상이면 자율, 이하면 에스컬레이션. **완전 커버리지는 전제하지 않는다** |
| **충실한 수행과 과도한 추측** | 언급하지 않은 부분도 채운다 | 근거 없는 할당은 금지한다 | **후보를 좁히는 작업은 자유롭게 하되, 근거 없이 하나를 할당하는 것은 금지한다.** 같은 행동이라도 남은 후보 수에 따라 허용 여부가 갈린다 |
| **역할 세분화와 오염 전파** | 역할을 나눌수록 완성도가 높아진다 | 채널이 늘수록 오염 경로가 늘어난다 | **4역할을 유지한다.** inspection은 2026-09-13에 hci로 통합했다. 조사와 git 관리는 소통 역할의 일부이기 때문이다. 측정된 오염 사례의 원인은 역할 수가 아니라 검사의 부재였다. 지표가 쌓인 뒤 다시 검토한다 |
| **항목 자립성과 조망 비용** | 작게 나눌수록 재사용과 무효화가 정밀해진다 | 조각이 많을수록 라벨 목록이 길어진다 | 병합 신호를 둔다. 복합체의 부분 수 상한은 7±2다 |
| **안전율(중복)과 컨텍스트 예산** | 같은 내용이 한 번 더 있는 것이 빠진 것보다 안전하다 | 중복은 작업 집합 안에서 예산을 두 번 쓴다 | **다른 적용 범위 사이의 중복은 안전율로 두고, 같은 작업 집합 안의 중복은 정리한다.** 알고 둔 중복은 `coUpdatesWith`로 묶고 재검증 시점에 정리한다 ([`p4-redundancy-as-safety-margin`](../kb/dev/decision/p4-redundancy-as-safety-margin/conclusion.md)). 중복률은 `consistency` 보고로 감시한다 |
| **표준어와 정확성** | 용어를 지어내지 않는다 | 표준어가 뜻에 정확히 맞지 않는 경우가 있다 | 표준 관계의 하위 속성으로 고유 관계를 두어 둘 다 취한다 |
| **검사와 활용** | 게이트가 규칙을 만든다 | 활용 도구 없이는 지식이 쓰이지 않는다 | **활용이 먼저다.** 2026-09-02에 검사 도구는 4개였고 활용 도구는 0개였으며, 이 상태가 재정렬의 이유였다. 지금 있는 활용 도구(workset, metrics, impact, handoff, consistency 등)의 목록은 [`tools.md`](tools.md)가 원본이다 |

가장 자주 적용되는 규칙은 세 번째 긴장인 **후보를 좁히는 것과 할당하는 것의 구분**이다.
