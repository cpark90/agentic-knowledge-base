# 리스크와 설계 긴장

체계가 실패하는 방식(리스크)과, 서로 당기는 힘 사이에서 정한 균형점(긴장)을 추적한다.
대응이 다른 곳의 결정을 **가리키는** 성격이라 지식이 아니라 문서다 — 여기서 결정을
서술하면 이중 관리가 된다.

## 리스크와 대응

| 리스크 | 대응 | 이 저장소의 방어 상태 |
|---|---|---|
| **어휘 우회** — 온톨로지 밖 용어로 지식이 생성됨 | 게이트가 어휘 밖 술어를 거부 | **기계화됨** — `validate.py` vocab |
| **가정 폭증** — 항목마다 가정을 붙이다 관리 불능 | ODD 속성만 참조하므로 상한 = 속성 수 × 항목 수. D등급 배제 | **기계화됨** — odd-ref 게이트 |
| **질의 지연** — 그래프가 커지면 작업 집합 조립이 느려짐 | 라벨·상태를 head 그래프에 두어 본문 없이 질의 | **구조로 충족** — head 분리 |
| **어휘 경직** — 온톨로지가 자라지 못해 새 개념을 담을 수 없음 | 일반화가 온톨로지까지 닿게 (d-0006) | 미착수 — 일반화 단계 |
| **계층 우회** — functional에서 곧바로 executable로 | 중간 산출물을 커밋 조건으로 | **현재 모든 항목이 concrete 직행** |
| **logical 공동화** — 후보 없이 형식만 남음 | 시험대: `contract`·`artifact`의 logical 칸 | [미해결](open-questions/contract-artifact-logical.md) |
| **정체성 단절** — 리팩터링 시 개체가 새로 생김 | 지속 IRI + 해시 버전 IRI | [미해결](open-questions/temporal-identity.md) · 해시 미구현 |
| **링크 붕괴** — 오래된 링크가 실제 구조를 오도 | 링크 상태 관리, 재검증 시점 | 미착수 — 링크 0 |
| **구축 누락** — 링크를 만들 수 있던 순간에 만들지 않음 | 편집 부산물로 강제. 복원은 감사용 (d-0009) | 미착수 — 읽기·쓰기 기록 없음 |
| **직렬화 노이즈** — diff가 의미 없는 변경으로 오염 | 정규화 직렬화 | 도구는 있으나 **게이트에 안 걸림** |
| **온톨로지 과설계** — 역량 질문에 기여하지 않는 개념 | 역량 질문 대조 | **역량 질문 목록 자체가 없다** |
| **항목 파편화** — 억지 분할로 자립성 없는 항목이 늘어남 | 병합 신호, 크기 분포 | 규약. 실측상 파편화 징후 없음(최빈 15줄) |
| **라벨 부패** — 본문은 바뀌고 라벨은 안 바뀜 | 본문 해시 변경 시 라벨 재검토 요구 | 해시가 없어 트리거 불가 |
| **ODD 단일 장애점** — ODD가 틀리면 전부 틀림 | 작성 5단계 검증, 판정 등급 | 조건 7개 전부 판정 방법 보유 |
| **도입 저항** — 42줄·라벨·plane 선택이 부담 | 앞 단계만으로 이득 확인 | [`roadmap.md`](roadmap.md) |
| **자기목적화** — 체계가 자기 자신을 서술하는 데 노력이 쏠림 | 산출물은 셋뿐(ontology·방법·도구), 결정은 참조로 동결 | **실제로 일어났다** — 2026-09-02 재정렬 |

**기계화된 것은 셋뿐이다.** 나머지는 규약이거나 미착수 단계에 걸려 있다. 리스크 표가 길다고
방어가 두꺼운 것은 아니다.

## 설계 긴장

어느 한쪽을 택하지 않고 균형점을 정한다. **균형점이 정해진 것과 아직 정해지지 않은 것을
구분하는 것**이 이 표의 목적이다.

| 긴장 | 한쪽 | 다른 쪽 | 균형점 |
|---|---|---|---|
| **컨텍스트 청결 vs 지식 누적** | dispatch — 깨끗한 컨텍스트 | 세션 유지 — 누적 지식 | 전체 컨텍스트가 아니라 작업 집합만 넘긴다. 누적은 `memory` 승격으로 보존 |
| **유저 판단 vs 자율 진행** | 결정마다 유저 | 무인 — 커버리지 전제 | 커버리지가 임계 이상이면 자율, 이하면 에스컬레이션. **완전 커버리지는 전제하지 않는다** |
| **충실한 수행 vs 과도한 추측** | 언급하지 않은 부분도 채운다 | 근거 없는 할당은 금지 | **후보를 좁히는 작업은 자유, 근거 없이 하나를 할당하는 것은 금지.** 같은 행동이 후보 수에 따라 갈린다 |
| **역할 세분화 vs 오염 전파** | 나눌수록 완성도 상승 | 채널이 늘수록 오염 경로 증가 | **5역할 유지.** 실측된 오염 사례의 원인은 역할 수가 아니라 검사 부재였다. 지표가 쌓인 뒤 재검토 |
| **항목 자립성 vs 조망 비용** | 작게 나눌수록 재사용·무효화 정밀 | 조각이 많을수록 라벨 목록이 길어짐 | 병합 신호. 7±2가 복합체 상한 |
| **표준어 vs 정확성** | 지어내지 않는다 | 표준어가 정확히 맞지 않을 때 | 표준 관계의 하위 속성으로 고유 관계를 두어 둘 다 취한다 |
| **검사 vs 활용** | 게이트가 규칙을 만든다 | 활용 도구 없이는 지식이 쓰이지 않는다 | **활용이 먼저다.** 검사 4개에 활용 0개인 현재 상태가 재정렬의 이유 |

세 번째 긴장(**후보를 좁히는 것과 할당하는 것의 구분**)이 가장 자주 적용되는 규칙이다.
