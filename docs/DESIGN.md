# 설계 — 이 저장소가 체계를 구현하는 방식

**체계의 설계**는 결정 청크(`chunks/decision/`)에 있다. 이 문서는 그 체계를 이
저장소가 **어떻게 실현했는가**를 기록한다. 청크가 "무엇을 왜"이고, 여기가
"이 저장소에서 어떻게"다.

그러므로 이 문서는 결정을 복사하지 않고 **IRI로 가리킨다** — 문서가 청크 위의
투영이라는 것이 4.6절이다.

## 확정 결정

- **A1 — 하네스는 Bazel이다.** 지식 산출물은 데이터 타깃, 검사 게이트는 테스트
  타깃. `bazel test //...` 한 번이 게이트 전체다. 근거와 기각된 대안은
  [`id:chunk-d0001`](../chunks/decision/d-0001-bazel-harness.md).
- **A2 — 한 청크는 한 파일.** 지식 청크(`chunks/`)도, 온톨로지 청크
  (`ontology/**`)도, shape도 파일 하나가 단위 하나다. 모듈은 디렉토리이고
  디렉토리가 Bazel 패키지다. 근거는 [`id:chunk-d0002`](../chunks/decision/d-0002-chunk-42-line-unit.md).
- **A3 — head는 생성물이다.** 청크의 head 그래프를 손으로 쓰지 않는다.
  frontmatter가 원본이고 `//kg:chunks_kg`가 생성한다 — 상세는
  [`storage-design.md`](storage-design.md).
- **A4 — 게이트가 곧 규약의 이빨이다.** 체계의 규칙 중 기계로 판정 가능한
  것은 전부 테스트 타깃이 된다. 판정 불가능한 것만 문서 규약(`STYLEGUIDE.md`의
  `[지킴]`)으로 남긴다 — 상세는 [`gate-design.md`](gate-design.md).
- **A5 — 그래프 안과 밖을 가른다.** 검사 대상인 지식(`ontology/`·`odd/`·`kg/`·
  `chunks/`)과, 대상이 아닌 운영 문서(`docs/`·`.claude/`)를 나눈다. 소통 기록을
  지식과 섞으면 어휘 폐쇄 검사가 무의미해진다.

## 왜 Bazel인가 — 세 성질의 대응

체계가 요구하는 성질과 빌드 도구의 성질이 맞물린다.

| 체계의 요구 | 노트 | Bazel의 성질 |
|---|---|---|
| 바뀐 지식만 재판정 | 8.6절 재판정 경계 | 입력 해시 기반 캐시 — 바뀐 파일의 게이트만 다시 돈다 |
| 산출물 간 의존을 명시 | Part VIII 링크의 전 단계 | BUILD 그래프가 의존을 선언으로 강제 |
| 판정 도구의 재현성 | 10.1절 재현성 | hermetic 툴체인 + 해시 고정 lock |
| 게이트 우회 금지 | 6.7절 검사 게이트 | 테스트 타깃이라 우회하려면 BUILD를 고쳐야 한다 (리뷰에 걸린다) |

파일·디렉토리로 구조화된 자료를 다루는 도구이므로 A2(한 청크 한 파일)와
자연스럽게 맞는다 — 청크가 파일이면 청크가 곧 빌드 입력이다.

## 층 구조

```
        ┌──────────────────────────────────────────────┐
  기반  │ 온톨로지 (T-Box)   ontology/**/*-ontology.ttl │  축 위에 있지 않다
        │ SHACL shape        ontology/shapes/*.ttl      │  (노트 0.1절)
        └──────────────────────────────────────────────┘
                              │ 어휘를 공급
        ┌──────────────────────────────────────────────┐
  경계  │ ODD                odd/project-odd.ttl        │  모든 스코프·가정의
        └──────────────────────────────────────────────┘  참조 대상 (0.4절)
                              │ 조건을 공급
        ┌──────────────────────────────────────────────┐
  지식  │ 청크 본문          chunks/<plane>/*.md        │  plane × level 격자
        │ 청크 head (생성)   kg/chunks-kg.ttl           │  위에 배치된다
        │ 그 밖의 개체       kg/{base,catalog,composite}-kg.ttl │
        └──────────────────────────────────────────────┘
                              │ 검사 대상
        ┌──────────────────────────────────────────────┐
  판정  │ 게이트 도구        tools/*.py                 │  executable
        │ 게이트 배선        defs/knowledge.bzl, BUILD  │
        └──────────────────────────────────────────────┘
```

**기반이 축 위에 있지 않은 것이 핵심이다** (노트 0.1절). 온톨로지는 plane·level을
갖지 않는다 — 그것으로 다른 것의 위치를 정하는 어휘이기 때문이다. 산출물이
격자 어디에 놓이는지는 [`artifact-placement.md`](artifact-placement.md)가 원본이다.

## 세 실패 모드의 이 저장소판

일반 원칙은 [`id:chunk-d0014`](../chunks/decision/d-0014-three-failure-modes.md).
여기서는 그것이 어떤 게이트로 실현됐는지만 적는다.

| 실패 모드 | 이 저장소의 방어 | 게이트 |
|---|---|---|
| context drift (어휘 분화) | 데이터의 술어는 `agt:` 온톨로지 또는 등록된 표준 어휘여야 한다 | `validate.py` vocab |
| context rot (컨텍스트 부패) | 본문 42줄 상한, 라벨 목록 우선 읽기 | `chunk_lint.py`, SHACL `lineCount` |
| orphan (고아 지식) | 모든 청크가 어느 구성체의 부분 | **아직 게이트 없음** — 규약과 리뷰로 지킨다 |

**고아 검사가 아직 기계화되지 않았다.** 현재는 청크 20개 전부가 구성체 7개 중
하나에 속하지만(고아 0), 그것을 강제하는 검사가 없다. 노트 4.13절 고아율이
지표로 정의되어 있으므로 3단계(링크)와 함께 게이트화하는 것이 자연스럽다.

## 하네스 밖 — 운영 문서

`docs/`와 `.claude/`는 그래프 밖이다(A5). 여기 있는 것:

| 위치 | 성격 | 원본 문서 |
|---|---|---|
| `docs/*.md` | 설계 문서 — 청크 위의 투영, 결정은 IRI로 인용 | 이 문서 |
| `docs/feedback/` | 유저 소통 채널 (3-lane) | `docs/feedback/README.md` |
| `.claude/agents/` | 별도 세션 역할 정의 | `AGENTS.md` 역할 표 |
| `.claude/agent-memory/` | 역할별 누적 메모리 | 9.4절 승격 규칙 |

**설계 문서가 지식이 아닌 이유** — 이 문서들은 저장소의 구조·배선을 서술하며,
그 내용은 저장소를 보면 확인된다. 지식(청크)은 저장소를 봐도 알 수 없는 것 —
왜 그렇게 정했는가 — 을 담는다. 문서가 결정을 서술하기 시작하면 청크와 이중
관리가 되므로, 결정은 **인용만** 한다.

## 미해결

- **고아 게이트** — 위 표의 빈칸. 구성체 소속과 링크를 함께 봐야 하므로 3단계
  이후.
- **9.6절 입력 검증** — 에이전트 카탈로그의 정합성(역할별 read plane 최소 1,
  설계/구현/운영의 write plane 비공유, `maxConcurrent` 합이 ODD 안)이 규약으로만
  지켜진다. 실제로 이 검사가 없어 ODD 한도와 카탈로그 합이 한동안 어긋나 있었다.
- **`artifact` plane의 등록** — `tools/*.py`는 executable 수준의 산출물이지만
  청크로 등록되어 있지 않다. 자세한 판단은 `artifact-placement.md` §3.
