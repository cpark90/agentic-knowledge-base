# 목적과 대상 지식

이 문서는 **무엇을 위해 이 체계가 있는가**와 **그 체계가 다루는 지식이 무엇인가**를
고정한다. 원본은 노트 v3([`agent-knowledge-system-notes.md`](agent-knowledge-system-notes.md))의
산출물 정의·Part 0과 운용 지도([`agentic-knowledge-base-structure.md`](agentic-knowledge-base-structure.md))다.
요구 층의 진입 문서는 루트의 [`INTENT.md`](../INTENT.md)이며, 궁극 목적의 정식 서술도
거기에 있다.

## 궁극 목적

> 특정 분야에서 사업을 수행하는 업체가, 그 분야의 지식을 에이전트가 활용할 수 있는
> 형태로 축적하고, 프로젝트마다 그 지식 위에서 시스템을 만들고 운용한다.

세 가지가 따라 나온다.

- **분야는 온톨로지의 프로파일 층으로 나타난다** — 업체·조직을 개체로 두지 않는다.
  분야마다 코어를 확장한 `profile/<분야>`가 있고, 그것이 "그 분야의 지식"이다
  ([`ontology.md`](ontology.md)).
- **프로젝트는 ODD 단위로 나타난다** — 프로젝트당 ODD 하나가 그 프로젝트의 운영
  조건이자 스코프·가정·시나리오의 분모다 (노트 3장).
- **행위자 층은 두지 않는다.** 업체·프로젝트·에이전트를 개체로 모델링하지 않는다
  (유저 결정 2026-09-04). 에이전트 역할은 지식이 아니라 하네스의 **입력**(에이전트
  카탈로그)이다 ([`input.md`](input.md), [`../AGENTS.md`](../AGENTS.md)).

## 대상 지식 — 두 묶음

지식은 **시스템을 만들기 위한 것**과 **시스템에 대한 것**으로 갈린다. 전자는 계층
정제의 산출이고 후자는 일반화의 입력이다 (노트 Part VI).

### 시스템을 만들기 위한 지식 (정제의 산출)

| 종류 | 어디에 놓이는가 |
|---|---|
| **요구** | `requirement` plane, functional 전용 — 이해관계자 관심사의 EARS 문장. `kb/dev/requirement/` |
| **의도** | ODD와 functional 수준 — 온톨로지 개념의 서술적 사용. 진입 문서는 `INTENT.md` |
| **결정** | `decision` plane. 결론(concrete)·근거(logical)·대안(logical) 세 청크의 복합체 (유저 결정 C2). `kb/dev/decision/` |
| **계약** | `contract` plane. 인터페이스 — 추적성의 기준축 |
| **스키마** | `schema` plane |
| **역량 질문** | 온톨로지가 답해야 하는 질문 목록 = 요구사항이자 완료 판정 |

### 시스템에 대한 지식 (일반화의 입력)

| 종류 | 어디에 놓이는가 |
|---|---|
| **구현** | `artifact` plane, concrete·executable 수준 |
| **관측** | 실행 기록. concrete 전용, append-only |
| **주석** | `annotation` plane. 판정·리뷰·설명 |
| **기억** | `memory` plane. 단기, 첫 실행 시 한 번에 읽는다 |
| **교훈** | 기억·관측에서 승격된 것. 결정 또는 규칙이 된다 |

plane은 일곱이고 **검증 메커니즘이 plane을 가른다** — 정의와 수준 허용표는
[`rules.md`](rules.md)와 `kb/ontology/entity/knowledge-item/`.

### 두 지식 베이스

지식은 저장소 하나 안에서 두 패키지로 갈린다 — **개발 KB**(`kb/dev/`)는 만들기 위한
지식, **V&V KB**(`kb/vv/`)는 검증 목표·시나리오·판정 기준. 두 KB를 잇는 링크는
`verifies` 하나뿐이고 그 주어는 항상 V&V 쪽이며, `kb/vv/`의 유일한 편집 주체는
vnv 역할이다 (노트 Part VII, `kg/catalog-kg.ttl`).

### 순환

```
만들기 위한 지식  →  시스템  →  시스템에 대한 지식  →  교훈  →  만들기 위한 지식
      (정제)                          (관측)          (일반화)
```

교훈이 두 묶음을 잇는 고리다. 정제만 있는 체계는 지식이 축적되지 않고, 일반화만 있는
체계는 의도와 산출물이 끊어진다 (노트 6.1·6.4절).

## 이 저장소가 만드는 것

세 산출물이다 — **온톨로지 코어**, **그것을 쓰는 방법론과 방법**, **그 방법을 수행하는
도구**. 분야 온톨로지와 개별 프로젝트의 ODD·지식은 이 저장소가 만들지 않는다 — 그것은
**입력**이 정해진 뒤의 일이다 ([`input.md`](input.md)). 현재 상태와 도입 순서는
[`roadmap.md`](roadmap.md).
