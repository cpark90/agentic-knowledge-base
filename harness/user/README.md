# 유저 채널 — 유저 ↔ hci 질문지 (`user/`)

> **규칙: 유저에게 피드백·결정을 요청할 때는 항상 이 채널의 질문지 파일로 한다.**
> 채팅의 선택지 UI나 본문 질문으로 결정을 받지 않는다. 채팅으로 먼저 답이 온 경우에도
> hci가 그 답을 질문지에 원문으로 옮겨 적어 기록을 남긴다.

hci가 유저에게 묻는 질문을 **파일**로 전달하고, 유저가 같은 파일에 답을 적어 돌려주는 채널이다.
hci ↔ orchestrator 채널(`harness/channel/`)과는 별개다. 프로토콜 전체의 원본은
[`../README.md`](../README.md)다.

## 구조

```
harness/user/
├── README.md            # 이 문서
├── Q-0001.md            # 질문지 (hci가 쓰고 유저가 답을 적는다)
├── Q-0002.md …
└── archive/             # 답이 모두 반영된 질문지 · legacy/ (2026-10-03 이전 채널의 기록)
```

## 쓰는 법 (유저)

1. `Q-<번호>.md`를 연다.
2. 각 질문의 `답:` 줄에 답을 적는다. 권장안을 따르면 `권장` 한 단어로 충분하다. 정하지 않으려면
   `보류`라 적는다. 덧붙일 설명은 그 아래에 자유롭게 적는다.
3. 다 적으면 hci 세션에 "답 적었어"라고 한마디 한다. hci가 `status: answered`를 대신 적고 읽어 처리한다.
   맨 위 frontmatter의 `status: open`을 `status: answered`로 직접 고쳐도 된다.

**반영 허가 신호는 둘 중 하나다**(Q24-b, 2026-10-04). 하나는 유저의 `answered` 태깅이다. 다른 하나는 질문지의 `답:` 줄이
채워져 있고 유저가 hci 세션에서 "답 적었어"라고 알리는 것이다. 이때 hci가 `status: answered`를 대신 적는다. 대신 태깅은 이 경우뿐이고,
`답:`이 빈 질문이 있으면 태깅하지 않는다. 허가의 주체는 어느 쪽이든 유저다. `보류`로 답한 질문은 반영하지 않는다.

## 처리 (hci)

- `answered` 질문지를 읽는다. 답을 `task`·`answer`·`knowledge` 메시지로 정제해 orchestrator에
  보낸다. `SOURCE=Q-<번호>`로 근거 질문지를 밝힌다. **hci는 답을 수행하지 않는다.**
- orchestrator의 `result`가 돌아오면 유저에게 결과를 보고하고, 질문지를 `status: closed`로 고쳐
  `archive/`로 옮긴다. 수행이 따르지 않는 답(확인·기각·보류)이면 메시지를 보낸 뒤 바로 닫는다.
- orchestrator가 보낸 `question` 가운데 유저 판단이 필요한 것도 질문지로 옮긴다. frontmatter의
  `re`에 그 메시지 id를 적는다.
- 유저가 채팅으로 먼저 답한 결정은 질문지를 만들어 `답:`에 원문을 옮겨 적는다.

## 상태

`open`(답 대기) → `answered`(유저 기입 완료 — 유저가 태깅하거나 유저의 알림으로 hci가 적는다) → `closed`(반영 완료, `archive/`로 이동)

## 형식

파일명은 `Q-<네 자리 번호>.md`다. 질문지 번호와 **질문 번호는 따로 센다.** 질문 번호(`Q1`, `Q2`, …)는
질문지 전역에서 단조 증가한다. 결정의 근거는 질문 번호와 선택지로 가리킨다(예: `Q12-a`).

```markdown
---
id: Q-0003
status: open             # open | answered(유저, 또는 유저 알림 뒤 hci) | closed(hci)
subject: 위험 등급 척도의 stable 전이
created: 2026-10-03
re: 0012                 # (선택) 이 질문지를 낳은 orchestrator question 메시지 id
---

# 위험 등급 척도의 stable 전이

> **이미 정해진 것** — 관련 결정과 그 결론. 이미 답한 것을 다시 묻지 않는다.
>
> **현재 상태** — 저장소 실물로 본 지금. 파일과 수치는 실측이다.

## Q12. 척도를 stable 로 올릴 것인가

(무엇이 정해지지 않았는가와 왜 어려운가를 적는다.)

- (a) 그대로 올린다. — 고르면 무엇이 바뀌는가와 비용
- (b) 문구를 검토한 뒤 올린다. — …
- (c) 둔다. — …

**권장:** (a) — 근거 한 줄

답:
```

- **한 줄 질문은 답을 받지 못한다**(유저 지적 2026-09-02). 질문마다 다섯 가지가 있어야 한다.
  다섯 가지는 질문과 그것이 어려운 이유, 이미 정해진 것, 현재 상태, 답이 가르는 것, 선택지다.
  앞의 둘은 머리 인용 블록에 모아 적어도 된다. 답이 가르는 것은 선택지마다 적는다.
- 선택지는 둘에서 넷이다. 각각의 비용을 적는다. `**권장:**`에는 hci 또는 orchestrator의 추천과
  근거를 적는다.
- 지식은 이름이 아니라 IRI·조건 id·`파일:줄`로 가리킨다. 수치는 실측한다.
- 산문은 단정 서술형이다. 의문문은 질문 제목과 질문 문장에만 쓴다.
- 유저의 작업이 필요한 판정지·기록지도 질문지다. 기입 칸마다 `답:` 줄을 둔다.
