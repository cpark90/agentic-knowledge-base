## Q197. Bazel을 누가 어떻게 설치하는가

Bazel이 없으면 메시지 발신과 모든 게이트가 멈춘다. 어려운 점은 설치가 저장소 밖의 시스템 파일을 바꾼다는 것이다. 그래서 interpreter의 파일 수정 경계 밖이다.

권장 방식은 bazelisk를 `bazel`이라는 이름으로 두는 것이다. bazelisk는 `.bazelversion`을 읽어 Bazel 9.2.0을 받아 쓴다. `/usr/local/bin`은 이미 떠 있는 두 세션의 PATH에 들어 있으므로 세션을 다시 띄우지 않아도 된다.

```bash
sudo curl -fL -o /usr/local/bin/bazel https://github.com/bazelbuild/bazelisk/releases/download/v1.25.0/bazelisk-linux-amd64
sudo chmod +x /usr/local/bin/bazel
cd ~/projects/agentic-knowledge-base && bazel version
```

- (a) **유저가 위 명령을 직접 실행한다.** interpreter 세션의 입력창에 `! ` 를 앞에 붙여 실행해도 된다. 비용은 명령 세 줄과 sudo 암호 입력이다. 첫 빌드에서 Bazel 9.2.0과 의존성을 받는 데 몇 분이 걸린다. 설치 뒤 interpreter가 Q-0087의 답을 보내고 `bazel test //...`로 이 호스트를 확인한다. 권한·방향: 그대로
- (b) **interpreter에게 설치를 맡긴다.** 이번 한 번에 한해 파일 수정 경계 밖의 쓰기(`/usr/local/bin/bazel` 하나)를 허가하는 것이다. sudo 암호가 필요하므로 설치 위치는 `~/.local/bin`이 된다. 이 경로는 지금 PATH에 없으므로 두 세션을 `run-interpreter.sh`와 `run-orchestrator.sh`로 다시 띄워야 한다. 권한·방향: 바꾼다
- (c) **이 호스트에서는 작업하지 않는다.** S5를 비롯한 진행이 멈춘다. 원본 작업 트리는 이미 지웠으므로 다른 호스트에 다시 클론해야 한다. 권한·방향: 그대로

**권장:** (a) — 경계를 바꾸지 않고, 두 세션을 다시 띄우지 않아도 된다.

답:a

hci의 읽기: 유저가 2026-11-28에 bazelisk를 설치했다(`/usr/local/bin/bazel`, `bazel version` 9.2.0). 이어서 `send.sh`의 검사 도구 빌드가 C 툴체인 자동 구성에서 멈췄다. 오류는 "Cannot find gcc or CC"였다. 이 호스트(Ubuntu 24.04.5)에는 `gcc`, `cc`, `g++`, `make`가 없다. Q197-a와 같은 방식으로 유저가 `sudo apt install -y build-essential`을 실행하는 것으로 읽었다. 선택이 새로 생기지 않으므로 새 질문은 두지 않는다.
