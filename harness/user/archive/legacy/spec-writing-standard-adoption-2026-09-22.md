# 명세 문서 작성 규격 — 기정을 두고 공백만 채우는 안 (2026-09-22, 2차)

원문: [`inquiries/spec-writing-standard-proposal.md`](inquiries/spec-writing-standard-proposal.md) (922줄, 유저 제공)

## 질문

유저 지시(2026-09-22) — "현 프로젝트에서 정해진 것을 최대한 손대지 않고 비어 있는 부분만 채운다". 그 범위에서
제안의 어느 조각을 채택할 것인가.

어려운 이유는 "비어 있다"의 판정이 셋으로 갈린다는 데 있다. **규칙이 없는 것**과 **규칙은 있으나 기계가 보지 않는 것**과
**대상 산출물 자체가 없는 것**이다. 첫째는 채우면 즉시 효력이 생기고, 둘째는 보고부터 시작해야 기존 695청크가 한꺼번에
위반이 되지 않으며, 셋째는 채워도 쓸 데가 없다.

## 이미 정해진 것 — 손대지 않는다

| 기정 | 제안의 대응 조각 | 처리 |
|---|---|---|
| 한 청크 = 한 파일, 본문 42줄(황금률 4) | 블록 = 파일, 줄 예산 | 그대로. 예산 수치를 바꾸지 않는다 |
| 결정은 결론·근거·대안 세 청크(`kb_decision`) | 7.2~7.4 세 블록 | 그대로. 슬롯 추가(Y-문장·결과 `(+)(−)`·확인)는 채택하지 않는다 |
| 요구는 EARS 패턴 + 이해관계자·관심사·출처 | 7.1 요구 틀 | 그대로. 현행 형태를 shape로 기술만 한다 |
| 상태 어휘 `draft`/`stable`/`suspect`/`invalidated`/`deprecated` | `valid` | `stable` 유지. 695청크·게이트·문서가 그 값을 쓴다 |
| 중복은 안전율로 용인(`p4-redundancy-as-safety-margin`, 유저 결정 2026-09-11) | 9.3 한 주장 한 블록 | **채택하지 않는다.** 기정을 뒤집는 유일한 조각이다 |
| 번호 제목과 `N.N절` 인용 | 5.1·5.2 무번호 + `[#id]` | **채택하지 않는다.** 실측 인용 2043건 · 690 파일 · 번호 제목 189개 |
| 게이트는 강화만 한다(STYLEGUIDE §2) | — | 새 검사는 보고(`consistency`)부터, 게이트 승격은 실측 뒤 |

## 답이 가르는 것

- **G1~G2를 채우면** 빈 값이 세 뜻으로 갈린다(검토했고 없다 / 적용되지 않는다 / 아직 모른다). 미결이 청크 안에 남아 `docs/open-questions/`가 손 관리에서 생성 뷰로 바뀐다. 기존 11 파일은 그대로 두고 새 미결부터 슬롯으로 적는다.
- **G3~G4를 채우면** 지금 쓰는 슬롯이 **성문화**된다. 여기서 중요한 것은 제안의 틀 28종을 들이지 않는다는 점이다 — 요구·결정 3종·검증 목표·합격 기준·케이스의 **현행 형태를 그대로** shape에 적고 슬롯마다 질문 하나를 등록한다. 청크를 고치지 않는다.
- **G5~G6을 채우면** 첨가가 보고에 잡힌다. 기존 695청크가 얼마나 걸리는지를 먼저 수치로 보고, 게이트 승격은 그 수치를 본 뒤 정한다. 지금 게이트로 올리면 대량 FAIL이 난다.
- **G7~G8을 채우면** 빈 plane과 손 표가 지식이 된다. G8은 유저 답 대기 중인 [`vv-profile-hazards-2026-09-19.md`](vv-profile-hazards-2026-09-19.md)의 현상 목록이 들어갈 그릇이다 — 두 항목이 여기서 맞물린다.
- **G9를 채우면** 판정자 질문의 형(예/아니오·선택·척도)·확신도 임계 셋·자동화 전 20건 라벨링이 규약이 된다. 라벨 실험(2026-09-11)이 사실상 이 절차를 썼고 기록만 없다.
- **채우지 않으면** 이 공백들은 다음에 같은 제안이 올 때 다시 검토 대상이 된다. 비용은 지금이 가장 싸다 — 청크가 695개이고 `annotation`·`artifact`가 아직 0이다.

## 선택지

1. **열 공백을 전부 채우되 게이트는 단계로 올린다** (권고).
   - 즉시 규칙 — G1·G2·G4·G9·G10을 `STYLEGUIDE.md`와 결정 2~3건으로 적는다. 새 저작부터 적용하고 기존 청크는 건드리지 않는다.
   - 보고부터 — G5·G6을 `consistency`의 새 축으로 넣어 기존 청크의 위반 수를 먼저 낸다.
   - shape — G3을 `development` 프로파일에 현행 형태 그대로 기술한다.
   - 그릇 — G7은 `annotation` 첫 청크가 생길 때, G8은 위험 분석 답이 올 때 함께 연다.
   - 비용: STYLEGUIDE 한 절 · 결정 2~3건 · shape 1 파일 · 도구 두 곳 · 뷰 하나(`//kg:open`).
2. **규칙만 채우고 기계 검사는 뒤로 미룬다.** G1·G2·G4·G9·G10만 문서화하고 G3·G5·G6은 보류한다. 비용: 문서 편집뿐. 강제력이 없어 다음 세션이 지키는지는 리뷰에 달린다.
3. **기계가 안 보는 셋(G3·G5·G6)부터 채운다.** 규칙은 이미 산문으로 있는 것에 가까우므로 검사를 먼저 붙인다. 비용: 도구 작업이 앞에 오고, 기존 청크의 위반 수가 먼저 드러난다.
