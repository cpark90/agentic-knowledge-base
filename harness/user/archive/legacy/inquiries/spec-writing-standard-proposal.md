# 명세 문서 작성 규격

## 1. 개요

에이전트가 생성하는 모든 명세 문서 — 요구사항 명세, 설계 명세, 인터페이스·데이터 명세, 테스트 명세, 검증 보고서, 운영 문서, 사후분석, ODD 문서, 용어집, 42줄 청크 — 는 이 규격을 따른다.

1. 문서는 섹션의 트리, 섹션은 블록의 목록, 블록은 슬롯의 목록이다. 블록 틀이 슬롯을 고정하고 문서 틀이 섹션과 블록 종류를 고정한다. 청크는 문서 틀 없이 블록 틀만 있는 문서다.
1. 표시용 번호는 소스에 쓰지 않는다. 목록 항목은 `1.`로만 쓰고, 제목·표·그림에는 `{#id}`를 붙이며, 참조는 `[#id]`로 한다. 번호는 정규화기·렌더러가 매기고 손 번호는 lint가 거부한다.
1. 필수 슬롯·필수 섹션은 삭제하지 않고 `없음` / `해당 없음` / `미확정`으로만 비운다. 틀 밖 내용은 `기타:` 슬롯 또는 `기타` 섹션에만 쓴다.
1. 목차·번호·변경 이력·색인·추적 매트릭스는 렌더러가 만든다. 소스에 있으면 lint가 거부한다.
1. 슬롯·섹션의 구조는 골격이 고정하고, 열거값·요인·환경·역할 등 어휘는 프로파일이 정한다. 틀은 프로파일 shape로 저장한다.
1. 값이 닫힌 집합에서 오는 슬롯은 선택하고, 생성 슬롯의 문장은 입력 상태에 근거가 있어야 한다. 같은 내용은 한 블록에만 있고 다른 곳에서는 참조한다. 근거 없는 문장·중복·채움은 판정자가 거부한다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 블록 | 한 정보 유형을 담는 슬롯 목록. 블록 틀 하나의 인스턴스. ID를 가진다 |
| 블록 틀 | 블록의 슬롯 순서·필수·형·줄 예산·검사 |
| 섹션 | 제목 하나 아래의 블록 목록. 하위 섹션을 가질 수 있다 |
| 문서 틀 | 문서의 섹션 트리와 각 섹션에 허용되는 블록 틀·개수 |
| 청크 | 블록 하나 = 파일 하나. 문서 틀이 없고 head(프런트매터)가 제목·plane·level을 맡는다 |
| 문서 | 문서 틀의 인스턴스. 블록을 직접 담거나(저작) 청크를 포함한다(투영) |
| 파셋 | 블록 안에서 기계가 읽는 부분. `facet=` 태그가 붙은 펜스 |
| 프로파일 | 어휘·예산·추가 틀을 정하는 도메인 모듈 |
| 렌더러 | 소스에서 번호·목차·색인·매트릭스를 생성해 읽는 형태를 만드는 도구 |
| 정규화기 | 슬롯·섹션 순서를 복원하고 목록 번호를 재부여하는 도구. 출력이 리비전 해시의 입력 |
| 판정자 | 고정된 입력 상태에 대해 원자 질문 — 예/아니오(noul) · 선택(choice) · 척도(score) — 에 확률과 확신도로 답하는 도구. 자유 서술을 하지 않는다 (TypeSafe Jev형 System-1 모델) |
| 입력 상태 | 블록을 쓰거나 판정할 때 주어지는 것 전부 — `sources`, 상위 블록, 참조 블록, 관측. 이 밖의 내용은 근거가 없다 |
| 선택 슬롯 / 생성 슬롯 | 값이 닫힌 집합(어휘·ID·기존 블록)에서 오는 슬롯 / 문장을 새로 쓰는 슬롯 |

## 3. 원칙

| 원칙 | 규칙 |
|---|---|
| 한 블록 = 한 정보 유형 | 절차·과정·원칙·개념·구조·사실·분류 중 하나. 섞이면 블록을 나눈다 |
| 첫 줄 = 결론 | 블록의 첫 슬롯, 섹션의 첫 블록, 문서의 첫 섹션은 결론·요약이다 |
| 표시용 번호는 소스에 없다 | 목록은 `1.`만, 제목·표·그림은 무번호 + `{#id}`, 참조는 `[#id]` |
| 비움의 세 값 | 필수 슬롯·섹션은 `없음`(검토했고 없다) / `해당 없음`(적용되지 않는다) / `미확정`(아직 모른다)으로만 비운다 |
| 배출구 하나 | 틀 밖 내용은 `기타:` 슬롯 / `기타` 섹션 하나. 반복되면 틀 확장 후보로 집계한다 |
| 파셋이 정본 | 같은 내용이 산문과 파셋에 있으면 파셋이 정본. 불일치는 verify 실패 |
| 생성물은 쓰지 않는다 | 목차·번호·변경 이력·색인·매트릭스는 렌더러 산출 |
| 어휘는 프로파일, 구조는 골격 | 열거값·요인·환경·역할 이름은 프로파일. 슬롯·섹션 구조는 골격 |
| 선택은 생성이 아니다 | 닫힌 집합에서 올 수 있는 값은 고른다. 생성은 생성 슬롯에서만 |
| 출처 없는 문장은 없다 | 생성 슬롯의 문장은 입력 상태에서 지지되어야 한다. 지지되지 않으면 삭제하거나 `미확정`으로 옮긴다 |
| 같은 내용은 한 곳에만 | 한 주장은 한 블록. 다른 곳에서는 `[#id]` 참조. 산문은 파셋을 되풀이하지 않는다 |
| 슬롯은 질문 하나에 답한다 | 슬롯마다 질문이 등록되어 있고, 그 질문의 답만 쓴다. 다른 슬롯의 답·메타 문장·채움은 첨가다 |
| 검사 가능해야 규칙이다 | 모든 규칙은 shape / lint / verify / judge / analysis 중 한 계층에 배정한다 |

## 4. 블록 규칙

### 4.1 슬롯 표기

| 규칙 | 내용 | 검사 |
|---|---|---|
| 슬롯 = 줄 머리 고정 키워드 | `키워드: 값` (한 줄) 또는 `키워드:` 다음 줄부터 블록. 키워드는 한글 고정어, 영문은 온톨로지 `rdfs:label` | lint |
| 블록 안 제목 금지 | `#`을 쓰지 않는다. 제목은 섹션의 것. 청크는 head가 제목을 맡는다 | lint |
| 산문 줄은 `단어:`로 시작하지 않는다 | 슬롯으로 읽힌다. 틀에 없는 키워드는 거부 | lint |
| 순서 고정 | 틀의 슬롯 순서대로. 어긋나면 정규화기가 되돌린다 | canonicalize |
| 필수 슬롯 삭제 불가 | 값이 없으면 세 빈 값 중 하나. 빈 줄 금지 | shape |
| 세 빈 값 외 금지 | `N/A`, `TBD`, `-`, `미정` 등 거부 | lint |
| 개방 슬롯 하나 | `기타:`만 자유 형. 두 항목을 넘으면 블록 분할 | lint |
| 첫 슬롯 = 결론 | 한 문장 | shape |
| 줄 예산 | 슬롯별 상한의 합 ≤ 블록 상한. 블록 상한은 프로파일 파라미터(기본 42) | lint |
| 정보 유형 하나 | 섞이면 분할 | 사람 검토 |

### 4.2 슬롯의 형

| 형 | 표기 | 규칙 |
|---|---|---|
| 문장 | 산문 1~N문장 | 문장 수 상한은 틀이 정한다. 첫 문장이 핵심 |
| 명사구 목록 | `- 항목` | 명사구, 마침표 없음, 같은 문법 형 |
| 절차 목록 | `1. 항목` | 4.3 목록 규칙 |
| 표 | 파이프 표, 열 고정 | 열 이름은 틀이 정한다. 열 추가·순서 변경 금지 |
| 펜스 | ```` ```<언어> facet=<이름> ```` | 언어 태그 필수. 파셋이면 `facet=` 필수 |

### 4.3 목록 규칙

| 규칙 | 내용 | 검사 |
|---|---|---|
| 순서 목록은 지정 슬롯에만 | 절차·자극·타임라인 슬롯. 그 외는 `-` 목록 | lint |
| 모든 항목을 `1.`로 쓴다 | 정규화기가 `1. 2. 3.`으로 재부여. `2.` 이상의 손 번호는 거부 | lint / canonicalize |
| 항목 참조는 ID | `1. 항목 {#id}` → `[#id]` | lint |
| 항목 ≤ 9, 중첩 ≤ 2단계 | 넘으면 블록 분할 | lint |
| 항목당 ≤ 2줄 | 넘으면 별도 블록 | lint |
| 같은 문법 형 | 절차는 명령문("~한다"), 명사구 목록은 명사구 | lint |
| 빈 목록 금지 | 항목이 없으면 `없음` | lint |

### 4.4 문서 안의 블록 표기

```
::: 요구 {#req-yield-upload}
When a device posts a harvest record, the system shall store it under the farm's plot.
패턴: event
이해관계자:
- farm-owner
관심사: data-integrity
근거: 구획 없는 기록은 집계에서 유실된다.
미확정: 없음
:::
```

| 규칙 | 내용 | 검사 |
|---|---|---|
| 여는 줄 `::: <틀> {#id}`, 닫는 줄 `:::` | 틀 이름은 카탈로그의 것. ID는 문서 안에서 유일, 영어 소문자 케밥 | lint |
| 블록 밖 본문 금지 | 섹션 제목과 블록 사이에 산문 없음. 산문은 `설명` 블록으로 | lint |
| 블록 중첩 금지 | 관계는 `[#id]` 참조로 | lint |
| 청크 포함 | `포함` 블록(`ref: <청크 IRI>`). 렌더러가 본문을 끼워 넣는다. 복사 금지 | analysis |
| 청크 파일 | 울타리 없는 블록 하나. 틀·ID는 head. 같은 블록 lint를 통과한다 | lint |

## 5. 문서 규칙

### 5.1 섹션과 제목

| 규칙 | 내용 | 검사 |
|---|---|---|
| 제목은 무번호 + `{#id}` | `## 인증 흐름 {#auth-flow}`. 절 번호 형(`3.`, `3.2`, `제N장/절/항`, 로마 숫자, `Part N`)으로 시작하는 제목은 거부. 번호는 렌더러가 트리 위치에서 생성 | lint |
| 제목 깊이 ≤ 3 | `#`(문서 제목, 하나) · `##` · `###` | lint |
| 깊이 건너뛰기 금지 | `##` 다음에 `####` 없음 | lint |
| 섹션 = 블록의 목록 | 섹션 본문은 블록만. 하위 섹션이 있으면 자기 블록을 앞에 둔다 | lint |
| 섹션당 블록 ≤ 9 | 넘으면 하위 섹션 | lint |
| 섹션의 첫 블록 = 결론 | 문서 틀이 첫 블록의 틀을 지정한다 | shape |
| 필수 섹션 삭제 불가 | 제목을 남기고 본문에 세 빈 값 중 하나만 | shape |
| 섹션 순서 고정 | 문서 틀 순서대로. 정규화기가 되돌린다 | canonicalize |
| `기타` 섹션 하나 | 문서 틀 밖의 내용. 하위 섹션 ≤ 2 | lint |

### 5.2 참조

| 규칙 | 내용 | 검사 |
|---|---|---|
| 참조는 `[#id]`뿐 | "3.2절", "표 4", "그림 2", "위에서", "앞서 말한" 형의 산문 참조 거부. 파셋 펜스 안은 검사 제외 | lint |
| 렌더러가 표시형으로 | `[#auth-flow]` → "§3.2 인증 흐름", `[#tbl-limits]` → "표 4", 청크 IRI → 라벨 | 렌더러 |
| 미해결 참조 금지 | 문서 안 ID·청크 IRI에 없으면 실패 | analysis |
| 외부 문서 참조 | `[#id]@<문서 ID>`. 문서 ID는 slug, 버전 없음 | analysis |
| 표·그림·수식 ID | 캡션에 `{#tbl-…}` `{#fig-…}` `{#eq-…}` | lint |

### 5.3 생성물

소스에 쓰지 않는다. 소스에 있으면 lint가 거부한다.

| 생성물 | 입력 |
|---|---|
| 목차 | 제목 트리 |
| 절·표·그림 번호, 요구 표시 번호 | 트리 위치·출현 순서 |
| 변경 이력 | 버전 관리 이력 |
| 용어 색인 | `개념` 블록과 온톨로지 라벨 |
| 미결 사항 | 모든 블록의 `미확정:` 슬롯 |
| 요구·기준 목록, 추적 매트릭스, 커버리지 | 블록 ID와 링크 |
| 문서 상태 | head의 `status` |

### 5.4 문서 head

```yaml
type: srs                 # 문서 틀 이름
id: harvest-srs           # slug. 정체성. 버전과 무관
title: 수확 기록 서비스 요구사항 명세
title_en: Harvest Record Service SRS
status: draft             # draft / valid / suspect / invalidated / deprecated
profile: software-dev
sources: []               # 읽기 집합. 하네스가 채운다
aliases: []               # 옛 ID·번호
```

### 5.5 예산

| 대상 | 예산 |
|---|---|
| 블록 | 슬롯 예산 합 ≤ 블록 상한 (프로파일, 기본 42) |
| 섹션 | 블록 ≤ 9, 하위 섹션 ≤ 9 |
| 문서 | 제목 깊이 ≤ 3. 총 블록 수는 문서 틀이 정한다 |

### 5.6 문서와 청크

| 방식 | 문서의 구성 | 블록의 정체성 |
|---|---|---|
| 투영 | 문서 틀 + `포함` 블록 | 청크 IRI. 문서는 배열만 소유 |
| 저작 | 문서 틀 + 직접 쓴 블록 | 문서 안 `{#id}`. 청크로 떼어낼 수 있다 |

두 방식은 같은 블록 lint를 통과한다. 저작 문서의 블록을 청크로 분해하는 것과 청크를 문서로 엮는 것은 서로 역변환이다.

## 6. 범용 블록 틀

표의 열: **#** 순서 · **슬롯** 키워드 · **필수** ● / ○ · **형** · **줄** 예산 · **검사**.

### 6.1 요약

| # | 슬롯 | 필수 | 형 | 줄 | 검사 |
|---|---|---|---|---|---|
| 1 | (첫 줄) 결론 | ● | 문장 1 | 2 | |
| 2 | 핵심: | ● | 명사구 목록 ≤5 — 정하는 것 | 5 | |
| 3 | 대상: | ● | 명사구 목록 ≤3 — 읽는 역할 | 2 | 카탈로그 역할 |
| 4 | 전제: | ● | `[#id]` 목록 ≤3 또는 `없음` | 3 | 참조 존재 |
| 5 | 미확정: | ● | 목록 또는 `없음` | 3 | |

### 6.2 개념

| # | 슬롯 | 필수 | 형 | 줄 | 검사 |
|---|---|---|---|---|---|
| 1 | (첫 줄) 정의 | ● | 문장 1 — "<상위> 중 <종차>인 것" | 2 | 온톨로지 개념이면 IRI 병기 |
| 2 | 용어: | ● | `ko: …` / `en: …` | 2 | |
| 3 | 설명: | ● | 문장 ≤5 | 6 | |
| 4 | 예: | ● | 명사구 목록 ≤3 | 3 | |
| 5 | 반례: | ○ | 명사구 목록 ≤2 | 2 | |
| 6 | 관련: | ○ | `[#id]` 목록 ≤4 | 2 | 참조 존재 |
| 7 | 미확정: | ● | 목록 또는 `없음` | 2 | |

여러 문서에서 반복되는 개념 블록은 온톨로지 개념(7.17)으로 승격한다.

### 6.3 절차

```

한 블록에 요구 문장 하나. 응답을 `and`로 잇지 않는다 — 둘이면 블록 둘. 블록 ID는 `{#req-<slug>}`이고 표시 번호는 렌더러가 매긴다.

## 9. 첨가와 중복의 방지

### 9.1 슬롯의 두 종류

| 종류 | 값의 출처 | 허용 | 검사 |
|---|---|---|---|
| 선택 슬롯 | 프로파일 어휘 (패턴 · 요인 · 갈래 · 추출 · 귀속 · 가능성 · 대응 · 라벨 · 장식 · 해소 · 상태 · 등급), 카탈로그 역할, 기존 블록·청크 ID, ODD 속성, 온톨로지 라벨 | 집합 안의 값만. 새 이름·새 ID·동의어 금지 | lint / verify |
| 생성 슬롯 | 문장 · 명사구 목록 · 절차 목록 · 표의 자유 열 | 입력 상태에 근거가 있는 내용만 | judge |
| 파셋 | 생성기 또는 사람 | 산문이 되풀이하지 않는다 | lint |

틀 정의(shape)는 슬롯마다 종류를 등록한다. 집합이 있는데 값이 집합 밖이면 그 슬롯은 `미확정`이고, 새 값은 용어 제안 워크플로로 보낸다.

### 9.2 근거 규칙

| 규칙 | 내용 |
|---|---|
| 문장 단위 근거 | 생성 슬롯의 문장 하나하나가 입력 상태 — `sources`, 상위 블록, 참조 블록, 관측 — 중 하나에서 지지되어야 한다 |
| 새 주장의 자리 | 입력에 없는 주장은 요구 · 결정(결론) · 가정 · 원칙 블록의 첫 슬롯에서만 허용된다. 이 블록은 사람 승인 또는 결정 근거가 출처가 된다 |
| 지지되지 않는 문장 | 삭제하거나 `미확정:`으로 옮긴다. 본문에 남기지 않는다 |
| 근거의 기록 | 근거 블록(7.3)과 관측 블록(7.8)은 항목마다 출처 IRI. 그 밖의 블록은 `sources`가 근거 집합 |
| 판정 | 문장마다 noul: "이 문장은 입력 상태에서 지지되는가?" 확신도 임계는 9.7 |

### 9.3 중복 규칙

| 규칙 | 내용 | 검사 |
|---|---|---|
| 한 주장 한 블록 | 같은 주장을 두 블록에 쓰지 않는다. 두 번째 자리에는 `[#id]` 또는 `포함` 블록 | judge — noul "두 블록이 같은 주장을 담는가?" |
| 쓰기 전 선택 | 블록을 새로 쓰기 전에 choice: "이 내용을 이미 담은 블록은? {기존 블록 라벨 목록, 없음}". `없음`이 아니면 참조한다 | judge |
| 산문은 파셋을 되풀이하지 않는다 | 파셋의 값(범위 · 시그니처 · 판정식 · 필드)을 산문으로 옮겨 적지 않는다. 산문에는 파셋에 없는 것 — 의도 · 이유 · 한정 — 만 | lint — 파셋 리터럴의 산문 출현 |
| 요약은 집계다 | 요약 블록의 `핵심:` 항목마다 지지하는 블록 `[#id]`가 있어야 한다. 본문에 없는 주장을 요약에 넣지 않는다 | judge |
| 용어는 라벨 하나 | 같은 개념을 다른 말로 쓰지 않는다. 온톨로지 `rdfs:label`만. `altLabel`은 색인용 | verify — 라벨 대조 |
| 문서 간 중복 | 다른 문서의 블록이 필요하면 `[#id]@문서` 참조 또는 `포함`. 복사 금지 | analysis |

### 9.4 슬롯 = 질문

틀 정의는 슬롯마다 그 슬롯이 답하는 질문 하나를 등록한다. 판정자는 슬롯을 다른 슬롯과 무관하게 그 질문으로만 평가한다.

| 슬롯 (요약 블록) | 등록된 질문 |
|---|---|
| (첫 줄) 결론 | 이 문서가 정하는 것을 한 문장으로 말하면? |
| 핵심: | 이 문서가 정하는 것 중 독자가 반드시 알아야 할 항목은? |
| 대상: | 누가 이 문서를 읽고 행동하는가? |
| 전제: | 이 문서를 읽기 전에 읽어야 할 것은? |
| 미확정: | 이 문서가 아직 정하지 못한 것은? |

| 규칙 | 내용 | 검사 |
|---|---|---|
| 질문 밖의 답 금지 | 다른 슬롯의 질문에 답하는 문장은 그 슬롯으로 옮긴다. 어느 슬롯의 질문에도 답하지 않는 문장은 삭제 | judge — choice "이 문장은 어느 슬롯의 질문에 답하는가? {슬롯 목록, 없음}" |
| 메타 문장 금지 | 안내 · 연결 · 예고 문장 — "이 절에서는", "다음과 같다", "아래에서 설명한다", "요약하면", "참고로", "앞서 말했듯" | lint — 패턴 |
| 채움 금지 | 빈 값을 피하려는 문장 — "특이사항 없음", "일반적인 방식을 따른다", "추후 결정" — 대신 세 빈 값 | lint — 패턴; judge — noul "이 슬롯의 내용은 질문에 실질적으로 답하는가?" |
| 예산은 상한 | 줄 예산을 채우기 위해 늘리지 않는다 | judge |

### 9.5 표현의 규칙

| 규칙 | 내용 |
|---|---|
| 한 문장 한 사실 | 문장을 `및` · `그리고` · `또한`으로 잇지 않는다. 둘이면 문장 둘 또는 항목 둘 |
| 수식어 최소 | 정도 부사(매우 · 충분히 · 적절히)와 평가어(중요한 · 핵심적인)는 판정식이나 척도로 대체한다. 대체할 수 없으면 삭제 |
| 이유는 근거 슬롯에 | "왜냐하면"으로 시작하는 문장은 `근거:` 슬롯에만 |
| 예시는 예시 블록에 | 산문 슬롯 안의 "예를 들어"는 예시 블록(6.7) 또는 `예:` 슬롯으로 |

### 9.6 입력 상태의 구성

블록을 쓰거나 판정할 때 하네스가 주는 입력 상태는 아래로 제한한다.

| 포함 | 제외 |
|---|---|
| 틀 골격과 슬롯 질문 | 다른 문서 틀의 골격 |
| 이 블록이 `refines` · `derives-from` · `verifies`로 잇는 상위 블록 | 형제 블록 (같은 섹션의 다른 블록은 라벨만) |
| `sources`의 블록 (라벨 목록 → 필요한 것만 펼침) | 작업 집합 밖의 블록 |
| 참조할 수 있는 ID 목록과 어휘 목록 (선택 슬롯용) | 온톨로지 전체 |
| 관측 (관측 · 사후분석 · 지도 블록에서) | 이전 초안의 자유 서술 |

입력에 없는 것은 쓸 수 없고, 형제 블록은 라벨만 보이므로 되풀이할 수 없다.

### 9.7 판정의 형식

| 규칙 | 내용 |
|---|---|
| 질문의 형 | 판정은 예/아니오(noul) · 선택(choice) · 척도(score) 중 하나. 자유 서술 리뷰는 판정이 아니다 |
| 원자성 | 질문 하나 = 판단 하나. 복합 질문은 나눈다. 같은 입력 상태에 대해 병렬로 묻는다 |
| 척도의 정의 | score의 각 단계는 정도가 아니라 상황으로 기술한다 (예: "입력에 같은 문장이 있다" / "입력에서 추론된다" / "입력에 없다") |
| 출력 | 값 + 확률 분포 + 확신도. 논평 블록(7.7)에 `question` 또는 `issue`로 기록 |
| 임계 | 확신도 ≥ 0.9: 자동 적용 · 0.5~0.9: 사람 확인 큐 · < 0.5: 판정 보류, 사람에게 |
| 판정 질문의 저장 | 질문 · 척도 · 임계는 프로파일 shape에 저장하고 판정자 모델 ID와 함께 버전을 맞춘다 |
| 도입 | 자동화 전에 판정 로그를 남기고 20건 이상을 사람이 라벨링해 임계별 정확도를 잰다. 게이트 차단은 그 뒤에 |
| 한계 | 판정자에게 계산 · 날짜 · 다단계 추론을 맡기지 않는다. 그 검사는 CEL · lint · analysis의 것 |

게이트에 거는 판정 질문:

| 게이트 | 질문 | 형 |
|---|---|---|
| 근거 | 이 문장은 입력 상태에서 지지되는가? | noul, 문장마다 |
| 중복 | 이 블록과 후보 블록은 같은 주장을 담는가? | noul, 라벨 유사 상위 k개와 |
| 자리 | 이 문장은 어느 슬롯의 질문에 답하는가? | choice {슬롯 목록, 없음} |
| 채움 | 이 슬롯의 내용은 질문에 실질적으로 답하는가? | noul |
| 요약 | 이 `핵심:` 항목을 지지하는 블록이 본문에 있는가? | choice {블록 ID 목록, 없음} |
| 라벨 대표성 | 라벨만 보고 본문의 주장을 고를 수 있는가? | choice {후보 본문 요약} |

## 10. 검사와 도구

### 10.1 검사 계층

| 검사 | 계층 | 도구 |

| 블록: 슬롯 존재·순서·필수, 세 빈 값, 손 번호, 항목 수·중첩·줄, 산문 줄 `단어:` 금지, 펜스 언어 태그, `facet=` | lint | `chunk_lint` |
| 블록: 슬롯 어휘, 산문 ↔ 파셋 불일치, `assumes`·`targets`·`verifies` 슬롯과 링크의 일치 | verify | `validate` |
| 문서: `:::` 여는 줄 형식, 블록 밖 본문, 블록 중첩, ID 유일 | lint | `doc_lint` |
| 문서: 제목 번호·깊이·건너뛰기, 섹션당 블록 수, 산문 참조 | lint | `doc_lint` |
| 문서: 섹션 존재·순서·필수, 섹션의 블록 틀·개수 | shape | `doc_lint` |
| 문서: 생성물이 소스에 있음 | lint | `doc_lint` |
| 참조: `[#id]` 해석, 청크 IRI 존재, 외부 문서 ID 존재 | analysis | 빌드 |
| 첨가: 메타 문장·채움 문구 패턴, 선택 슬롯의 집합 밖 값, 산문의 파셋 값 되풀이 | lint | `chunk_lint` |
| 첨가: 문장의 근거 존재, 슬롯 질문 밖의 답, 빈 값 회피 채움 | judge | `judge` |
| 중복: 새 블록과 기존 블록의 동일 주장, 요약·설명 문장의 참조 대체 가능성 | judge | `judge` |
| 예산: 블록 상한, 섹션 블록 수, 제목 깊이 | shape | `validate` / `doc_lint` |

### 10.2 도구

| 도구 | 동작 |
|---|---|
| `chunk_lint` | 블록 lint. 입력이 청크 파일이든 문서 안 블록이든 같은 함수 |
| `doc_lint` | 문서를 (head, 제목 트리, 블록 목록)으로 파싱하고 10.1의 문서 검사를 수행. 블록마다 `chunk_lint` 호출 |
| `canonicalize` | 블록: 슬롯 순서 복원, `1.` 재부여, `{#id}` 보존. 문서: 섹션 순서 복원, 블록 여는 줄 통일. 번호 재부여는 리비전 해시를 바꾸지 않는다 |
| `render` | 제목·표·그림·요구 번호, 목차, `[#id]` 표시형, 포함 블록 전개, 변경 이력, 색인, 미결 사항, 매트릭스 |
| 틀 저장 | 블록 틀·문서 틀은 프로파일 shape. 골격 = 구조, 프로파일 = 어휘 |
| 생성기 | 대안 표 · 케이스 표 · 스키마 필드 표 · 계약(api-spec 파셋에서) · 참조 블록의 긴 표 |
| `judge` | 9.7의 판정 질문을 블록·슬롯 단위로 실행. 입력 = 슬롯 내용 + 입력 상태. 출력 = 확률·확신도. 결과는 논평 블록으로 기록 |
| 하네스 | 문서 틀을 고르면 섹션 골격과 각 섹션의 빈 블록 골격을 프롬프트에 넣는다. 블록마다 입력 상태를 9.6대로 구성한다 |

### 10.3 에이전트 작성 지시

```
문서 작성 규칙
- 아래 섹션을 이 순서로 채운다. 섹션을 지우지 않는다. 해당 없으면 본문에 `해당 없음`만 쓴다.
- 제목에 번호를 붙이지 않는다. 제목마다 {#id}를 붙인다. #은 문서 제목 하나뿐, ## ###까지만.
- 섹션 본문은 ::: 블록만. 블록 밖에 산문을 쓰지 않는다. 산문은 ::: 설명 블록에.
- 블록은 `::: <틀> {#id}`로 열고 `:::`로 닫는다. 블록 안에 블록을 두지 않는다.
- 블록 안: 슬롯을 이 순서로 채운다 · 지우지 않는다 · 비우려면 없음/해당 없음/미확정만 ·
  산문 줄을 `단어:`로 시작하지 않는다 · `-` 항목은 명사구 · 순서 목록은 지정 슬롯에만, 번호는 전부 `1.` ·
  항목·표·그림에는 {#id}를 붙이고 [#id]로 참조 · 펜스에 언어 태그, 기계용이면 facet=
- 다른 절·표·그림·요구를 가리킬 때 "3.2절", "표 4", "위의" 대신 [#id].
- 목차·절 번호·변경 이력·색인·미결 사항을 쓰지 않는다. 시스템이 만든다.
- 틀에 없는 내용은 `기타:` 슬롯 또는 `기타` 섹션에만.
- 어휘·역할·ID·환경처럼 목록이 주어진 값은 목록에서 고른다. 새 이름을 만들지 않는다.
- 입력에 없는 사실을 쓰지 않는다. 확실하지 않으면 `미확정:`에 적는다.
- 이미 있는 블록의 내용은 다시 쓰지 않고 [#id]로 참조한다.
- 슬롯의 질문에만 답한다. "이 절에서는", "다음과 같다", "참고로" 같은 안내·연결 문장을 쓰지 않는다.
- 빈 값을 피하려고 문장을 만들지 않는다. 없으면 `없음`.
- 파셋에 있는 값을 산문으로 옮겨 적지 않는다. 산문에는 이유·의도만.

### 10.4 기존 문서의 이행

| 상태 | 처리 |
|---|---|
| 번호 매긴 제목 | 번호를 벗기고 제목에서 `{#id}` 생성. "3.2절" 참조는 번호→ID 표로 `[#id]` 치환. 표에 없는 참조는 `[#?]`로 남긴다 |
| 블록 없는 산문 | 정보 유형을 판정해 `설명` · `개념` · `절차` · `원칙` 블록으로 감싼다. 판정 불가면 `설명`. 결과는 `draft` |
| 목차 · 변경 이력 섹션 | 삭제 |
| 손 번호 목록 | 텍스트 순서를 따르고 번호 값은 무시 |
| 빈 값 표기 제각각 | 전부 `미확정`으로 바꾸고 재검토 큐 |
| 요구 번호 `REQ-017` | ID는 slug, 옛 번호는 head `aliases`에 보존. 렌더러가 alias를 해석한다 |
| 판정식이 산문에 묻힘 | 파셋 펜스로 추출. 실패하면 `미확정` + `기타:`에 원문 |
| 문서 틀에 없는 섹션 | `기타`로 이동 |

### 10.5 도입 순서

| 단계 | 대상 | 통과 조건 |
|---|---|---|
| 1 | 목록·제목·참조 규칙 (`doc_lint`의 번호·참조 검사) | 손 번호·산문 참조 위반 0 |
| 2 | 범용 블록 6종(요약 · 개념 · 절차 · 참조 · 원칙 · 설명) + `design-note` | 새 문서의 블록 lint 통과율 100% |
| 3 | `srs` · `adr-log` + 요구 · 결정 블록 | 요구 ID 불변 상태에서 표시 번호 재생성 확인 |
| 4 | `api-spec` · `data-spec` + 계약 · 스키마 | 계약 블록 ↔ 파셋 불일치 0 |
| 5 | `test-spec` · `vv-report` + V&V 블록 | 산문 ↔ 파셋 불일치 0, 생성물 섹션 소스 0 |
| 6 | `ops-doc` · `postmortem` · `odd` · `glossary` | 기존 문서 이행 완료 |
| 7 | 판정자 게이트(9.7) — 근거 · 중복 · 채움 질문을 게이트에 연결 | 판정 로그 20건 이상 라벨링, 임계에서 정확도 측정 후 자동화 |

## 답 (hci, 2026-09-22)

제안 922줄을 저장소 실물과 대조했다. 결론은 셋이다.

1. **설계가 이미 같은 방향이다.** 청크 = 블록 · 42줄 예산 · 생성물은 소스에 쓰지 않음 · 입력 상태 제한 · 닫힌 어휘는 이 저장소에 이미 규칙과 게이트로 있다. 제안은 그것을 **슬롯 수준까지 내린다**.
2. **값이 가장 큰 새것은 슬롯 = 질문(9.4)과 세 빈 값이다.** 지금 게이트가 잡지 못하는 첨가(메타 문장·채움·질문 밖의 답)를 잡고, `미확정:` 슬롯이 미결 사항을 손 관리에서 생성물로 바꾼다.
3. **정면 충돌이 하나, 큰 이행 비용이 하나 있다.** 중복 규칙 9.3이 유저 결정 2026-09-11(`p4-redundancy-as-safety-margin`)을 뒤집는다. 번호 제목·절 인용 폐지는 실측 **2043건 인용 · 690 파일**을 건드린다.

반영 범위는 유저 판단이므로 항목 [`../spec-writing-standard-adoption-2026-09-22.md`](../spec-writing-standard-adoption-2026-09-22.md)로 올렸다. 근거와 단계 배치는 그 항목에 있다.
