## Q194. 원격 호스트로 프로젝트 복사와 사용하지 않는 파일 제거 (유저의 대화 지시 기록)

답: (유저의 대화 지시 원문, 2026-11-28) 위 인용 그대로

hci의 읽기: 지시는 둘로 읽었다.
첫째, 복사는 바로 했다. 대상 `~/projects`가 비어 있어 덮어쓸 것이 없었기 때문이다. scp는 심볼릭 링크를 따라가 복사하므로, 작업 트리를 tar로 묶어 scp로 보내고 원격에서 풀었다.
작업 트리의 Bazel 출력 링크 넷(`bazel-bin`, `bazel-out`, `bazel-testlogs`, `bazel-agentic-knowledge-base`)은 빼었다. 이 링크들은 로컬 빌드 캐시를 가리키고, 원격에서 빌드하면 다시 생긴다.
`.git`, git 밖의 채널 메시지, 질문지, `.scratch/`는 모두 담았다. 묶음의 sha256이 양쪽에서 같았고, 파일과 링크 수가 양쪽 모두 9,389개다. 원격의 `git log`는 `fbb889d`이고 `git status`는 로컬과 같다.
둘째, "사용하지 않는 파일"은 interpreter가 정할 수 없다. 위 표에서 쓰이지 않는다는 증거를 가진 디렉토리가 없고, ssh로 지운 파일은 휴지통 없이 사라진다. 그래서 제거는 하지 않고 Q195로 대상을 묻는다.

## Q195. 원격 호스트에서 무엇을 지우는가

지시의 "사용하지 않는 파일"이 무엇인지 정한다. 어려운 점은 사용 여부를 보여 주는 기록이 원격에 없다는 것이다. 실행 중인 프로세스와 예약 작업은 위 디렉토리를 쓰지 않지만, 이것은 지금 돌지 않는다는 뜻일 뿐이다. 디스크 사용률은 3%이므로 공간 때문에 지울 이유는 없다.

이미 정해진 것과 현재 상태는 머리 인용 블록에 있다. 새 프로젝트 사본 `~/projects/agentic-knowledge-base`는 제거 대상에서 뺀다.

- (a) **아무것도 지우지 않는다.** 원격은 지금 상태로 남고, 되돌릴 일이 없다. 권한·방향: 그대로
- (b) **유저가 지울 경로를 이 답 아래에 적는다.** interpreter가 적힌 경로만 지운다. 멈춘 docker 컨테이너를 지울지도 함께 적는다. 비용은 유저가 목록을 적는 시간이다. 권한·방향: 바꾼다
- (c) **이름으로 대체가 보이는 옛 묶음 `rm_bundle`만 지운다.** 868K가 비워진다. 대체 관계는 이름에서만 읽은 것이고 내용으로 확인하지 않았다. 권한·방향: 바꾼다

**권장:** (b) — 사용 여부를 아는 것은 유저뿐이고, interpreter가 찾은 근거로는 어느 디렉토리도 쓰이지 않는다고 단정할 수 없다.

답:b. harvest_bundle, hilbundle, ranging_module과 같이 시스템에 필수적인 파일이 아닌 타프로젝트 파일들은 제거.

hci의 읽기: "시스템에 필수적인 파일이 아닌 타프로젝트 파일"을 홈의 프로젝트 디렉토리 아홉으로 읽었다. `harvest-bundle`, `harvest-webservice`, `hilbundle`, `journey`, `ranging_module`, `rm_bundle`, `rm_bundle_i88`, `rm_bundle_v2`, `rmflash`이다.
도구와 시스템 자료는 프로젝트가 아니므로 남긴다. `anaconda3`, `.platformio`, `snap`, `.cache`, 설정 파일, 빈 기본 디렉토리 8개다. 새 사본 `~/projects/agentic-knowledge-base`도 남긴다.
멈춘 docker 컨테이너 harvest-* 8개와 그 이미지는 파일이 아니고 답에 적히지 않았으므로 지우지 않는다.
