# 용어 표준화 — 범위와 순서를 정한다

> Q97 지시("용어를 분야 표준 용어로, 읽기 쉽게")에 따라 orchestrator가 조사를 마쳤다(파일 변경 0). 질문은 넷이다.

## 먼저 견본을 본다

`docs/purpose.md`를 새 용어로 고쳐 쓴 견본이 **[`.scratch/0178/purpose.after.md`](../../.scratch/0178/purpose.after.md)** (커밋하지 않는 임시 파일) 에 있다. 몇 줄을 비교하면 이렇다.

| 지금 | 고친 뒤 |
|---|---|
| plane은 일곱이고 검증 메커니즘이 plane을 가른다. | 지식 종류는 일곱이다. 종류를 가르는 기준은 그 지식을 검증하는 방법이다. |
| `decision` plane. 결론(concrete)·근거(logical)·대안(logical) 세 청크의 복합체 | 설계 결정: 결정·근거·고려한 대안의 세 파일로 이루어진 결정 기록이다. |
| 프로젝트당 ODD 하나가 그 프로젝트의 운영 조건이자 스코프·가정·시나리오의 분모다 | 프로젝트마다 ODD가 하나 있다. 그 ODD가 운영 조건을 정하고, 범위·가정·시나리오는 그 조건을 기준으로 센다. |

견본 맨 앞에는 용어 일곱을 풀어 쓴 정의 표가 있다.

## 조사에서 나온 것

- 문서는 2,417개다. 자주 쓰는 말 40개 가운데 23개가 용어집에 없다.
- **이름만 바꿔서는 읽기 쉬워지지 않는다.** 자주 쓰는 말 10개 가운데 8개는 문장을 다시 써야 한다(예: "분모", "사슬", "갈래", "frontier" 같은 비유).
- 주요 대응(전체 60행은 단계 1에서 용어집에 넣는다):

| 지금 | 바꿀 말 | 표준 출처 |

| 청크 | 지식 항목 | DITA topic |
| plane | 지식 종류 | 표준 없음 |
| 수준(level) | 추상화 수준 | 시나리오 공학 |
| 결정 복합체 | 결정 기록 | ISO 42010, ADR |
| 근거 · 대안 | 결정 근거 · 고려한 대안 | ISO 42010 |
| 투영 | 생성 산출물 | W3C PROV |
| 설계 공간 | 열린 설계 질문 | QOC |
| 판정자 · 확신도 | 평가자 모델 · 신뢰도 점수 | 기계학습 관용 |

| 주석 | 검토 의견 | W3C Web Annotation |

- 한국어 표준(TTA 용어사전)은 이번에 접속하지 못했다. 한글 열은 아직 확인 전이다. 확인된 것만 확정 행으로 넣는다.

## Q98. 어디까지 바꾸는가

- (a) **한글 문장과 한글 제목까지 바꾼다. 영문 이름(파일 이름, 온톨로지 이름, 게이트 이름)은 그대로 둔다.** 고칠 지식 파일은 826개다.
- (b) 한글 문장만 바꾼다. 제목은 그대로 둔다(793개).
- (c) 영문 이름까지 바꾼다. 파일 1,182개의 이름이 바뀌고 링크가 전부 움직인다. 되돌리기 어렵다.

**권장:** (a). 읽는 사람이 보는 것은 한글 문장과 제목이다. 영문 이름은 프로그램이 쓰는 것이라 바꾸면 비용만 크다.

답:c

## Q99. "청크 · plane · 수준"도 바꾸는가

세 말은 전에 유저가 "유지한다"고 정했다(2026-09-02·04).

- (a) **바꾼다.** 한글 문장에서 "지식 항목 · 지식 종류 · 추상화 수준"으로 쓴다. 영문 이름(chunk, plane, level)은 그대로다. 전의 결정을 고친다.
- (b) 그대로 둔다. 처음 나올 때 풀이만 붙인다.

**권장:** (a). 견본을 읽어 보면 차이가 가장 큰 곳이 이 세 말이다. 단 "청크"만 1,359번 나와 고칠 양이 많다.

답:a

## Q100. 어떤 순서로 하는가

모두 여섯 단계다. 단계마다 테스트를 통과시키고 한 번씩 커밋한다.

1. 용어집에 새 용어를 넣는다.
2. 규칙 문서(AGENTS.md, STYLEGUIDE.md, docs/rules.md, docs/method.md)를 고친다.
3. 읽기 쉬운 문장 규칙을 STYLEGUIDE에 더한다. 문서 앞에 용어 정의를 둔다. 약어는 처음 나올 때 풀어 쓴다. 비유를 쓰지 않는다.
4. 사람이 읽는 문서 22개를 고친다(README, INTENT, purpose 등).
5. 지식 파일 826개를 고친다.
6. 코드 주석을 고친다.

- (a) **1~4를 먼저 하고, 고친 문서를 유저가 읽어 본 뒤 5·6을 다시 승인받는다.**
- (b) 1~6을 한 번에 승인한다.
- (c) 3·4만 한다(용어는 용어집에 대응만 적고 본문은 바꾸지 않는다).

**권장:** (a). 1~4로 효과가 바로 보인다. 5(파일 826개, 그 가운데 확정된 것 606개)는 비용이 커서, 결과를 보고 정하는 것이 맞다.

## Q101. 설계 노트(docs/agent-knowledge-system-notes.md)는 어떻게 하는가

노트는 고치지 않기로 잠가 둔 원천 문서다. 다른 파일 1,590개가 노트의 절 번호를 인용한다.

- (a) **그대로 둔다.** 용어집에 "노트의 옛 말 → 새 말" 대응을 적어 읽게 한다.
- (b) 잠금을 풀고 노트도 새 용어로 고친다.

**권장:** (a). 노트를 고치면 인용 1,590개의 기준이 흔들린다.

답:a
