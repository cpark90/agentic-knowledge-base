# abstract 결정 청크의 구현 방식

> Q92-a(공간 넷의 변수 출발을 abstract 결정 청크로)를 수행하던 orchestrator가 질문(0167)을 올렸다.
>
> **이미 정해진 것** — Q92-a: 출발 결정마다 abstract 청크(결정 변수 선언)를 두고 확정 후보가 그것을 정제한다. 새 파일 3~4개를 승인했고 넘으면 묻는다.
>
> **현재 상태 (orchestrator 실측 2026-10-22)**
> - 결정 복합체는 빌드 타깃 하나이고 부분은 결론·근거·대안(+선택 규약)뿐이다(`defs/kb.bzl:556`). 타깃의 수준은 결론의 수준이라, 기존 복합체 안에 abstract 파일을 더해도 concrete로 검사돼 "정제 대상은 더 높은 수준" 규칙을 넘지 못한다.
> - 필요한 abstract는 넷이다(layer-scope와 requirement-layer는 같은 결정에서 출발하지만 변수가 달라 둘).

## Q93. abstract 결정 청크를 어떻게 두는가

| | (a) abstract마다 독립 결정 복합체 | (b) 복합체에 abstract 부분을 더하는 구조 변경 | (c) candidate-container 하나만 (a)로 먼저 |
|---|---|---|---|
| 새 파일 | 4 × 3(결론 abstract·근거·대안) = 12 | 4 | 3(승인 범위 안) |
| 도구·규칙 | 변경 없음 | `kb_decision`에 선택 부분과 새 역할 표지(예: "변수")를 더한다. 결정 규칙(결론·근거·대안 + 선택 규약, Q22-b)을 바꾼다 | 변경 없음 |
| 위험 | 대안 슬롯이 상투문이 되기 쉽다 | 구조 변경 | 나머지 셋은 head 링크 결함이 남는다(열린 공간이라 아직 필요 없다) |

**권장:** (c) — orchestrator의 추천이고 hci도 같다. 결함이 실제로 해가 되는 곳은 이미 닫힌 candidate-container 하나다(확정 A에 head 링크가 없다). 나머지 셋은 열린 공간이라 확정이 생길 때 필요하다. 하나를 먼저 만들어 보고 대안 슬롯이 상투문이 되는지 본 뒤 (a)·(b)를 고른다.

답:c

## Q94. r-011 개정 묶음(Q90-a·Q91)의 새 파일 수를 승인하는가

> orchestrator가 Q90-a의 조건("만들기 전에 수를 다시 알린다")에 따라 질문(0168)을 올렸다. 대체 결정은 supersedes이고 옛 결정은 deprecated가 된다(`p7-decision-supersession`). `r-011` 개정 초안은 기존 파일의 편집이라 새 파일이 아니다.

| 묶음 | 새 파일 | 내용 |
|---|---|---|
| 대체 결정 둘 | 2 × 4 = 8 | `p9-evidence-ledger`·`p9-possibility-as-feasible-set`의 범위를 "확정의 표현"으로 좁힌다. 결론·근거·대안·규약. 규약이 있어야 규범 문서(`docs/method.md`의 "가능성은 확률이 아니라" 줄 등)의 원본이 끊기지 않는다 |
| 공간 "믿음 정도의 계산과 보정" | 1 | `space/degree-of-belief-space.md`(이름 가안). 변수는 `r-032`(믿음 정도) × refines이고 다른 공간과 겹치지 않는다 |
| 그 후보 결정 | 3 × 3 = 9 | A 증거 종류 서열에 가중치를 준 점수(규칙) · B 지지/반박 수에서 베타-이항 사후분포(사전 + 증거 기록) · C 학습 판정자의 출력을 사람 라벨로 보정(확신도 어휘 재사용) |
| **지식 파일 합계** | **18** | |
| Q91-a 반박 증거 경로 | 0 | 도구 편집(verify·V&V 실행의 실패를 반박 증거로). 지시로 수행 |
| Q91-b 사람 라벨 표본 | 0 | 링크 쌍 20과 근거를 판정 질문지로 따로 올린다(유저 판정 작업) |
| Q91-c 동시 편집·공동 커버 | 0(기존 도구 확장) | 새 도구가 필요해지면 그때 묻는다 |

- (a) **위 표대로 승인한다(지식 파일 18).** Q91 셋은 공간의 후보가 아니라 어느 후보든 필요한 재료라 지시로 수행한다.
- (b) 대체 결정에서 규약을 빼 16으로 한다. 규범 문서의 해당 줄이 원본 없이 사라진다.
- (c) 공간의 후보를 A·C 둘로 줄여 15로 한다.

**권장:** (a) — orchestrator의 추천이고 hci도 같다. 후보 셋은 규칙 · 통계 · 학습이라는 서로 다른 계산 방식이라 하나를 빼면 비교가 성립하지 않는다. 확률화(Q87-b)의 "딥러닝식" 몫은 C가 진다.

답:a

## Q95. 사람 정답 라벨 표본 20건을 어떻게 뽑는가 (Q91-b)

> orchestrator가 판정 질문지의 재료를 준비하고 질문(0169)을 올렸다. 판정은 링크마다 "성립 / 불성립 / 판단 불가" 셋 중 하나를 고르는 일이다. 이 표본이 믿음 정도를 보정하는 기준이 된다.
>
> 층화 무작위 추출이다(seed 20261022). 확정·구축 기록만 6 · 확정·언어모델 제안으로 복원 6 · 후보 cites 4 · 후보 satisfies 4다. 치우침 둘이 있다. 같은 출발이 겹친다(3건이 같은 검증기 파일, 2건이 같은 결정). 후보 cites 4건은 전부 옛 시드 결정이다(모집단이 거기 몰려 있다).

- (a) **그대로 쓴다.** hci가 20문항 판정 질문지를 만든다.
- (b) **출발마다 1건으로 제한하고 같은 seed로 다시 뽑은 뒤 올린다.**
- (c) **40건으로 늘린다.** 성립·불성립 각각에서 하한 20을 채우려면 20건으로는 모자랄 수 있다. 판정 부담이 두 배다.

**권장:** (b) — orchestrator의 추천이고 hci도 같다. 같은 출발의 판정은 서로 독립이 아니라 표본의 정보량을 깎는다. (c)는 첫 20건의 결과를 보고 정한다.

답:b
