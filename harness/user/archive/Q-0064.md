**닫기 기준 셋의 문안.** 설계 공간에 적을 문장이다.
1. 계산 규칙은 사람 정답 라벨 표본(하한 20, Q-0047)에서 Brier 점수가 기저율 규칙의 Brier보다 낮아야 닫힌다. 기저율 규칙은 모든 후보에 표본의 참 비율을 내는 규칙이다.
2. 신뢰도 그림의 구간별 관측 빈도가 예측값의 허용폭 안에 들어야 한다. 표본이 50 미만이면 구간은 셋(0~0.33, 0.33~0.67, 0.67~1)이다. 허용폭은 그 구간 표본 수에서 계산한 95% 이항 신뢰구간이다.
3. S2의 일관성 게이트를 통과해야 한다. 그 게이트는 둘을 본다. 상태 전이 규칙은 믿음 정도를 읽지 않는다. 닫힌 계산 규칙이 없는 동안 병기 값은 선호의 동률 깨기에 쓰이지 않는다(Q137-a).

셋을 모두 통과한 규칙만 값을 병기한다(Q137-a). 둘 이상이 통과하면 Brier가 낮은 규칙을 고르고 나머지는 열어 둔다.

## Q159. `verified` 목록을 판정 이력으로 누적하는가

### 질문
결정 `p2-judgement-history-in-verified`(판정 이력의 누적)는 "판정 이력은 `verified` 목록에 누적된다"고 정하고, 재검증 때 이전 판정과의 차이가 판정자 드리프트를 재는 재료라고 적는다. 그런데 신뢰 shape(`kb/ontology/shapes/trust-shapes.ttl`)는 생성 시각이 **모든** 검증 시각보다 이르거나 같아야 한다고 본다. 그래서 내용을 고치는 순간 옛 판정 항목은 모두 위반이 되고, 이력이 남을 수 없다. 결정과 게이트가 어긋나 있다. 어느 쪽에 맞추는지 정한다.

### 이미 정해진 것
- 결정 `p2-judgement-history-in-verified`(판정 이력의 누적)의 결론은 누적이다. 같은 결정이 게이트 `writer`의 해소를 `endorse`로 `verified`를 붙이는 것이라 적는다.
- 결정 `p2-trust-tier-from-generated-and-verified`(신뢰 등급과 검증 시각)는 "검증 뒤에 내용이 바뀌면 재검증 없이 검증 항목을 고칠 수 없다"를 정하고, 신뢰 shape가 그것을 판정한다.
- 검사를 약하게 하는 변경은 유저 승인이 필요하다.

### 현재 상태
orchestrator가 HEAD와 작업 트리를 대조했다(0278). 지식 파일 150개에서 `verified` 항목 158개가 지워져 있었다. 내용을 고친 작업들(이번 세션과 그 전 세션)이 목록을 지금 시각의 한 항목으로 덮어썼고, 게이트가 그것을 강제했다. 지워진 항목은 orchestrator 130, 라벨 판정 과정 16, 시험 과정 7, vnv 2, 유저(`human:cpark`) 2다. **유저 승인 기록도 둘 사라졌다.** 되살리려 하자 신뢰 shape 위반 149건이 나서 내용보다 이른 항목은 되돌렸고, 내용보다 늦은 항목 여섯만 되살아 있다. 지금 `bazel test //...`는 124/124 통과다. 용어·문장 5단계는 확정 지식 659개의 내용을 고치므로, 지금 규칙대로면 그 파일들의 판정 이력이 모두 지워진다. HEAD보다 오래된 커밋에서 지워진 수는 대조하지 않았다.

### 답이 가르는 것
판정 이력(사람 승인과 판정자 결과)이 지식 파일 안에 남는지, git 이력에만 남는지가 갈린다. 5단계를 시작하기 전에 정해야 손실이 커지지 않는다.

### 선택지
- (a) **누적한다. shape는 가장 늦은 검증 시각만 본다.** 신뢰 shape의 비교 대상을 모든 검증 시각에서 가장 늦은 검증 시각 하나로 바꾼다(SPARQL 제약이나 생성 그래프의 파생 값으로). 내용 수정 뒤의 재검증은 목록에 항목 하나를 덧붙인다. 지워진 158개는 HEAD에서 되살린다. 받아들이는 그래프가 늘어나므로 검사 약화로 표시하되, "내용이 바뀐 뒤 재검증 없이 신뢰를 주장할 수 없다"는 불변식은 그대로 지켜진다. 비용은 shape 하나와 생성기 한 곳, 항목 158개 복원이고, 5단계의 재검증이 덮어쓰기 대신 덧붙이기가 된다. 권한·방향: 바꾼다(검사 범위)
- (b) **지금 내용의 판정만 담는다. 이력은 git이 맡는다.** 결정 `p2-judgement-history-in-verified`(판정 이력의 누적)의 "누적" 문장을 "지금 내용에 대한 판정만 담고, 지난 판정은 git 이력에 있다"로 개정한다. 판정자 드리프트는 git의 옛 판에서 재므로 밀폐 게이트로는 잴 수 없다. 지워진 158개는 git에 있으므로 복원하지 않는다. 비용은 결정 하나의 개정이다. 권한·방향: 바꾼다(결정)

**권장:** (a). orchestrator의 권장과 같다. 결정이 누적을 정한 이유(판정자 드리프트의 재료, 유저 승인의 기록)는 파일 안의 이력이 있어야 서고, 유저 승인 기록 둘이 이미 사라졌다. 신뢰의 불변식은 가장 늦은 검증 시각으로도 지켜진다.
