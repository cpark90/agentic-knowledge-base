# 뷰·skill은 프로세스 층의 항목인가 투영인가

> orchestrator의 확인 요청(메시지 0007)을 질문지로 옮긴 것이다. 통일 기획 2단계의 다음 조각은 뷰 13과 skill 21의 편입이다.
> 그런데 둘의 지위를 적은 문언이 두 쪽으로 갈려 있어 구현 방향을 정할 수 없다.
>
> **이미 정해진 것**
> - 유저 정의(2026-10-01): 서비스는 *"에이전트가 작업을 수행할 때 context에 포함되는 구조화된 지식 자체와 지식과 작업을 연결하는
>   방법론, 작업을 수행하는 프로세스를 제공하는 … 매우 정돈되고 기능화된 위키"*다. 처리 방향은 제거가 아니라 편입이다.
> - skill은 API가 아니라 프로세스 층의 실행 표면이다(결정 `p0-service-is-a-three-layer-wiki`).
> - 게이트 49는 단일 정의처(`defs/kb.bzl` `GATES`)와 그래프 개체(`agt:Gate`)로 섰고 프로세스 층에 세어진다(2026-10-02).
>
> **현재 상태 (hci 확인 2026-10-03)**
> - 항목으로 읽는 문언: `kb/dev/decision/p0-service-is-a-three-layer-wiki/conclusion.md:22`의 표가 프로세스 층을
>   "도구(코드 청크)·게이트·뷰·skill·절차"로 적는다. 개념 `agt:processLayer`(`kb/ontology/related/layer/layer-ontology.ttl:29`)와
>   CQ-38 질의의 주석도 같다.
> - 투영으로 읽는 문언: 1-① 감사 `kb/vv/verdict/layer-assignment-audit.md:18`이 "뷰 13과 skill 21은 전부 도구 코드 청크의 투영"이라
>   적는다. 같은 감사의 24행은 "투영이 아닌 것은 항목이어야 한다"고 적어 감사 안에서도 두 읽기가 섞여 있다.
> - orchestrator 실측: 뷰 13 중 열둘은 생성기 함수가 이미 `layer: process` 코드 청크다. 남은 `//kg:cq`의 원본 질의 30개는 청크로
>   추출하도록 developer에게 dispatch했다. skill 21은 도구 docstring 청크와 `kb_lib` 절 청크에서 생성된다.
> - 뷰·skill은 지금 그래프에 개체가 없고 CQ-38의 층 집계에 세어지지 않는다. 뷰 목록의 단일 정의처(`defs/kb.bzl` `VIEWS`)는 어느 안이든
>   필요해서 진행 중이다.

## Q9. 뷰와 skill의 지위를 무엇으로 정할 것인가

- (a) **투영이다.** 개념 `agt:Projection`·`agt:View`·`agt:Skill`을 세우고 `prov:wasDerivedFrom`이 원본 코드 청크를 가리킨다. 층은
  원본 청크만 갖는다. 결정 표와 `agt:processLayer` 정의의 "뷰·skill" 문언을 고친다. 비용은 손 파일 약 10개다.
- (b) **항목이다.** 뷰 13·skill 21이 프로세스 층 개체가 된다. CQ-38의 프로세스 층 집계가 34 늘고 결정 문언이 그대로 선다. 비용은 손
  파일 약 10개다. 원본 코드 청크와 개체가 같은 것을 두 번 세는 문제가 남는다.
- (c) **기록만 한다.** `VIEWS` 목록만 두고 개체를 세우지 않는다. 비용은 손 파일 3개이고 진행 중인 일로 끝난다. 문언의 갈림은 그대로 남는다.

**권장:** (a) — orchestrator의 추천이다. 뷰·skill의 내용은 코드 청크에서 결정론적으로 생성되므로 층은 원본이 갖고 같은 것을 두 번
세지 않는다. 유저 정의의 "프로세스를 제공하는"은 원본 코드 청크와 게이트가 채운다.

답:(a)

## Q10. 손으로 쓴 BUILD·Starlark 배선을 항목으로 요구할 것인가

손 `BUILD.bazel`과 `defs/*.bzl`의 배선은 뷰·테스트의 입력 집합과 인자를 정한다. 이것은 청크가 아니다. 어려운 이유는 "저장소의 모든
것을 층의 항목이거나 그 투영으로 만든다"는 통일 기획의 목표에 비추어 배선이 어느 쪽에도 들지 않는다는 데 있다.

- (a) **빌드 시스템의 정의로 본다.** 항목이 아니고, 2단계는 매크로 하나로 닫는다. 배선의 의미는 게이트 개체와 도구 청크가 이미 담는다.
  비용은 기획 목표에 "빌드 배선은 예외"라는 문장이 하나 생기는 것이다.
- (b) **항목으로 요구한다.** 배선을 청크로 추출하는 별도 단계를 둔다. 비용은 약 50건의 판정이 다시 열리는 것이다.

**권장:** (a) — orchestrator의 추천이다. 배선은 무엇을 어떤 입력으로 돌리는지의 정의이고 그 의미는 이미 그래프에 있다.

답:(a)
