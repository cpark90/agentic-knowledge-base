## Q181. S3에 착수하는가

### 질문
사람 라벨 20건이 갖춰져 S3의 선행 조건이 채워졌다. S3은 세 규칙의 값을 20개 링크에서 모아 Brier와 신뢰도를 계산하고, 닫기 기준을 통과한 규칙이
있으면 설계 공간을 닫는다. 어려운 점은 셋이다. 계산 도구가 없다. C는 판정 증거가 있어야 값이 생긴다. 표본이 20건이라 결과의 판별력이 약하다.

### 답이 가르는 것
믿음 정도가 처음으로 병기될 수 있는지, 새 도구가 생기는지, 판정자 실행이 따르는지, 설계 공간의 상태가 바뀌는지가 갈린다.

### 선택지
- (a) **지금 착수하고 계산 도구를 만든다.** Brier와 신뢰도 구간을 계산하는 도구를 만들어 결과를 생성물로 낸다. C 값이 없는 링크는 세션 판정자로
  판정해 증거를 만든다(20건 이하이므로 Q170-c 안이다). 닫기 기준을 통과한 규칙이 있으면 설계 공간을 닫고 그 규칙의 값을 병기한다. 비용은 새 도구 파일
  하나와 추출물, 판정자 실행 한 번이다. 결과는 표본이 늘 때마다 같은 도구로 다시 잰다. 권한·방향: 바꾼다(새 파일, 설계 공간 닫기)
- (b) **한 번만 계산하고 도구는 만들지 않는다.** 저장소 밖에서 한 번 계산해 결과를 관측으로 기록하고, 설계 공간은 닫지 않는다. 도구는 표본이 50건을
  넘을 때 만든다. 비용은 낮지만 수치를 생성물에서 다시 얻을 수 없고, 표본이 늘면 계산을 처음부터 다시 한다. 권한·방향: 그대로
- (c) **보류하고 독립 사람 라벨을 먼저 늘린다.** 독립 라벨이 4건뿐이므로, 새 판정지로 독립 라벨을 더 모은 뒤 착수한다. 비용은 유저의 판정 시간과
  S3의 지연이다. 권한·방향: 그대로

**권장:** (a) — 닫기 기준은 이미 정해져 있고 표본 하한도 채워졌다. 도구가 있어야 표본이 늘 때마다 같은 방법으로 다시 잴 수 있고, 수치를 문서에 적지 않고
생성물에서 인용하는 규칙과도 맞는다. 판별력의 한계는 결과와 함께 적는다.

## Q182. 그래프에 없는 링크 11개의 값을 무엇으로 구하는가

### 질문
S3을 하려면 라벨을 붙인 20건마다 계산 규칙의 값이 있어야 한다. 그런데 11건은 링크가 그래프에서 사라졌다. 라벨은 질문지에 실린 주장(그때의 두 문서와
연결 종류)에 대한 판단이므로, 값도 같은 주장에 대해 구해야 라벨과 맞는다. 어려운 점은, 판정자는 옛 원문으로 다시 물을 수 있지만 규칙 A·B는 링크의
증거 항목이 있어야 값이 생긴다는 것이다.

### 답이 가르는 것
어느 규칙이 S3에서 판정 가능한지(표본 20건을 채우는지), 그리고 값과 라벨이 같은 주장을 가리키는지가 갈린다.

### 선택지
- (a) **판정자에게 표본 당시의 원문으로 다시 묻는다.** 11건은 git 이력의 옛 원문과 질문지에 실린 주장 그대로 세션 판정자에게 물어 C의 값을 얻는다.
  C는 20건이 채워져 판정할 수 있다. A·B는 9건뿐이므로 이번 S3에서는 판정하지 않고 "표본 부족"으로 적는다. 비용은 판정자 실행 한 번이다.
  권한·방향: 그대로
- (b) **뒤이은 링크에 대응시킨다.** 뒤이은 링크가 있는 6건은 그 링크의 값을 쓰고, 없는 5건은 빼거나 판정자로 채운다. A·B도 값을 얻을 수 있다. 비용은
  값과 라벨이 다른 주장을 가리킬 위험이다. L02·L03·L06·L13은 연결 종류가 '구현한다'에서 '구체화한다'로 바뀌었고, 라벨은 '구현한다'에 대한 판단이다.
  권한·방향: 바꾼다(표본의 대상 정의)
- (c) **그래프에 있는 9건만 쓴다.** 9건은 하한 20에 못 미치므로 어떤 규칙도 판정하지 않는다. S3은 새 라벨을 모은 뒤로 미룬다. 권한·방향: 그대로

**권장:** (a) — 사람과 판정자가 같은 원문, 같은 주장을 보게 되어 라벨과 값이 어긋나지 않는다. A·B는 이번에 판정할 수 없다는 사실을 그대로 적는 편이
값을 다른 주장에서 빌려 오는 것보다 건전하다.

답:a
