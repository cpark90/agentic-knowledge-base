# 서비스 완결성 검토와 구조조정 기획안

> 유저가 Q-0059의 끝에 요청한 검토와 기획을 orchestrator가 마쳤다(result 0219). 본문은 `.scratch/0217/plan.md`(256줄)이고, 사례 원자료 19건은 `.scratch/0217/cases/`, 저장소 실측은 `.scratch/0217/repo-survey.md`에 있다. 저장소 파일은 바꾸지 않았다. hci가 기획안 전체를 읽었다. 아래는 판정의 요지와 유저 결정이 필요한 갈림길 아홉이다. 답을 받은 뒤 단계를 지시로 쪼개어 보낸다.
>
> **2026-10-24 재검토(Q-0063).** 유저가 "확률적 지식 모델"의 모델은 지식을 확률 구조적으로 모델링한 결과물이고 학습 기반 방법의 모델이 아니라고 정했다. 아래 요지의 "고리 2·3"과 Q134~Q136, 단계 S1~S3은 "확정 지식을 내보내 저장소 밖에서 모델을 학습시킨다"는 전제에 서 있어 철회한다. **Q137~Q142는 그대로 답하면 된다.** 고친 기획은 Q-0063과 그 뒤의 질문지로 올린다.

## 판정의 요지

**한 서비스로서의 완결성.** 이 프로젝트는 "지식을 결정론적으로 쌓고 검사하는 기반"으로는 완결에 가깝다. 지식 항목과 온톨로지, 링크, 게이트, 생성 뷰, V&V가 "지식은 파일 하나이고, 링크는 증거를 갖고, 판정은 게이트가 한다"는 한 원칙으로 맞물려 있고 구조 지표는 모두 초록이다(고아 0, 연결 성분 1, 후방 추적 99.8%). 그러나 처음 정한 목적인 "확률적 지식 모델"의 서비스로는 미완결이다. 목적을 세 고리로 나누면, 첫째 고리(확정 지식의 축적)는 통일되어 있지만 둘째 고리(내보내기와 학습, r-030)와 셋째 고리(출력 검사와 믿음 정도, r-031과 r-032)는 요구와 설계 공간만 있고 결정과 코드와 값이 0이다. 바깥 소비자가 지식을 받아 갈 접점도 0이다. 점검표(요소 열하나)로는 22점 만점에 12점이다. 한 줄로 줄이면, 지금은 "확률적 지식 모델을 위한 데이터 공장"까지 와 있고 출하구와 품질 검사대가 비어 있다.

**사례가 보여 준 것.** 여섯 범주에서 19개 서비스를 조사했다(위키, 결정 기록, 에이전트 기억, 지식 그래프 완성, 추적성 도구, 데이터 거버넌스). 지식 단위에 확률을 붙이는 것은 셋(ComplEx, NELL, Knowledge Vault)이고, 보정까지 검증한 것은 Knowledge Vault 하나다. 나머지 열여섯은 상태와 사람의 승인으로 신뢰를 나타낸다. 그래서 "확정은 결정론으로 하고 믿음 정도는 병기한다"는 이 프로젝트의 길은 드문 조합이다. 이 길은 NELL이 겪은 의미 표류(자기 출력으로 다시 학습해 오류가 커지는 현상)를 확정 게이트가 구조로 끊는다. 따라서 **서비스의 의의는 "표류하지 않는 확률적 지식 모델의 기반"** 이다. 다만 이 의의는 아직 주장이고, 확정 지식을 내보내 단순한 모델 하나를 학습시키고 그 출력을 보정 검사로 재어 보일 때 증명된다.

**구조조정의 방향 셋.** 첫째, 빈 고리를 잇는다(내보내기, 출력 검사, 보정 검사, ODD 경계). 둘째, 같은 일을 두 곳에서 하는 부분을 합친다(손 문서 15개 가운데 일곱은 생성 뷰로 대체 가능, V&V 목표와 요구의 이중 서술, 판정 주석의 근사 중복, 규범 절의 정확 중복 258쌍). 셋째, 유저 결정의 기록을 지식으로 올린다. 질문 133개 가운데 60개(45%)만 지식에 번호로 인용되고, 확정 권한의 기록이 질문지와 결정 인용과 증거의 세 자리에 흩어져 있다.

**유저가 답한 문서의 처리안 다섯.** 원문은 그대로 보존한다. 질문마다 답과 반영처를 한 표로 내는 생성 색인 뷰를 둔다. 결정의 결론에 `Q-NNNN#Qn` 참조를 적는다. 뒤집힌 답(예를 들어 Q90-a를 Q109-b가 넓힌 것)은 supersedes나 개정 근거로 표시한다. 질문지 꼴에 "확정 권한이나 방향을 바꾸는가" 표시와 대상 지식의 IRI·한글 라벨을 더한다.

**운영의 최적화.** `//kg:gate_test`가 84초까지 늘었으므로 지식 종류별 타깃으로 나눈다. 살아 있는 지식의 토큰 가운데 코드 추출물이 53.6%이므로 추출 범위를 좁힌다. 유저에게 묻는 질문을 확정 권한과 방향으로 좁힌다. 미커밋 경로가 500을 넘으므로 단계마다 커밋한다.

## Q134. 다음 단계의 중심을 어디에 두는가 (G1)

### 질문
구조조정의 첫 묶음을 "확률 고리의 첫 실물"에 두는지 "구조 정리"에 두는지 정한다.

### 이미 정해진 것
목적은 확률적 지식 모델이다(Q87, Q89). 비용이 커도 통일성과 건전성을 높이는 변화는 진행한다(Q-0055 추가답변). 구조 정리의 일부(옛 결정 트리 삭제, 손 문서 둘 삭제, 용어·문장 3·4단계)는 이미 지시되어 있다.

### 현재 상태
고리 2와 3은 요구만 있고 결정과 코드와 값이 0이다. 겹침은 주로 사람이 읽는 층에 있다.

### 답이 가르는 것
의의가 처음 증명되는 시점이 앞서는지, 통일성이 먼저 오르는지가 갈린다. 단계 S1~S3이 확률 고리이고 S4~S5가 구조 정리다.

### 선택지
- (a) **확률 고리의 첫 실물.** 내보내기, 저장소 밖에서 단순한 모델 하나의 학습, 보정 검사와 시간 분할 평가다. 결정 둘과 도구 둘, V&V 넷, ODD 개정이 든다. S1의 새 파일 12를 함께 승인한다.
- (b) **구조 정리 먼저.** 손 문서 합침, V&V 이중 서술, 추출 범위다.
- (c) **둘을 번갈아 한다.**

**권장:** (a). 목적의 의의가 거기서 처음 증명되고, 구조 정리는 진행 중인 지시들이 이미 상당 부분 한다.

> **철회(2026-10-24, Q-0063).** 선택지 (a)의 "저장소 밖에서 단순한 모델 하나의 학습"이 유저의 뜻에 없는 것이 되어 이 질문은 답하지 않아도 된다. "확률 고리"는 믿음 정도의 계산과 보정, 게이트로 다시 짜서 올린다.

답: 보류 — 질문이 철회됐다(Q-0063 Q153, 2026-10-24). 유저의 답이 아니라 hci가 닫으면서 적었다.

## Q135. 모델 버전과 학습 실행을 그래프에 넣는가 (G2)

### 질문
믿음 정도를 낸 모델이 어느 것인지를 그래프가 기억하게 하는지 정한다.

### 이미 정해진 것
믿음 정도는 병기하고 선호의 동률만 깬다(Q90-a, Q109-b). r-031은 모델 출력을 확정 지식과 게이트로 검사한다.

### 현재 상태
모델 버전과 학습 실행을 나타내는 개념이 온톨로지에 없다. MLflow와 DVC는 모델 버전에서 학습 실행을 거쳐 데이터 스냅숏으로 가는 계보를 남긴다.

### 답이 가르는 것
믿음 정도 곁에 모델 버전 ID가 붙어 검사가 재현되는지, 아니면 매니페스트 파일로만 남는지가 갈린다.

### 선택지
- (a) **넣는다.** 개념 둘(모델 버전, 학습 실행)과 계보 링크가 생기고, 믿음 정도 곁에 모델 버전 ID를 적는다. 새 개념 파일 둘이다.
- (b) **넣지 않고 내보내기 묶음의 매니페스트 파일로만 남긴다.**

**권장:** (a). 믿음 정도가 어느 모델에서 왔는지 모르면 r-031의 검사가 재현되지 않는다.

> **철회(2026-10-24, Q-0063).** 학습 실행과 모델 버전은 없다. 믿음 정도를 낸 것은 지식 베이스 안의 계산 규칙(결정 하나)과 그때의 커밋이고, 둘은 git이 이미 기억한다. 이 질문은 답하지 않아도 된다.

답: 보류 — 질문이 철회됐다(Q-0063 Q153, 2026-10-24). 유저의 답이 아니라 hci가 닫으면서 적었다.

## Q136. ODD의 "학습 모델 임베딩" 제외를 어떻게 바꾸는가 (G3)

### 질문
ODD가 지금 명시 제외하는 "학습 모델 임베딩"을 어떻게 고쳐 고리 2를 여는지 정한다.

### 이미 정해진 것
저장소의 빌드는 밀폐이고 결정론이다. ODD의 조건만 참조하고 필요하면 ODD를 먼저 넓힌다(CLAUDE.md 3항).

### 현재 상태
`kb/odd/project-odd.yml`의 명시 제외에 "학습 모델 임베딩"이 있다. 내보내기 도구와 확률 계산 도구가 0이다.

### 답이 가르는 것
학습을 저장소 밖 소비자가 하는지 저장소 안에서 하는지가 갈린다.

### 선택지
- (a) **학습은 저장소 밖 소비자가 하고, 저장소는 내보내기와 출력 검사만 한다고 경계를 적는다.** ODD 파일 하나를 고친다.
- (b) **저장소 안에서 학습까지 한다.** 의존성과 재현성 비용이 크다.

**권장:** (a). 저장소의 결정론과 밀폐 빌드를 지키면서 고리 2와 3을 연다.

> **철회(2026-10-24, Q-0063).** 저장소 안에서도 밖에서도 학습하지 않으므로 ODD의 명시 제외 "학습 모델 임베딩"은 그대로 둔다. 이 질문은 답하지 않아도 된다.

답: 보류 — 질문이 철회됐다(Q-0063 Q153, 2026-10-24). 유저의 답이 아니라 hci가 닫으면서 적었다.

## Q137. 믿음 정도의 병기 조건에 보정 검사를 더하는가 (G4)

### 질문
믿음 정도의 값을 병기할 때 "보정 검사를 통과한 모델의 값만"이라는 조건을 붙이는지 정한다.

### 이미 정해진 것
믿음 정도는 병기하고 선호의 동률을 깬다(Q90-a, Q109-b). 믿음 정도의 계산 규칙은 설계 공간이 열려 있다(후보 셋).

### 현재 상태
사례 19건 가운데 보정을 검증한 것은 Knowledge Vault 하나이고, 보정 없는 확신도는 NELL에서 정확도와 갈렸다.

### 답이 가르는 것
병기되는 값이 "0.9면 그 무리의 약 90%가 참"이라는 뜻을 갖는지, 아니면 값만 있고 그 뜻은 지표로만 보는지가 갈린다.

### 선택지
- (a) **보정 검사(Brier 점수와 신뢰도 그림)를 통과한 모델의 값만 병기한다.** 설계 공간을 닫는 기준에 이 조건이 들어가고 `p9-evidence-ledger-with-belief`의 병기 조건을 개정한다.
- (b) **값을 병기하고 보정은 지표로만 본다.**

**권장:** (a). 사례 수준의 신뢰를 얻는 조건이다.

> 2026-10-24: 이 질문의 "모델"은 믿음 정도의 계산 규칙(설계 공간의 후보 A·B·C)을 말한다. 질문은 Q-0063의 정정 뒤에도 그대로 선다.

## Q138. 링크에 시간 필드 둘을 두는가 (G5)

### 질문
링크마다 "현실에서 참이던 구간"과 "지식 베이스에 기록된 구간"의 두 시간 필드를 두는지 정한다.

### 이미 정해진 것
링크의 이력은 git 커밋과 deprecated 상태로 남는다. 시간 정체성 결정(`p2-temporal-identity`)과 링크 속성 결정(`p10-link-attributes`)이 있다.

### 현재 상태
Zep과 Graphiti는 두 구간을 두어 모순이 생기면 지우지 않고 무효 시각을 채운다. 이 프로젝트는 git 커밋이 기록 시각을 이미 준다.

### 답이 가르는 것
링크 속성과 shape가 늘어나는 대신 시간 분할 평가가 쉬워지는지, 지금처럼 git에 기대는지가 갈린다.

### 선택지
- (a) **두 필드를 둔다.** 링크 속성과 shape가 늘고 결정 둘을 개정한다.
- (b) **지금처럼 git 이력과 deprecated로만 둔다.** Q134의 시간 분할 평가가 필요로 하면 다시 묻는다.

**권장:** (b). 지금은 git 커밋이 기록 시각을 주고, 필요가 확인된 뒤 더하는 편이 낫다.

답:b

## Q140. 유저에게 묻는 질문의 범위를 좁히는가 (G7)

### 질문
hci가 유저에게 올리는 질문의 범위를 "확정 권한과 방향, 비용이 큰 선택"으로 좁히고 구현 선택은 orchestrator가 정해 결과로 알리게 하는지 정한다.

### 이미 정해진 것
새 파일은 만들기 전에 묻는다(Q66). 검사를 약하게 하는 변경은 승인이 필요하다. 질문지는 다섯 요소다.

### 현재 상태
질문지 59개와 질문 133개, 채널 메시지 292개다. 이번 주 질문의 다수는 orchestrator가 정할 수 있는 구현 선택이었다. RFC 절차는 "확정을 막는 의견과 막지 않는 의견"을 가른다.

### 답이 가르는 것
질문 왕복이 줄어 진행이 빨라지는 대신 구현 선택을 유저가 사후에 보게 되는지, 지금처럼 모두 묻는지가 갈린다.

### 선택지
- (a) **좁힌다.** 확정 권한과 방향, 비용이 큰 선택, 새 파일, 검사의 약화만 묻는다. 구현 선택은 orchestrator가 정하고 result에 적으며 hci가 보고로 알린다. 질문지 선택지마다 "확정 권한이나 방향을 바꾸는가" 표시를 더한다.
- (b) **지금처럼 새 파일과 stable 개정을 모두 묻는다.**

**권장:** (a). 다만 새 파일과 검사의 약화는 계속 묻는다.

답:a

## Q141. 질문지 색인 뷰와 결정의 질문 참조를 두는가 (G8)

### 질문
유저가 답한 질문 133개가 어디에 반영됐는지를 한 표로 내는 생성 뷰를 두고, 결정의 결론에 질문 참조를 적게 하는지 정한다.

### 이미 정해진 것
증거 종류 "유저 결정"의 참조 꼴은 `Q-NNNN#Qn`이다(Q111-a). 질문지 원문은 고치지 않는다.

### 현재 상태
133문 가운데 60문만 지식에 번호로 인용된다. 확정 권한의 기록이 세 자리(질문지의 답, 결정 본문의 "유저 답 Qn", 설계 공간의 증거)에 흩어져 있다.

### 답이 가르는 것
확정 권한의 세 자리가 하나의 색인으로 묶이는지, 뷰만 두고 결정은 그대로 두는지가 갈린다.

### 선택지
- (a) **생성 뷰 하나를 두고, 결정 결론의 `sources`에 `Q-NNNN#Qn`을 적게 한다.** 뷰 하나와 도구 수정 하나, 기존 결정 인용의 기계 치환이 든다.
- (b) **뷰만 두고 결정은 그대로 둔다.**

**권장:** (a). 세 자리를 하나의 색인으로 묶는다.

답:a

## Q142. 코드 추출 범위를 좁히는가 (G9)

### 질문
코드 추출물(함수와 절마다 지식 항목 하나)의 범위를 좁히는지 정한다.

### 이미 정해진 것
코드는 함수 하나가 지식 항목 하나다. 추출 범위를 정하는 설계 공간이 열려 있다.

### 현재 상태
코드 추출물이 모듈 45, 지식 항목 1,008이고 살아 있는 지식 토큰의 53.6%다. 추적 수치가 이 사본으로 부풀려진다.

### 답이 가르는 것
작업 집합의 질과 토큰 비용이 바로 좋아지는 대신 추출물 수백이 deprecated가 되는지, 지금처럼 모두 추출하는지가 갈린다.

### 선택지
- (a) **결정이 정제하는 함수와 공개 접점만 추출하고 나머지는 모듈 항목 하나로 둔다.** 추출물 수백이 deprecated가 된다. 열린 공간의 근거와 맞춰 정한다.
- (b) **지금처럼 모든 함수와 절을 추출한다.**

**권장:** (a). 토큰의 절반이 코드의 사본이다.

## 함께 알릴 것

### 단계 다섯 (6절)
진행 중인 작업이 끝난 상태를 기준으로 하고 단계마다 커밋한다. 순서는 Q134의 답으로 바뀐다.

| 단계 | 내용 | 새 파일 |
|---|---|---|
| S1 | 확률 고리의 결정과 경계(ODD 학습 경계, 내보내기 결정, 출력 검사 결정, r-030·r-031의 검증 목표와 기준, 믿음 정도 공간의 닫는 기준) | 12 |
| S2 | 내보내기 도구와 학습 매니페스트, 모델 버전·학습 실행 개념 | 6~9 |
| S3 | 출력 검사와 첫 측정(시간 분할 평가, 보정 검사, 저장소 밖에서 단순한 모델 하나) | 5~7 |
| S4 | 유저 결정의 색인(질문지 색인 뷰, 결정 결론의 질문 참조) | 2~3 |
| S5 | 구조 정리(손 문서 여섯 합침, V&V 목표의 이중 서술 정리, 추출 범위, 세션 교훈 자리, 규범 절 중복) | 8~12 |

S1~S3은 2026-10-24에 철회됐다(Q-0063). orchestrator가 "믿음 정도의 계산과 보정, 게이트"로 다시 짠 단계를 올린다. S4·S5는 그대로다.

### 구조조정안에서 유저 결정 없이 진행할 것
부분 열다섯의 처리표(4.1절) 가운데 다음은 기존 결정과 맞으므로 갈림길 없이 단계 S5에서 지시한다. V&V 목표가 요구 문장을 다시 쓰지 않고 요구를 가리키게 고치는 것, 판정 주석의 근사 중복을 판정 묶음으로 모으는 것, 규범 절의 정확 중복 258쌍을 다시 세어 합치는 것, 세션 교훈의 자리 셋을 둘로 나누는 것, 설계 공간에 보류와 만료를 들이는 것, `//kg:gate_test`를 지식 종류별 타깃으로 나누는 것이다. CI의 신설은 ODD가 명시 제외하므로 S1 뒤에 따로 묻는다.

### 커밋을 권한다
기획안이 지적한 대로 마지막 커밋(aeb0a58) 뒤로 미커밋 경로가 500을 넘는다. 되돌리기와 리뷰가 어려워지므로, 진행 중인 지시 가운데 하나가 끝나는 시점에 커밋을 요청해 주면 `bazel test //...` 확인 뒤 역할별 요지를 적어 커밋한다.

### 그 밖
- **2026-10-24 답을 받았다(Q137-a, Q138-b, Q139-b, Q140-a, Q141-a, Q142-a).** 반영을 task 0260으로 보냈다. Q140-a(질문 범위의 축소)는 지침과 질문지 꼴에 적고, Q137-a는 S1의 닫기 기준에, Q139-b·Q141-a·Q142-a는 S4·S5의 내용에 들어간다. 그 작업의 끝에 orchestrator가 다시 센 합친 단계표와 S1의 새 파일 둘을 question으로 올리고, hci가 그것을 S1 착수 승인 질문지로 올린다. 이 질문지는 0260의 result를 확인한 뒤 닫는다.
