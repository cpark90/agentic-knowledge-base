# 위임 판정의 지위와 남은 논리 검사

> - 결정 `p9-belief-by-calibrated-judge`(사람 라벨로 보정한 판정자 확신도): 세션 판정자가 낸 확신도를 사람 정답 라벨 표본으로 보정한다.
>   그 합격 기준(`kb/vv/criteria/belief-calibrated-against-human-labels.md`)은 표본을 "질문지 Q-0047의 사람 정답 라벨"로 정하고, 20건 미만이면

> - 결정 `p2-ontology-compiler-three-tiers`(온톨로지 검사기 — 온톨로지 검사 3단계): 셋째 단계의 검사로 불만족 클래스, 의도치 않은 동치, 순환 분류

>   "아직 판정하지 않는다"고 적는다.
> - 결정 `p6-weakening-a-check-needs-user-approval`(검사 약화는 유저 승인 사항이다).
>
> **현재 상태** (2026-11-27, interpreter가 실측)
> - Q-0047(연결 20건 판정)은 L01~L04를 유저가 직접 답했고, L05~L20은 오늘 유저의 지시("추천대로 진행해줘")로 hci가 판정해 적었다. 문항별 추천은
>   원래 없었으므로 hci가 원문을 읽고 판정했다. 위임 판정은 맞다 13, 틀리다 3이다(L05·L13·L15는 틀리다, L14·L18은 '약함'을 붙였다).
> - 보정 대상인 세션 판정자는 에이전트다. 에이전트 판정으로 에이전트를 보정하면 기준이 순환한다. 그래서 hci는 위임 판정에 "사람 라벨 아님"을
>   표시했다. 사람 라벨은 이 질문지 전에 있던 10건과 Q-0047의 4건이다.

>   - 순환 분류 계층: 단언된 `rdfs:subClassOf`에서 0건이다.
>   - 불만족 클래스: 클래스마다 프로브 개체를 하나씩 넣고 OWL-RL 추론을 적용하는 방법으로 쟀다. `owl:Nothing` 소속과 추론기 오류가 모두 0건이다.
>     RL 추론은 클래스 수준 불만족을 완전히 찾지 못하므로 이 값은 근사다.
>   - 의도치 않은 동치: 같은 폐포에서 서로 하위인 클래스 쌍이 0건이다.
>   - 추론은 1.8초 걸렸다. 스크립트는 interpreter 세션의 임시 파일이고 저장소에는 없다.

## Q178. 위임 판정 16건을 사람 라벨로 셀 것인가

### 질문
Q-0047의 L05~L20은 hci가 판정한 것이다. 이것을 합격 기준의 사람 라벨 표본에 넣으면 표본이 20건이 되어 믿음 정도의 첫 측정(S3)을 할 수 있다.
그러나 에이전트 판정이 사람 기준을 대신하게 된다. 어려운 점은 측정을 시작하는 속도와 기준의 독립성이 부딪힌다는 것이다.

### 답이 가르는 것
합격 기준의 표본이 몇 건인지, S3을 지금 할 수 있는지, 측정 결과가 무엇을 뜻하는지가 갈린다.

### 선택지
- (a) **세지 않는다.** 사람 라벨은 Q-0047에서 4건이다. 표본이 20건이 안 되므로 S3은 계속 기다린다. 새 사람 판정지를 나중에 만든다. 비용은 S3의 지연이다.
  권한·방향: 그대로
- (b) **유저가 16건을 확인하면 센다.** 유저가 Q-0047의 L05~L20에 적힌 hci 판정과 근거를 읽고, 이 질문의 `답:` 줄에 바꿀 문항만 적는다(예:
  "L13 맞다로, 나머지 동의"). 확인을 거친 라벨은 "hci 권장 뒤 사람 확인"으로 따로 표시해 기록하고, S3 보고는 독립 사람 라벨 4건의 값을 함께 낸다.
  비용은 유저가 16줄을 읽는 시간이다. 권장안을 먼저 보고 답하므로 판단이 권장안 쪽으로 끌릴 수 있고, 그 편향은 기록에 남는다. 권한·방향: 바꾼다(표본 정의)
- (c) **그대로 센다.** 표본이 바로 20건이 되고 S3을 시작한다. 비용은 기준의 순환이다. 에이전트 판정이 사람 기준을 대신하므로 측정이 판정자의
  자기 일치만 보게 된다. 합격 기준을 약화하는 것이므로 검사 약화로 기록된다. 권한·방향: 바꾼다(표본 정의, 검사 약화)

**권장:** (b) — 사람이 마지막 판단을 하므로 기준이 순환하지 않고, 유저가 16건을 처음부터 판정하는 것보다 시간이 적게 든다. 편향은 표시와 독립
라벨 4건의 병기로 드러낸다.

## Q179. 아직 판정하지 않는 논리 검사 셋을 다룰 것인가

### 질문
결정이 셋째 단계의 검사로 드는 불만족 클래스, 의도치 않은 동치, 순환 분류 계층은 지금 게이트가 판정하지 않는다. 지금 근사로 재면 셋 다
0건이다. 어려운 점은 클래스 수준 불만족을 완전히 판정하려면 OWL 2 DL 추론기가 필요한데, 그 추론기는 RL 밖이고 Java 의존이 생긴다는 것이다.

### 답이 가르는 것
검사의 완전성, 새 의존의 유무, `//kg:reason_test`의 판정 범위와 시간이 갈린다.

### 선택지
- (a) **RL 안에서 근사로 판정한다.** `//kg:reason_test`에 세 검사를 더한다. 순환 분류 계층은 단언된 하위 관계의 순환으로 찾는다. 불만족 클래스는 클래스마다
  프로브 개체를 넣고 추론해 `owl:Nothing` 소속으로 찾는다. 의도치 않은 동치는 폐포에서 서로 하위인데 동치로 선언되지 않은 쌍으로 찾는다. 새 의존은
  없고, 추론 시간은 실험에서 2초 안쪽이다. RL의 한계 때문에 놓치는 불만족이 있을 수 있고, 결정에 그 한계를 적는다. 권한·방향: 바꾼다(검사 추가)
- (b) **DL 추론기를 배치 검사로 돌린다.** 결정 `p2-owl2-rl-profile`(추론은 OWL 2 RL로 제한한다)이 허용하는 "배치"로, 게이트 밖에서 HermiT 같은
  DL 추론기를 돌린다. 완전성이 높다. 비용은 Java 런타임과 추론기 의존이 새로 생기는 것이다. ROBOT을 들이지 않기로 한 Q175-a와 같은 부담이다.
  권한·방향: 바꾼다(검사 추가, 의존)
- (c) **두고 결정 문구를 유지한다.** 결론에 적힌 "아직 판정하지 않는다"가 그대로 남는다. 비용은 없다. 온톨로지가 바뀌어 이 셋이 생겨도
  게이트가 알리지 않는다. 권한·방향: 그대로

**권장:** (a) — 이 온톨로지의 공리는 모두 RL 프로파일 안에 있으므로 RL 근사로 대부분을 잡는다. 새 의존 없이 결정이 든 검사를 모두 게이트에 올린다.
