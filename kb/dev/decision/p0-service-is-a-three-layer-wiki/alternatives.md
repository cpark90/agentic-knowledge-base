**대안** — 여섯을 기각한다.

| 대안 | 기각 이유 |
|---|---|
| 서비스 = 에이전트 하네스 제품 | 통일 축이 실행 표면이 되어 지식 층이 부속이 된다. 유저 정의는 지식 자체를 첫째로 둔다 |
| 서비스 = 지식 베이스 자체(방법론·프로세스는 밖) | 도구 37·게이트·skill이 서비스 밖에 남아 산발이 그대로다. 유저 정의가 셋을 한 위키로 묶는다 |
| 접점 셋(skill = API, 게이트, 뷰) | 1차 재조정의 안이고 철회됐다. 접점이 셋이면 에이전트가 어디로 들어가는지가 갈린다 — 접점은 작업 집합 하나다 |
| 층을 plane의 상위 분류로 | 같은 plane의 항목이 다른 역할(분야의 결정 대 저작 규칙의 결정)을 가지므로 가를 수 없다. 층은 직교 속성이다 |
| 뷰·skill을 프로세스 층 항목으로 세운다 | 원본 코드 청크와 그 생성물이 같은 것을 두 번 센다. 유저가 Q9에서 고르지 않았다 |
| 빌드 배선을 항목으로 요구해 청크로 추출한다 | 약 50건의 판정이 다시 열리고, 배선의 의미는 게이트 개체와 도구 청크가 이미 담는다. 유저가 Q10에서 고르지 않았다 |

"제거로 다듬는다"는 안은 검토 대상이 아니었다 — 유저가 편입을 지시했다.
