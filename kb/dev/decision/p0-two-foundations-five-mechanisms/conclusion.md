**결론** — 체계는 두 **기반**과 다섯 **메커니즘**, 메커니즘으로 만든 두 **지식
베이스**로 구성된다. 작업 종류를 가리지 않으며, 도메인 중립 코어와 도메인
프로파일(2.11절)로 나뉜다.

| 구성 | 푸는 문제 |
|---|---|
| 온톨로지 (기반 1) | 모든 것이 표현되는 공통 어휘가 없다 |
| ODD (기반 2) | 프로젝트 전체의 전제 조건이 적힌 곳이 없다 |
| 청크·복합체 | 지식의 최소 단위와 조립 규칙이 없다 |
| plane | 성격이 다른 지식이 뒤섞인다 |
| 정제 계층 | 요구와 실제 산출물이 끊어져 있다 |
| 연결의 가능성 | 미확정 연결을 표현할 수단이 없다 |
| 링크 | 지식 사이의 관계가 암묵적이다 |
| 개발 KB · 검증·확인 KB | 만든 쪽이 판정하면 검증이 형식이 된다 |

두 기반은 메커니즘이 아니다 — 온톨로지는 어휘이고 ODD는 그 어휘로 쓴 첫 문서이며,
나머지는 전부 온톨로지 어휘로 ODD 안에서 쓴 문장이다.

**범위 밖은 두 방향이다** — 체계가 소모하는 **입력**(파라미터, Part XI)과 체계의 출력을
소비하는 **활용**(Part XII). 입력이 바뀌면 체계가 재구성되고, 체계가 바뀌면 활용이
영향받는다 — 의존 방향이 반대다.
