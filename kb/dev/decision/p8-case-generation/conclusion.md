**결론** — 논리 시나리오 하나에서 concrete 테스트 케이스 여럿을 생성하는 규칙. 표본 추출 근거가 규칙 이름이다 (노트 8.23절).

| 규칙 | 생성 | 근거 태그 |
|---|---|---|
| 등가분할 | 각 도메인 구간에서 대표값 하나 | `sampling:equivalence` |
| 경계값 | 각 범위의 양 끝과 바로 안팎 | `sampling:boundary` — 별도 집계 (8.7절) |
| 조합 (t-wise) | 변수 쌍(또는 t조)의 모든 값 조합 | `sampling:pairwise` |
| 요인 주입 | 결함 요인 태그별 최소 하나 | `sampling:factor` |
| 관측 재현 | 실행 기록에서 실패한 조합 | `sampling:observed`, `origin:observed` |

생성된 테스트 케이스는 ODD 안이어야 하고(게이트), `cover()` 정의가 커버리지 계산의 분모다. 생성 규칙과 seed가 테스트 케이스의 provenance에 남으므로 재생성이 가능하다.

**게이트** `case-gen`·`case-drift`(유저 답 Q27-a, 노트 6.8절·8.23절, 실행 계층 analysis와 test) — `tools/case_gen.py`가 생성 시점에 근거 규칙 없는 `cover` 항목과 손으로 적은 값(`cases`, 관측 재현 밖의 `values`)을 거부한다(2026-10-04). `//:case_drift_test`는 트리의 테스트 케이스를 재생성과 비교해 생성 결과와 어긋난 테스트 케이스를 거부한다. 테스트 케이스 밖에 있는 concrete 값의 표본 근거는 검사하지 않는다(5단계). 해소는 vnv가 logical 시나리오의 `keep`·`cover`를 고쳐 `python3 tools/case_gen.py --out kb/vv/case`로 반영하고, 그 시나리오를 `//:case_drift_test`의 `scenarios`에 더하는 것이다.
